# 教程电子棋图：GPT 识别与人工校准

## 适用范围

使用现有解析文字、原页图片和 GPT-6.1-Sol，将围棋教材制作成可查看、逐图校准及导出 SGF 的电子棋图集合。

当前主流程：

`来源清点 → 复用最终结果 → 整页查漏定位 → 完整棋图识别 → 契约检查 → dry-run → 增量候选入库 → 后台核对 → 人工确认`

这是旧 `tutorial-recognition-pipeline` 的替代流程。默认不运行 CV 逐格分类、Gemini patch 识别、`--force` 重建或全表教程同步。语音和视频另行交接。

## 1. 确认输入与写入范围

- 读取当前 `AGENTS.md`、应用实现、书籍 `output/book.json`、`output/pages/`；批量任务以 `curriculum/catalog.json` 为清单，解析真实路径去重。
- 从当前配置确认后台、数据库、媒体存储及部署目标。测试授权只用于测试；不得据此写入生产。
- 先只读清点：PDF 总页数、图引用、独立棋图、已有最终结果、数据库来源映射及人工成果。
- 图引用数是覆盖基准，不是独立棋图数量上限；逐页记录无图、多个小图、变化图、实战谱、拆分与额外发现。
- 来源 ID、书中图签和数据库 `figure_id` 是不同标识。通过书籍来源、页码、JSON pointer、图引用及已有映射关联；不能只按重复图名匹配。

## 2. 优先复用最终结果

- 复用已验收的 `results.json` 及最终复核，不能用 `raw/` 首次响应覆盖它们。
- 保存输入、最终结果和来源文件哈希；冻结需保留的既有批次，仅处理未覆盖或确实失败的部分。
- 《围棋形势判断基础》前 100 页应复用最终 266 张结果，保留第 92 页 `p092-f03` 的编号及提子注记修正。
- 缓存键包含模型、提示词、契约和图片哈希；缓存成功前校验结果。保留失败记录、断点、token 用量与耗时。按现有有限重试恢复，不因一个失败反复重跑全书。

## 3. GPT 整页定位与完整棋图识别

- 使用已有 Codex 登录调用 **GPT-6.1-Sol**。核对实际 runner 的模型与参数；当前续跑脚本为 `gpt-6.1-sol / high`。不自动改用其他模型或恢复 Gemini。
- 复用已有渲染页及 JSON 文字，不默认重新 OCR。
- 先让 GPT 检查整页，识别全部独立棋图及图引用对应关系；再输入包含必要图签、正文和图下注记的完整棋图进行转录。不要将棋子逐格裁成 patch 代替整图理解。
- 特别保留打劫、提子、停着、“某手在某编号／三角处”等说明。不能把被提掉的缺号补在无编号棋子上。
- 记录棋子颜色、印刷编号、大小写字母、符号、局部图原点、可见范围、推断与疑点。原页、裁剪框和输入图片可追溯。

## 4. 坐标与数据契约

- 最终棋子与疑点坐标统一为完整 **19×19、左上角零基坐标**。确认输入坐标空间；已经全盘化的结果不能再次叠加区域偏移。
- 分开保留：静态局面及印刷标记、初始摆子、真实有序落子、停着、提子／同点复用、来源范围和序列完整性。
- 新识别／转换候选必须显式采用 `schema_version: 2`，完整声明 `stones.B`、`stones.W` 与 `unknown_stones`；来源、初始局面或序列证据不足时，保留未确认的 `source_region` 及 `replay: null`／`needs_calibration`，不能根据 viewport 或编号通过推定完整 replay。原始 final/raw 保留不改。
- `board_payload` 通过现有 `StrictBoardPayload` 检查；原模型输出、`inferences`、`uncertainties`、置信度及来源保存在不可变识别候选中，不把额外字段塞入严格棋盘契约。
- 颜色未知点保留为 `unknown_stones`。成功识别不等于人工审核，静态终局也不等于完整手顺。

## 5. 疑点必须可定位、可解释

每项疑点保留原始依据、候选解释、来源，以及能够可靠确定的全盘点位：

- **疑似漏子／假阴性**：有证据表明可能漏掉棋子。
- **疑似误子／假阳性**：有证据表明可能把空点、污点等识别成棋子。
- **颜色不确定**：黑／白难辨。
- **编号或符号不确定／模型推断**：文字褪色、数字或三角等标记难辨。
- **无法定位／范围不确定**：保留图级提示，不猜一个交叉点。

只有明确的棋子存在性证据才能归为漏子／误子；黑白候选不是漏检，`无标记／三角`也不是棋子误检。沿用现有 `cell` 全盘坐标；仅有局部 `at` 且缺少可靠转换时，不直接定位到当前棋盘。

后台应让当前页和棋图的疑点醒目可见；具体点位用不遮挡棋子、数字的提示与说明列表对应。历史识别疑点与当前人工审核状态分别显示。人工平移或更换来源后，无法可靠对齐的旧疑点在原候选中对照，不指认当前其他棋子。

## 6. 幂等增量入库

- 先 dry-run，输出逐来源到 `book_id / figure_id / candidate_id` 的映射和处理结果；匹配歧义保留现有数据，报告后继续其他项。
- 同一 dataset 与 recognition ID 表示不可变证据；重复执行跳过一致内容，变更内容使用明确的新数据集身份。
- 已有人工编辑、审核、棋图和音视频不得被自动识别覆盖。新结果可以作为候选供比较；只有现有导入器明确允许的未编辑记录才增量填入当前值。
- 实际写入前按现有工具核对测试数据库与存储身份。使用事务、审计和历史；人工保存使用 `expected_updated_at`，409 保留草稿。
- 原页及媒体按现有资产存储接入，验证后台浏览器可访问，不能写 Mac 绝对路径作为远程 URL。

## 7. 后台逐手查看与人工校准

- **已有完整真实手顺**：复用现有围棋规则／SGF 实现，前进执行落子和提子，后退恢复全部上一状态；支持停着、白棋起手、任意原书起始编号及同点再落。
- **仅静态编号图**：自动检查编号唯一、连续、正整数及黑白交替；任意起始编号与任一方起手均可。通过即开放初始、上一手、下一手、末手和进度条，不要求先人工审核或手动建立手顺。
- 静态编号预览保留无编号背景子，只按顺序显隐图中现有编号子；明确标为“按原书编号预览”，不宣称重演图中未记录的提子，不升级真实 replay 完整性或媒体同步资格。
- 编号错误直接说明点位和原因，修正后自动重检；无编号是合法的 0 步。字母和形状不参加编号检查。
- 人工编辑支持摆黑白、编号摆子、符号字母、坐标修正和真实序列编辑，保留撤销、重做、保存和取消。
- 棋图只保留一个人工确认入口；有草稿时先保存，再用保存返回的新版本审核。失败或冲突不登记审核。
- 人工确认写入 `board_review`；任何棋图内容修改（含真实序列）撤销相应审核，讲解文稿单改不撤销棋图审核。旧媒体按实际依赖失效。
- Astra 或规则检查属于工程／机器检查，不能代替管理员的人工审核；授权代为登记时保留确认来源。

## 8. 音视频交接与交付

- 静态棋图人工审核通过后，才交给现有语音与 2D 视频流程；先用少量图验证，不自动铺开全书。
- `video_2d_review` 独立记录针对具体视频文件和内容版本的人工审核。静态编号预览不自动赋予完整手顺或音画同步资格。
- 交付逐页覆盖、失败／歧义及疑点清单、来源到数据库映射、真实后台入口、校准实例、逐图 SGF 与整书打包来源索引；独立棋图不能串成一盘棋。
- 分别报告识别完成、待人工审核、人工校准完成、真实可回放、仅编号预览和序列待校准数量，避免用“识别完成”代替“人工审核完成”。

## 当前代码入口

在包含当前实现的工作树中核对文件和 `--help` 后使用：

- 识别样例：`scripts/recognize_ishida_remaining.py`；已完成批次的 final 数据与断点存于书籍仓库。
- 增量导入样例：`scripts/import_tutorial_recognition.py`；默认 dry-run，apply 要显式测试环境身份。
- 严格契约：`katrain/web/tutorials/models.py`、`workbench_models.py`。
- 候选与导入：`recognition_models.py`、`recognition_catalog_import.py`。
- 后台保存／审核：`katrain/web/admin/routers/tutorial_workbench.py`、`tutorial_media.py`、`katrain/web/tutorials/manual_review.py`。
- 管理前端：`smartbox-software/admin-console/ui/src/admin/tutorials/workbench/`。

两个识别／导入脚本目前包含石田书及前 100 页冻结检查，**不是任意书籍通用 CLI**。处理其他书先确认已有工具是否支持，必要时最小适配，不能只替换目录就运行，更不能绕过现有来源和环境校验。
