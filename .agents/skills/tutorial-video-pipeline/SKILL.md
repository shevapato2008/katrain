# 教程视频：先音频，再按讲解顺序落子

使用已有电子棋图、真实语音时间戳和棋盘渲染器录制视频，不使用生成视频模型。默认制作 2D 棋盘的 Galaxy 4K 与 kiosk 7 英寸两份成片。

**职责仅为生成。** 不内置质量校验、抽帧审核、抽样计划或 Astra 调用，不把独立审核设为生成下一页的条件。生成完成后交给用户人工检查；只有用户另行要求审核时，才单独派发审核任务（见 tutorial-media-review），不得自动启动。本流程仍处理 API／渲染器自身的输入错误和任务失败，不能绕过现有鉴权、版本及来源约束。

**核心要求：原图已有可靠落子编号时，应随音频依次显示对应棋子。不需要知道整盘棋从第一手如何下到这里；`replay` 待校准不等于不能按编号演示。不能把有编号的视频静态降级后算作完成。**

## 1. 开场局面与语音触发规则

- 开场只显示无编号、无符号／字母标注的静态背景棋子，以及棋盘底板（网格、星位、坐标轴）。
- 带编号、三角、圆圈、方块、叉号、字母等教学标注的棋子先隐藏，语音首次明确提及该对象后，棋子和相应标注一起出现；无编号但带符号的棋子也不能提前显示。
- 棋盘网格外、原书明确用于教学的路线名称和外向箭头同属教学对象，不能归为页眉／装饰而漏掉。用来源绑定的 `presentation_plan.callouts`（边缘 anchor、top/right、短文案及源图 SHA）按明确语音结束显现；不增加棋子或落子声，无 callout 的既有计划与证明保持不变。
- 盘内“隅、边、中央”等原书区域文字同样是教学对象；用 `side: "board"` 与网格内 anchor 按语音显现纯文字，不画箭头、不扩展边距。
- 独立符号、字母、选点标记、箭头等先隐藏，在语音明确提及后显示在来源确认的位置；不能因此凭空增加实体棋子或播放落子声。它们不必属于黑白交替的落子序列。
- 以指代该对象的真实语音片段结束时点触发（不是仅字幕出现或语音尚未说到时）。重复提及已显示对象不重放落子。相同符号有多个对象时，以颜色、位置或明确集合映射；“两颗黑三角子”可同时显示明确对应的两颗，不能显示未提及的其他三角子。
- 每个需展示的教学对象都应有明确讲稿引用及音频 cue。漏讲、指代含糊或映射不可靠时先补稿／校准，不提前展示，也不把遗漏当完成。
- 此规则控制展示层，不改原始棋图、标注及真实规则局面／手顺证据；“没有编号”不代表整图都能开场显示。
- 原书明确展示禁止的立即劫反提时，仅用 `forbidden_ko` 有界录制计划：同书双方来源及前图棋盘／有效静态人审 SHA 均绑定；先静默显现来源初态编号子，完整说完“规则禁止／假设／实际不能”声明后才按完整假设指代显示一次提子。该模式不证明合法 replay，也不放宽普通手顺的来源或劫规则。

## 2. 先选择正确的演示方式

| 棋图证据 | 视频行为 | 不能推断的内容 |
| --- | --- | --- |
| 来源确认的初始局面及真实有序落子 | 按真实手顺播放，依据规则处理有证据的提子、停着和同点再落 | 不补造缺失手顺；也不要求整盘历史 |
| 仅保存的静态图，但印刷编号对应的棋子可靠且顺序明确 | 保留无编号且无教学标注的背景子；编号子按1→2→3→4→5推进，其他标注按语音触发 | 不伪造未记录的提子，不把编号演示写成真实 `replay.status=complete` |
| 无落子顺序，但有符号／字母等教学对象 | 背景局面开场显示，带标注棋子及独立标注在语音提及后出现 | 标注不自动成为真实落子，不要求黑白交替 |
| 既无有序步骤，也无待触发的教学标注 | 可以用静态棋图讲解数气、棋形等概念 | 不把“无编号”与“编号不清／时间线没生成”混同 |

编号演示前核对：编号唯一、正整数、连续（可从任意编号开始）、颜色与坐标准确、黑白交替（可白先）。问题序号、选点标签或同色备选点不能自动当成落子顺序；原书明确的特殊记法另据来源解释。缺号、重号、颜色／点位不确定或提子注记影响演示时，定位并报告，进入校准；不能在无编号背景子上猜补缺失编号。

后台“编号预览通过”表示这些棋子及顺序可用于生成；音画同步仍需真实音频与逐步／标注 cue，**不能因真实 replay 待校准而反向禁止编号演示**。以上分类是内容语义，不能向现有 API 发送未支持的模式字段来假装已实现。

## 3. 固定生产顺序

1. 核对目标环境、当前保存的棋图及人工确认版本；按任务范围跳过识别疑点。机器审核不能代替人工确认，用户已授权代登记时保留原授权来源。
2. 按 tutorial-voice-pipeline 准备准确讲稿，保存最终文字。
3. **先完成真实音频生成**，保存同一次 TTS 返回的 WordBoundary、时长、音频 SHA 和讲稿 SHA。音频任务失败、缺少音频或时间戳时不能进入视频。
4. 从该音频及最终讲稿建立落子与标注显现时间线，以“对象类型＋颜色／标识＋坐标”绑定每个对象。编号按原书顺序推进；符号／字母等按明确语音引用触发，均遵守第1节的开场与提及后显现规则。真实手顺模式仍从来源初始规则局面执行实际落子／提子，不能因显示层暂时隐藏标注对象而改变规则计算。
5. 用同一份音频与落子／标注时间线渲染两个输出档位；落子轻柔、不弹跳，落子声轻于讲解。字幕、棋子编号与自然贝壳纹理在实际输出尺寸下清楚。正式视频不带调试／待校准徽标、原书范围框或灰色遮挡。
6. 两档任务均为 `succeeded` 后保存成片地址、依赖及任务回执，标记“已生成，待人工检查”。不调用审核模型、不建立逐页审核门禁。

讲稿重复回顾早先编号时，不再落一次或倒退。讲稿倒序、缺少中间步骤锚点，或只有“白1到白5”这样的范围引用时，先补充有来源依据的逐步讲解并重新生成音频，再建立 cue；不能按视频总时长平均分配、凭文字长度估时，或在没讲到时机械连播。已合格的音频仅在讲稿、音频哈希与所有必需锚点仍匹配时复用。

## 4. 当前执行入口与展示契约

以当前工作树和部署版本为准。`scripts/generate_voice.py`、`scripts/generate_video.py` 的旧批量生成／固定路径回填已停用；不要恢复它们或直接 SQL 写媒体字段绕过鉴权、版本检查及人工审核。

通过已鉴权的管理后台教程 API 使用以下契约，BASE 从当前环境确认：

- `PUT BASE/figures/{id}/narration`：`{ "expected_updated_at": "当前版本", "narration": "最终讲稿" }`
- `POST BASE/figures/{id}/media-tasks`：先完成有效的 `kind: "audio"`；已有合格音频可复用。读取当前图版本，再提交 `kind: "video", render_mode: "2d", output_profile: "galaxy-4k-v1"`，然后 `"kiosk-7-v1"`。每次写入都带该图最新匹配的 `expected_updated_at`。
- `GET BASE/media-tasks/{task_id}` 查询真实状态；202／queued 不代表生成完成。

**先检查实际实现是否支持选定演示方式。** 若 `build_step_cues` 在 `validate_replay != complete` 时直接返回 pending，或渲染器只会显示最终静态图，说明编号及标注语音触发能力尚未接通。应报告并先修复该缺口，不能修改验收标准、伪造 replay 完整状态，或继续铺量静态视频。

新版 `presentation_plan` 为录制输入：`schema_version: 1`，`bindings` 把最终讲稿字符区间 `[start,end)` 绑定到保存棋图的对象 ID（`labels:x,y`、`letters:x,y`、`shapes:x,y`）；`arrows` 须有当前服务端来源指针及图片 SHA。缺省仅自动匹配可靠的唯一引用；多对象同标记须明确绑定。中文“黑十一”和阿拉伯数字“黑11”均可使用真实语音锚点，不为数字写法重复合成合格音频。

印刷图保留被提的历史编号子，或有同点再落、粘劫注记时，使用来源绑定的 `source_replay` 录制局部手顺：声明初始局面、已知范围、每步动作及来源；未直接印在棋子上的额外动作须附明确 `source_note`。服务端验证规则、提子和来源，原始保存棋图及其 `replay` 不变。不得仅凭缺号补棋；有证据的真实末局面可以不同于保留历史编号的纸书图。初始标记必须在其棋子被提之前讲到，不能将旧标记转移给后来同点重落的棋子。

完整录制证明返回 `mode: presentation|replay|source_replay|forbidden_ko|static`、`objects/events/cues/frames` 及依赖哈希。前端消费这些经过验证的可见帧；pending 必须阻断。两档使用同一个当前展示身份；改变计划后，旧档位文件保留但须重新生成，不能把不同计划的两档同时算作当前成品。

复用已成功且依赖一致的任务／不可变资源。409 停止该图写入并核对版本；写请求结果不明时先只读核对是否已提交，不盲重试。用户暂停后不提交新写入或新任务，保留断点及已有回执；不擅自取消远端任务。用户取消批次时停止该批调度，保留已有成品／记录，禁止自动恢复旧控制器。

## 5. 两份 2D 成片

| 用途 | output_profile | 规格与版式 |
| --- | --- | --- |
| Galaxy 全屏 | `galaxy-4k-v1` | 原生 3840×2160、30fps；放大仍能看清棋子纹理、光泽及编号，不能低清放大冒充 4K |
| RK3562／7 英寸 kiosk | `kiosk-7-v1` | 1024×600、30fps；左棋盘、右字幕，实际小屏尺寸可读 |

两版依赖的源音频 SHA、讲稿版本及落子／标注 cue 一致，只改变布局与输出尺寸。现有实现支持哪些参数以 `media_profiles.py` 和后台 schema 为准；不传 profile 会落入旧档位，不能作为上述任一版本交付。

## 6. 生成完成与交付

- 交付图／页标识、Galaxy 4K 与 kiosk 成片地址、音频与讲稿身份、展示计划、任务状态及失败原因。仅一档成功时明确记为部分生成，不冒充双档完成。
- 生成服务返回的时间线／对象证明和依赖哈希随成片留存，供后续人工或独立审核使用；本 skill 不额外运行全片解码、逐事件抽帧、字幕审计或模型检查。
- “已生成”不等于“审核通过”。不写机器通过结论，不代填 `video_2d_review`／人工审核字段，也不因用户尚未人工检查而自动派 Astra。
- 当前早期阶段由用户人工检查生成效果。机器抽检是否启用、审核哪些页面、采用何种比例，均属于之后单独派发的审核任务；没有该任务时只生成和交付。
- 避免启动持续轮询的模型智能体。任务状态可用普通脚本等待／记录；任务失败或确有生成问题时再处理。历史批次若把 `independent_review` 硬接在生成循环内，不能直接作为纯生成入口；已取消的旧批次保持取消，不为适配新 skill 而自动续跑。
