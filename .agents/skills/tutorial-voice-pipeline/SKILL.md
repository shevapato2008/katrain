# 教程语音与落子讲解

将原书文字、原图及已核对电子棋图整理为讲稿，再生成真实语音及同一次合成的词级时间戳，交给 tutorial-video-pipeline。**先音频，后视频；有可靠落子编号时，讲稿和音频必须支持依次展示这些棋子；符号／字母等教学对象也必须有语音触发锚点。**

本 skill 负责讲稿与音频生成，不内置独立审核／抽检，不自动派发 Astra。当前由用户人工检查，后续机器审核需另行明确派发。

## 围棋术语读音

生成中文语音前读取共享[读音表](../../../katrain/web/tutorials/go_pronunciations.json)。例如“提子”读 **tí zǐ**，子是第三声，不是轻声；棋子、黑子、白子、落子中的子也按棋子语义读zǐ。三声在连续语流中允许正常的半三声／变调，不要求每次夸张读完整降升调。

- **“黑一／白一”（含黑1／白1）的“一”固定读第一声 yī。** 这里是一号棋子的标识，不是数量短语，不因后字声调变成 yì／yí。共享合成规则只将完整编号替换为等长的“黑衣／白衣”；`match_scope: stone_number`阻止命中黑10、黑11、黑一百等数字前缀。讲稿、字幕、棋子编号及触发锚点仍用原文；“一口气、一起、一下”不套此规则。
- 读音表按词与语境维护，不对“一、子、着、长、空”等单字全局替换；“这样子”的子和“紧挨着”的着不能套围棋术语读音。有歧义先核实，新增词条写明拼音、语境和来源，不猜读。
- **表格不能代替合成层控制。** `media_pronunciation.py`只执行有`tts_text`的明确纠音规则；其他词条为正确读音参考，不宣称已强制控制。当前Edge TTS不支持自定义`phoneme` SSML；已确认的“提子”误读通过仅用于TTS的等长同音字“提籽”指定zǐ，保存讲稿、字幕和展示锚点仍是“提子”。不要往保存讲稿写错别字或括号拼音。
- `synthesize_audio`保留同次真实WordBoundary时间，仅将纠音字映射回原字；实际语音文本不匹配时停止，不能捏造时间戳。音频与时间戳同时记录`pronunciation_sha256`；只对命中纠音规则的讲稿生效，未受影响的音频不作废。
- 受影响范围使用`matched_pronunciation_rules(narration, voice)`精确匹配，是否须重做使用`pronunciation_is_current(narration, voice, audio, speech_timing)`；不能用“包含一”或历史完成标记代替当前身份。新增词条不提升词表格式`schema_version`，指纹仅包含实际命中的执行规则；只改来源／备注、增加未命中规则不会使现存有效音频失效。
- 用户指出误读时，先确认规范读音，再更新共享词表中的明确规则并部署到合成服务（仅修改本地skill不会改变后台读音）；只重做受影响音频，再按新真实时间戳重生成对应两档视频，保留原有讲稿、棋图和教学动作。不直接给旧视频换音轨而沿用旧时序，也不把旧词表音频当成已纠音版本复用。
- **地域与空点分开读：**表示所围地域的“空”读第四声 **kòng**，如实空、黑空、白空；空点、空棋盘、空三角、空间中的“空”读第一声 **kōng**。新增词条已追加到共享表末尾，实空／黑空／白空通过`territory_compound`限定语境执行TTS纠音，避开“真实空间”“黑空三角”等词内前缀；不把所有“空”统一替换。“围空”“数空”“九目空”等歧义短语，优先准确改写为“围取实空”“计算实空的目数”“九目的实空”，不能将尚未成立的地域改说成已经围成的实空。
- **动作与数量分开读：**围棋的“数目”指计算地域，读 **shǔ mù**，数是第三声；数气、数子也读shǔ。表示数量的“棋子数目”（shù mù）、“目数”（mù shù）保留第四声。共享表对“数目方法／开始数目／进行数目”提供等长TTS纠音；单独“数目”只有语境参考，不全局替换。其他有歧义的句子先改为“逐点计算目数”等明确说法，或补充经核实的具体短语规则，不仅追加拼音就宣称音频已纠正。
- 纯纠音才保留原讲稿；若同时有书本口吻或纸面要求，先按下节改为最终教学稿，再合成音频、重建cue与双档视频，不因新增词表而保留不合格文案。
- 发布新纠音规则时同步部署共享JSON和`media_pronunciation.py`，让合成进程重新加载词表缓存；新`territory_compound`范围需要匹配代码支持，不能只拷词表到旧进程，也不能为兼容而去掉范围保护。本地规则测试通过不等于线上服务已加载或旧音视频已重制。

## 1. 输入与讲稿

- 核对目标环境、来源页、当前图版本及静态棋图人工确认。用户明确授权代登记时保留确认来源；机器审核不代替人工确认。
- `book_text` 为空不等于无来源：按 figure／来源映射使用原页、`page_context_text` 及来源文字，不能混入邻图结论。图文冲突、颜色／编号／点位不明时定位报告；按任务约定跳过或校准，不猜补。
- 直接查看原PDF和必要相邻页，解析文字仅作辅助；补齐漏掉的前提、图文关系和章节衔接。每幅讲解可独立播放，同时与前后课程的术语和知识顺序一致。
- **面向智星盒用户独立讲解。**书籍和PDF仅作备稿依据；成片口播及字幕不说“原书说／本书／书中／教材指出”，不报纸书页码、印刷题号，不要求“填入空白处／在方框里填写、画圈、打叉”或翻页。来源书名、页码和授权信息保留在后台与来源元数据，不混入口播。把来源叙述改成画面中的观察与棋理；纸面问题改为暂停思考、观察演示并讲清答案和理由。只在真实练习界面可操作时才要求点击或落子，视频播放本身不能假装可交互。
- 关联前后图时，讲清具体的棋形和比较条件，不依赖“上一页／下一页／第几道练习”才能听懂。删除书本措辞不能顺带删掉贴目规则、假设前提、禁止动作或“尚未提走”等棋理边界；这些改为自然、准确的教学语言。保存／提交TTS前逐句检查这些真实已发生的文案问题；“填气、填眼、自填”等合法围棋动作不属于纸面填空，不能按“填”字一律删除。
- 讲稿与教学动画一起设计：每段交付明确的目标棋块／交叉点／路线、视觉动作及触发短语。原图没有画出的气点、路线强调、计数和关系箭头，可以依据原文教学含义与已核对棋局推导后补充到视频辅助层。
- 使用能定位画面的具体说法。例如先讲“左边三口气”“右边三口气”“上下一口气”，再总结总数；路线讲清从哪条边往内数。避免只说“这里”“这几个”而画面没有指示。对数气、打吃等能确定性推导的练习给出答案与理由，条件不足时说明限制。
- 根据原书准确改写观察、原因和结论；保留必要条件、否定、提子／粘劫／同点注记。不凭静态图编造未记录的变化、提子过程或题目答案。
- **已有可靠编号：**先说明背景和轮谁下，再按原书顺序讲出每步的颜色与编号，例如白1、黑2、白3、黑4、白5；任意起始编号／白先均可。不要求整盘棋历史，也不因真实 replay 待校准而省掉这些步骤。
- 编号的颜色和坐标来自已核对棋图；描述棋理须有来源依据。讲到每个新落子时给出明确语音锚点，不能只说“1到5”而省掉中间步骤。后文回顾先前编号须与新落子叙述区别，不能让时间线倒退或重复落子。
- 首次明确引用也包括“标着数字一的是黑子”这类完整、无歧义的编号＋颜色陈述；按该句真实结束点显现，不延迟到后来重复的“黑一”，已有有效音频无需重做。
- 逐一覆盖需展示的符号／字母标注棋子、独立符号／字母、选点、箭头等，给出有来源的准确指代；多个同符号对象用颜色、位置或明确集合区分。它们在首次明确提及的真实语音片段结束后才出现，不能漏讲后默认开场显示。
- 有提子／同点续下时，先讲清被提的初始标记对象，再推进到提子；不能在它已被提走后才首次引用，或把旧标记套在新落的棋子上。按来源逐步讲清粘劫等补充动作；中文数词与阿拉伯数字均可作准确编号锚点，已有合格音频不因写法差异重做。
- 只有无编号、无符号／字母教学标注的静态背景子可在开场显示；没有有序步骤但有符号／字母的图仍需要标注触发时间。问题序号、备选点标签不自动成为真实手顺，但作为教学标注也应在提及后显现；不能靠改写讲稿猜出缺号。
- 每幅视频可独立播放；比较其他图时交代有明确来源的关键棋形／处理，不能只报图号。字幕保留原讲稿完整句或原分号分句，不按固定字数截断颜色＋编号、否定及条件与结论；长句按现有目标设备排版核对，已有合格音频不因旧字幕硬截断而重做。

## 2. 保存讲稿并生成音频

当前入口是已鉴权的管理后台教程 API。BASE 按当前环境核对，不使用公开客户端写接口或直接 SQL：

1. `PUT BASE/figures/{id}/narration`，请求仅含最终 `narration` 与匹配当前版本的 `expected_updated_at`；保留用户手改稿，不用批处理强制覆盖。
2. 用保存返回的当前版本提交 `POST BASE/figures/{id}/media-tasks`，`kind: "audio"` 并带 `expected_updated_at`；语音默认由当前服务配置选择（现有默认 `zh-CN-XiaoxiaoNeural`）。
3. `GET BASE/media-tasks/{task_id}` 等待真实 succeeded；202／queued 不算完成。失败不能用静音 MP3、原文兜底文件或仅有路径冒充成功。
4. 保存任务返回的真实音频地址、时长、音频 SHA、讲稿 SHA、voice 及该次合成的 WordBoundary。音频或时间戳缺失时报告生成失败；本流程不另起全片解码、听音或模型审核。
5. 把编号子、带符号／字母的棋子、原书独立标注，以及新增教学辅助动作的点位／分组／计数与真实语音片段结束时点交给视频流程；编号子需顺序正确，其余按明确引用触发。缺锚点、指代不清或顺序不符时先最小修稿／重新合成；已有合格音频可绑定新辅助动作时直接复用，不平均分配时间、不提前显示。

修改讲稿或命中的纠音规则会使旧音频／视频依赖失效。两份视频应复用同一合格音频与时间戳，不分别合成不同长度的音轨。已有音频只有在讲稿／音频哈希、voice、当前纠音规则身份和所需逐步锚点都一致时才能复用。

409 停止该图写入并核对版本；结果不明的写请求先只读确认是否已提交。用户暂停后不提交该批次讲稿／棋图／审核等业务写入，也不创建新任务；保留任务回执与恢复点，只读核对。

## 3. 当前实现与交付

`scripts/generate_voice.py` 的旧批量生成已停用；不要照旧 `--force` 或直接数据库写入流程绕过当前鉴权、版本和人工审核。音频成功也不表示落子时间线成功：服务若因 `replay` 待校准未产生编号 cue，需按视频 skill 补齐编号同步能力，不能说音频失败或降低视频验收标准。

交付：来源／图版本、最终讲稿、真实音频与时间戳／哈希、逐步编号及符号／字母等对象映射、生成成功／失败及待校准状态。来源或指代不确定时报告问题，不猜补，不擅自派模型审核。独立内容／音视频验证见 tutorial-media-review，仅在用户另行要求时使用。

生成成功不代表人工或机器审核通过，不代填审核字段。批量范围、并发与汇报频率按用户当前任务执行，不把单图音频成功算作整页音视频完成。用户暂停或取消时停止调度，保留结果且不自动恢复。

代码入口：`katrain/web/admin/routers/tutorials.py`、`tutorial_media.py`；`katrain/web/tutorials/media_tasks.py`、`media_timing.py`；视频交接使用 tutorial-video-pipeline。
