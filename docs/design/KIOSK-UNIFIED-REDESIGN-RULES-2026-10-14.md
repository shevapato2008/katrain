# 智星盒 Kiosk 统一改版规则

更新：2026-10-24。配套参考为[围棋界面设计集合](kiosk-current-based-redesign-2026-10-14.html)。本文记录已确定的视觉与交互原则，供围棋、五子棋等棋类模块复用。HTML 中的棋盘、棋谱、复盘和课程是**围棋实例**，不是五子棋的页面清单或业务契约。设计稿、实机截图和已上线实现可能处于不同阶段，页面事实以目标设备与当前代码为准。

## 1. 不动的基础几何

- 围棋目标画布为 **1024 × 600**，顶部栏 56 px，一级页面底栏 82 px。五子棋若在同一设备和外壳中运行，也应在 1024 × 600 实机核对，但棋盘与内容区尺寸必须依据五子棋页面确定。
- 围棋二级对局页以实机 **516 px 棋盘区、460 px 右栏**为准。这是围棋稿的几何参考，不应机械复制到五子棋。页面内可以重排卡片、选项和文字；不缩小棋盘给文案腾位置。
- 对局页右栏在 1024 × 600 下默认完整呈现当前操作。内容确实超出时，用清楚命名的页内 Tab 分组；说明放在信息弹窗。Tab 与弹窗必须保留原有信息和功能入口。

## 2. 字体和信息层级

中文默认 **霞鹜文楷（SmartBox Kai）**；若提供设置，另可选真正不同的 **楷体（CNS Kai）、隶书（刀隶体）、黑体（Noto Sans CJK）**。字体资源须在目标设备实际加载，不能只声明一个字体名或依赖 macOS 本机字体。中文字体只影响中文；英文字母、阿拉伯数字和棋盘坐标保持各自固定字体，数字列优先用等宽数字字体。新绘制的数字在本围棋设计稿中使用 **IBM Plex Mono**。每张 1024 × 600 页面优先使用以下三档，不用缩小字体解决拥挤：

| 字号 | 用途 | 示例 |
| --- | --- | --- |
| **28 px** | 当前页面名称、主数据或当前轮次；每页最多一类 | “对弈”、胜率、倒计时 |
| **22 px** | 可点击的文字、选项值、卡片标题、当前状态 | “自由对弈”、“开始对局”、“黑方” |
| **18 px** | 必须常显的辅助数据、字段名、次级状态 | “中国规则”、“已连接”、“提子 1” |

- 一页优先只用 **22 / 18 px**；只有主要数据需要突出时才加 28 px。图表轴、棋盘坐标等固定素材可另定。不得靠字号随文本长度变化或极窄行距塞下更多字。
- 顶部品牌图形、棋盘交叉点与坐标、分析曲线轴标属固定视觉素材；围棋稿中新绘制的棋盘坐标统一为 18 px。旧实机截图中的小字不能作为“新版文字”裸露：涉及改版区域必须遮盖并重绘。
- 文字与深色背景保持清晰对比；弱化依靠颜色和层级，不能依靠缩小字号。重要信息一行放不下时，先缩短文案，再调整组件排列，最后拆 Tab。
- 保留标志和“智星盒”龙藏行楷。英文品牌字 **StellaBox** 单独使用实际加载的 **Fondamento Regular**；仅微调英文的字号、字距和基线，不改变品牌顺序、颜色与顶栏布局，也不受中文字体切换影响。
- 四个中文字体选项的标签始终用其**自身**所代表的字体显示，不随当前选中项改变；各标签在按钮内水平、垂直居中。设置入口放在“关于”之前。字号以现有大字号为最大，再提供小一档、小两档。切换字体或字号后，该棋类模块的页面和弹窗立即同步变化，设置页本身就是预览，不另设孤立预览框；设备重启后保留上次选择。跨棋类是否共用此设置须明确决定，不得无意影响启动器或另一棋类。

## 3. 同类按钮同形，同功能同名同图标

| 组件类别 | 统一尺寸与布局 | 统一状态 |
| --- | --- | --- |
| 围棋一级底栏七个入口 | 每个入口等宽；高 68 px；24 px SVG 图标和 22 px 文字**水平**排列 | 当前项绿底深字；其他项深底浅字 |
| 一级页面模式卡片 | 同一页面采用同宽同高、同圆角；图标 24 px、标题 22 px 水平排列。不可用项仍占同类位置 | 可用、当前、禁用按同一套颜色处理 |
| 二级主要操作 | 高不小于 48 px，文字 22 px；同一操作区宽度规则一致 | 主操作绿底，危险操作红色轮廓 |
| 二级次要操作 | 高不小于 44 px，图标 22 px 与文字 22 px 水平排列 | 禁用状态清晰且不能触发 |
| 设置项、Tab | 同排等高；文字 22 px，必要字段名 18 px | 选中态统一深绿底 |

触控目标最小 44 × 44 px。图标使用仓库已有 SVG / 同一套 24 × 24 线性图标，不用 emoji、Unicode 符号或临时不同风格的图形代替。

按钮材质统一采用已选定的**圆润软键**：沿用各棋类既定主题色，用圆润轮廓、柔和顶部反光、底部暗边和外阴影呈现凸起，按住后下沉并改为内阴影。可点击列表卡片、弹窗操作和分页按钮也要有一致的立体层级，不能只给大按钮加阴影；纯数据表行不强加凸起。禁用按钮保持同一轮廓，但不凸起、不响应按压。信息按钮与播放等圆形操作保持圆形，圈内图标必须视觉居中。

同页导航入口使用同一按钮尺寸与圆角，按钮外不再叠加另一层不同圆角的卡片背景；入口卡片本身不逐个放说明图标。可展开的设置项也使用同一软键凸起与按下状态。大厅的导航键和 Tab 比对局内容卡片更紧凑；本地对局侧栏的次要操作每行两列、各键同宽，常用的“确认落子”独立放大。

同组的页面 Tab、筛选选项和“开／关”分段控件统一采用训练营首页的样式：整组为**连续的深绿内凹圆角容器**，选项紧贴、只留很窄的容器内间距，不形成几枚彼此悬空的按钮；当前选项是容器内略微缩进的立体软键，具有顶部反光、底部暗边和轻微阴影。首尾与容器边缘贴合；按下时选项下沉，容器位置不动。标签较多时优先**单行横向触控滚动**，如报告分析标签，不靠缩字或挤成两行。搜索框、说明按钮及独立操作按钮不并入容器。

“坐标”“手数”等可切换按钮只显示**图标 + 功能名**，同组等宽；选中外观与 `aria-pressed` 表达开关状态，不在按钮内再写“开／关”。设置页中“开”“关”分别是两个明确选项时，保留选项文字。

同组按钮应以**图标与文字构成的可见整体**水平、垂直居中，不能只把按钮盒子放到中间。图标、文字、边框的光学中心需在目标尺寸截图中检查；圆形说明键的 `i`、分页箭头和字体选项尤其如此。相邻等价按钮保持等宽等高，状态框内的标签和值留出上下空间，不能压到边框。

以下词表是**围棋模块示例**；五子棋只复用“同功能同名同图标”的原则，另定自己的词表。

| 功能 | 固定文字 | 固定图标语义 |
| --- | --- | --- |
| 底栏 | 对弈、训练营、棋谱、复盘、成长、课程、设置 | 游戏手柄、拼图、棋谱册、棋盘格、趋势线、书本、齿轮 |
| 返回上一级 | 返回 + 目标页名（如“返回对弈”） | 左箭头 |
| 开始 / 退出 | 开始对局 / 退出对局 | 播放 / 左箭头 |
| 对局操作 | 领地、支招、图表、数子、悔棋、停一手、认输 | 折页地图、灯泡、趋势线、四方块计数、回转箭头、手、旗帜 |
| 棋盘显示 | 坐标、手数、实体棋盘 | 九宫格、数字列表、相机 |
| 说明 | 说明（视觉为圆圈 i） | 同一信息圆圈图标 |

同功能跨页必须复用固定文字与图标；页面已有更具体的真实功能名称须保留，不能为了统一而改成错误的动作。

## 4. 文案与说明

- 主界面只留下完成当前动作必需的信息。模式卡片只显示名称和必要状态，点击卡片直接进入对应页面；不在每张入口卡片上放“说明”圆圈 i。设置规则、实体棋盘状态等需要解释的内容可在区块标题旁保留说明入口，点开后用 18 / 22 px 字显示原说明，关闭按钮 44 × 44 px 以上。
- 选项直接显示用户关心的值：如 **“对手 6 级”**，不强调内部“第 15 档”；贴目、路数、规则、让子与对手按同类虚拟按钮呈现。字段名和数值分别使用 18 / 22 px。
- 用时从当前页面**可选范围内的最大值**开始：自由对弈、本地对局是“不限时”；升降级对弈的选项不含“不限时”，最大是“60 分 + 30 秒×3”。这项是提案默认值，当前设备默认值以实机为准。
- 实机当时未连接、未登录、不可用的功能必须如实显示；示例数据须标为“设计示意”。不凭设计稿增添实机代码没有的入口。
- 说明、等待、错误、确认等状态都用相同规则；必要的警告可常显，不能隐藏到说明里。

## 5. 最近补充的列表、分页与状态规则

- **选择与进入分开**：对有相邻预览的记录列表，卡片主体负责选中并更新预览；“查看棋谱”“查看分析”等进入动作由明确的独立按钮负责。删除图标与卡片主体分开，只在该项被选中、且确实允许删除时显示。模式入口卡片仍可直接导航。其他棋类可复用这一交互关系，但动作名称和删除范围以自己的业务为准。
- **预览对应真实选中项**：有棋局预览时展示所选记录的真实终局或当前约定局面；没有分析或报告时，相关按钮灰显且不可点击，不画虚假的胜率、推荐或进度。点击卡片不应悄悄跳页。
- **跨卡片对齐**：同语义字段使用固定列和共同基线。中间的胜负结果在所有卡片间横向、纵向对齐；棋子标识、落点坐标等表格列应从同一左边界开始，不能因每行字数不同分别居中。文案采用符合该棋种习惯的语序，围棋例如“白中盘胜”。
- **搜索与类型**：保留记录列表的搜索入口；若对局类型已经在卡片上明确标注，就不要额外添加没有筛选价值的“全部／面对面”等 Tab。卡片类型、结果、时间和双方信息使用稳定的跨卡片列布局。
- **分页保留能力**：长列表可按数据量分页；分页栏使用同一软键材质，提供首／上一页、当前页、下一／末页和输入页码跳转，边界键正确禁用。可精简可见页码，但不能在精简时丢掉指定页跳转。围棋稿的“每页 20 局”只是该页面的决定，不是五子棋通用值。
- **菜单和弹窗有明确职责**：按钮下拉菜单清楚展示动作，并按真实状态区分“生成”和“查看”；确认弹窗说明后果，取消与确认同样好点。信息说明入口按当前区块或当前选中 Tab 设置，避免每个 Tab 的 `i` 与右上角说明重复。
- **能力按平台展示**：RK3562 不提供桌面本地文件导入，Galaxy 网页可提供本地 SGF；这是围棋导入场景的例子。五子棋应按设备实际文件能力决定入口，不照搬 SGF 文案。
- **交互不误触**：主轮播卡片本身和两侧卡片均可左右滑动；横向 Tab、纵向列表与棋盘点击各有清楚的触摸区域。加载、离线、未分析、已完成、失败和权限受限须如实区分，未完成内容不得呈现完成态。

## 6. 按现状复原与分批验收

1. 每页先核实对应的 RK3562 截图与当前 React 页面结构，记录“现状 → 改动”。旧 Claude 稿只能提供视觉参考，不能替代现状。
2. 同一批页面共用组件和词表。先检查 1024 × 600 原尺寸，再用滑杆看同位置的实机与提案，检查是否遗漏小字、图标、按钮尺寸、状态、功能和是否出现右栏滚动。
3. 以一个可操作的用户旅程为单位完成设计核对；先有同尺寸可视预览，再对接真实数据与行为。页面确有字体切换、选中、弹窗和滚动时，至少检查这些状态中最易出错的一个代表状态，不机械全量重拍。
4. 设备无法进入的状态保持明确的“未采集 / 设计示意”标记，不把推测画面伪装成实机复原；生产界面不能混入模拟业务数据。

## 7. 评审逐页核对

- 页面事实与实机及代码一致，尤其是本地双人居中棋盘、成长首页、分析报告。
- 主要文字层级优先使用 18 / 22 / 28 px；固定素材如坐标和图表轴有合理例外。说明文案已收纳，必要状态没有被隐藏。
- 同类按钮等高等形，同功能同名同图标，图标没有丢失；点击目标至少 44 px。
- 1024 × 600 下无截断、重叠或被迫阅读右栏滚动；Tab、弹窗和返回动作可操作。
- 对有实机参考的页面，滑杆 0% 是实机截图，100% 是完整改版页面；无实机状态应明确标为设计示意。不允许把旧截图中的小字当成新版保留。
- 特别检查标题上沿是否被挡、状态文字是否压到边框、圆形图标是否居中、Tab 是否贴合容器、按钮及卡片是否有正确立体感、跨卡片字段是否对齐、分页输入与跳转是否可用。
- 页面内可点击目标至少 44 × 44 px。若有字体设置，至少核对大字号和一种字形明显不同的中文字体；英文、数字、品牌字及各字体选项本身保持固定字体，切换后无裁切。

## 8. 交给五子棋开发 session 时

先以本文确定共享外壳、字体分工、触控材质、Tab 和验收方法，再用五子棋的当前设备截图与真实功能决定页面结构。可参考[围棋设计集合](kiosk-current-based-redesign-2026-10-14.html)的**视觉处理**，但不要直接沿用围棋七入口底栏、516／460 分栏、棋谱／复盘结构、贴目术语、SGF 导入和 OGS 课程流程；只有五子棋产品确有对应功能时才设计相应入口。
