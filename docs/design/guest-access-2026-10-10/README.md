## 登录时效和这次截图

两台服务器运行配置均为 `ACCESS_TOKEN_EXPIRE_MINUTES=10080`（7 天）、`REFRESH_TOKEN_EXPIRE_DAYS=90`。Galaxy 登录保存 access token；当前前端未保存或调用 refresh token。因此正常期限是**从签发时起 7 天**，不是闲置 7 天，也不是打开网页后再续 7 天。没有前端闲置登出定时器。RK3562 严格盒端另走 launcher 的 HttpOnly SSO cookie，不能把 Galaxy 的浏览器 token 生命周期直接当作盒子会话期限。

本次具体登出原因尚未确认：无法读取用户当时浏览器的认证响应。源码确认存在两种非正常表现：

1. `AuthContext` 首次 `/auth/me` 的任何非成功响应，包括 5xx，都可能清除保存的 token；应仅对确实失效的认证响应处理认证失效，403 也应按具体原因区分。
2. 8 秒探针超时或网络失败会将 user 设为空，显示为未登录；异常不应被设计成“登录已过期”。

大厅永远加载的原因已确定：`HvHLobbyPage` 没有页面登录门禁，缺 token 时请求函数提前返回，`loaded/rankLoaded` 不结束。无请求不代表正在加载。未来改造应先判断认证状态，再挂载受保护内容，而不是用模糊样式隐藏旧列表。

## 改造前模块清单（访问政策依据）

“未登录”指没有真实账号会话；盒子 `username=guest` 是另一种有技术凭据的访客身份，当前守卫只检查 `isAuthenticated`，并不等于真实账号。下表首先准确记录匿名访问；访客身份的差异单独列出。不能仅凭按钮禁用或路由守卫判断后端授权。

### 保留 guest 身份差异

- `AuthContext.isGuest` 识别 `username=guest`；当前 `KioskAuthGuard` 仅检查 `isAuthenticated`，所以技术上的 guest 会话可能穿过路由门禁。
- 个人棋谱、复盘写入、兑换、关注等使用 `require_writable_user`，拒绝这个共享身份；死活题前端已明确不向云端写访客进度。
- 严格盒端在线大厅还需能转发真实中央账号身份，访客不能用“存在 cookie”代替真实账号登录。后续只针对已要求真实账号的功能补齐访客引导；其他现有访客允许功能维持原政策。

## 统一设计

主表面为浏览页面。沿用已批准的 Galaxy 对局舞台和 kiosk 星阵式大厅；使用现有字体、青绿色、控件和触控密度。中文文案使用霞鹜楷体（现有 LXGW WenKai 字体资源），Galaxy 的英文与数字也保持楷体；kiosk 外壳保留原 Latin 字体。

### 页面门禁

- 未登录的受保护页面显示公开标题、静态占位轮廓，内容区模糊；不读取/保留真实棋友、棋局、账号记录、人数或段位。导航与品牌保持清晰，但弹窗在场时其他控件不可交互。
- 居中弹窗标题“登录后进入对战大厅”，说明能进行的操作。主按钮“登录并继续”，次按钮“返回对弈”；其他整页模块沿用结构，替换准确的模块名称、原因与安全返回目标。
- 无关闭叉、点遮罩不关闭；Escape 等同次按钮返回公共入口。受保护内容不可能因关闭弹窗而露出。初始焦点在主按钮，焦点在弹窗中循环。
- Galaxy 点击主按钮打开既有登录/注册流程，取消回到该引导，成功回到原安全的站内目标。
- RK3562 使用统一 launcher SSO 登录入口，不在围棋页再造账号密码表单。当前 launcher 尚无本稿确认过的“登录后直返具体模块”契约，因此**文案只承诺去盒子主页登录，随后从围棋入口返回**；跨应用直返仅在确认 launcher 支持后实现。

### 操作门禁

- 公开页面继续展示公开内容；只在点击分析、云端保存等受保护动作时弹提示，允许“继续浏览”取消。
- 登录后保留当前棋盘、输入和安全的继续目标；付费、保存、删除等动作仍由用户确认，不隐式重放。
- 无权访问、未定级、平台断开、引擎故障分别保留自己的提示，不统一成“去登录”。

### 认证状态

| 状态 | 呈现与行为 |
| --- | --- |
| 检查中 | “正在确认登录状态”，占位背景；不宣称游客、不请求保护内容，不强制跳登录 |
| 明确未登录 / 技术访客需要真实账号 | 登录引导，按两端实际登录流程继续 |
| 明确认证失效 | “请重新登录”，说明已暂停个人内容读取；不从一次网络失败推断 token 到期 |
| 网络或服务不可用 | “暂时无法确认登录状态”，按钮“重试 / 返回”；保留凭据，不清除或执行注销 |
| 已登录但无权访问对象 | 原模块权限提示，安全返回；不要求重复登录 |

## 实现边界与最低验证

- 后续应用改造优先共享认证状态和引导组件，按路由元数据提供模块名称、原因和安全返回；页面门禁在挂载 protected children 前判断。先闭环两端大厅，再复用已确认模式，不扩展账号体系。
- 退出/换号时立即卸载受保护内容，取消轮询、WS 和未完成请求；未登录不生成虚假 0 人在线/0 局的统计。恢复身份不以 `token` 有无判断严格盒端是否登录。
- 聚焦验证：匿名大厅无受保护内容请求；网络失败保留凭据并可重试；登录成功回到目标；退出不留旧内容；guest 不绕真实账号限制；两端目标 viewport、中文实际字体、焦点/44px 触控范围。
- 生产应用不放设计样例。HTML 原型没有真实登录、没有业务数据或访问策略变更。
