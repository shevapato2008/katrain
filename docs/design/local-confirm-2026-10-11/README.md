# 本地实体盘对局 · 逐手确认设计

方案确认：2026-10-11；HTML 预览与审核：2026-10-12。

## 范围

本轮设计为独立 HTML。用户已于 2026-10-12 确认该稿，并追加屏幕版逐手确认需求：点击先预选，可多次改选，仅显示最后选择的落子标识；确认成功才入谱、换方并播放落子音效。实体盘和屏幕版共用该三栏布局，终局保持现有界面。原 HTML 演示仍以实体盘为主，屏幕行为在真实前端切片中验收。

- [打开 HTML](./index.html)：字体、品牌图与终局参考截图均内嵌，可离线打开。
- 本地预览：`http://127.0.0.1:8864/index.html`。
- 目标画布 1024×600；页面下方的状态选择器为审核工具，不属于产品。
- 表面类型：Operate（操作台）。单一确定方向：黑方在左、棋盘居中、白方在右。
- 布局：16px 外边距，224 / 512 / 224px 三栏，16px 栏间距。玩家面板高 516px，棋盘 512px；确认键实际 190×108px，辅助按钮 58×44px。
- 沿用仓库青玉/深灰/木色、龙藏品牌字、霞鹜文楷、Geist/Newsreader 与 JetBrains Mono。等待方通过背景、边框和文本色降低亮度，避免整栏 opacity 使姓名、时间难以读取。

## 已确认的回合与计时规则

1. 开局语音：落子并拿除提子，移开双手，按本方确认；听到确认提示、对方区域亮起后，对方再下。
2. 当前方落子期间计时；只有当前方可确认或停一手。
3. 按确认后双钟暂停；本次识别锁住双方动作，重复点击不产生第二次提交。
4. 使用点击后的新画面，待手移开和盘面稳定。只接受一手合法变化，允许与本手相符的提子。
5. 成功入谱后发短音，启动对方棋钟、切换面板亮度，并关闭本次识别。
6. 无棋子、多颗新棋子、遮挡/超时、提子未拿净均不换方、不入谱；提示具体操作，恢复本方计时，整理后重新确认。
7. 相机保持采集与标定就绪，回合识别及盘面对比在确认期间开启。待确认时不沿用连续落子注入，不以旧帧/旧事件触发误报。
8. 停一手需要短暂核对实体盘没有未确认的落子；双停继续沿用自动数子。数子门槛读后端下发值。
9. 双方认输均指本方，保留二次确认；等待方可认输。识别过程中先锁住，识别结束后恢复。

## 预览状态与交互

URL 可带 `?state=black|white|recognizing|retry|nostone|multi|capture|byoyomi|guide`。

- 主流程：点击本方大确认键，识别演示约 1.5 秒，成功后换方并响短音。
- 页面下方的“本次识别结果”决定演示成功或哪一种错误；重试前可改回成功。
- 识别期间双方时钟不走；失败恢复本方；白方等待时也可打开“白方认输”确认框。
- “现有终局参考”以及演示中的认输/双停显示既有截图，**不是本局模拟生成的终局结果**。该截图用于确认终局视觉范围保持不变。
- 数子按钮在第 33 手样例中禁用，页面明确写需满 100 手。未接真实手数、门槛或分析服务。
- 开局引导可播放浏览器中文语音；实际应用需接现有语音资源，不依赖原型的浏览器 TTS。

## claude-design 自检与 UI/UX 优化

初稿使用 claude-design 的操作台构图与现有产品视觉体系。自检的十项常见模板化信号为 0 项：没有营销 hero、功能卡片网格、无依据的大数字、装饰性侧条、技术渐变或默认 Inter。大时钟直接服务双人计时。

随后使用 ui-ux-pro-max 的设计系统搜索与 touch / loading / recovery / contrast 检索。综合搜索返回的营销布局与本任务不符，未采纳；采用适用的交互规则并保留仓库设计系统。优化包括：44px 辅助触控、108px 大确认键、固定按钮位置、14px 状态标签、明确重试动作、双钟暂停说明、成功短音、可见键盘焦点、弹窗焦点约束、aria-live 和 reduced-motion。

## 与现有对局屏的预期差异

参考图为 `superpowers/tracks/kiosk-local-play/impl-shots/05a-game-local.png`，尺寸同为 1024×600。

- 构图：从左棋盘/右动作栏改为黑方/棋盘/白方三栏；棋盘由 516px 收至 512px。
- 几何：棋盘与确认键居中对称，双方辅助动作和确认键的高度、纵向位置一致。
- 层级：双方时钟升级为主要信息，大确认键升级为首要操作。
- 字体/色彩/材质：保持现有字体与语义色；待走棋方亮起，等待方降低亮度；异常用琥珀。
- 素材：品牌图复用；棋盘为准确的 SVG 网格与示例棋子，不接生产棋局；待处理标记与实际入谱棋子区分。
- 显示选项：原型固定显示坐标和最后一手标记，暂未安排现有“坐标 / 手数”开关的位置。这个取舍随本稿提交用户确认，不能据此在生产实现中直接删除原有显示偏好。
- 文案/状态：增加逐手确认、识别中、未入谱重试与提子未拿净状态；认输区分本方。

## 浏览器验证

- 在 Chromium 的 1024×600 画布检查黑方、白方、识别中、重试、多子、提子、读秒与开局引导八种状态；无 JavaScript 页面错误，双方面板、时钟、提示与确认键无内部溢出。

## 下一阶段约束

用户审核通过后，才设计接口契约与实现计划，再开展 Fixture 前端、同尺寸视觉对比、后端集成及测试。

- 权威：后端拥有当前方、节点、计时暂停区间、确认请求结果；前端不自行切换真实回合。
- 确认至少绑定会话/对局/节点/颜色与唯一请求，旧请求、迟到事件和刷新重试不得提交两手。
- 识别资源预算需 RK3562 实测，本原型的 1.5 秒不是性能承诺。
- 超时/断连/相机故障需要有限等待、重试或沿用已有恢复路径，不能把对局永久停钟。
- 每手帧仅用于本机识别，不新增持久化相机图像或远程传输。
- HTML 中所有演示状态与业务数据只存在此设计目录。生产验收前，临时 Fixture 必须删除，真实计时、落子和错误由后端下发。
