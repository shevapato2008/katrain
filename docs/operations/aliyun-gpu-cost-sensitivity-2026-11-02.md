## 计算输入与公式

直接使用已有[完整报告原始结果](artifacts/membership-cost-20261101/full-report-result.json)：tf3-b11c768，305手、306位置，逐一串行500 visits，ownership开、policy关，预热引擎，总耗时 **397.483996633秒**。没有新增GPU请求。

- 每标准单位时间 `t = 397.483996633 / 306 = 1.298967309秒`。
- 300手报告取301位置，归一估算耗时 `301t = 390.989160087秒`，并非另测一份300手报告。
- 30天取 `T = 2,592,000秒`，在同速假设下名义吞吐 `Q = T/t ≈ 1,995,431.280标准单位`。
- 月租情景 `C = 3500 / 3817 / 4579元`。3500为用户原假设，后两项为截图价格输入；把厂商“1个月”用于30天预算比较，不声称包月等价于720小时按量价格。
- 成本公式：`单位租金 = C/(κQ)`；`报告租金 = 301C/(κQ)`；`套餐满用租金 = UC/(κQ)`。
- Plus / Pro / Max的30天额度 `U = 9030 / 36120 / 117390`，候选售价 `P = 29 / 99 / 299元`；满用租金余量比例 `(P−UC/(κQ))/P`。该比例仅扣租金，不是包含全部费用后的经营毛利。

## 容量不随租金变化，仍不是可销售容量承诺

同速假设下，三档租金的 `Q`相同。κ100%为约1,995,431标准单位 / 30天，相当于约6629.34份300手报告；κ50%为约997,716单位，相当于约3314.67份。租金改变单位成本，不改变计算吞吐。

| 假设 | Plus | Pro | Max |

它们未验证峰值、周上限同步耗用、排队、前台web与cron争用，也未包含真实报告任务的持久化与网络耗时。现有样本是预热的单份连续棋局；用户也可用预算做零散局面，不能保证所有耗用都取得该样本效率。
