# V100 请求成本实验资料

2026-11-01。原始引擎实验与本机派生计算，均不是支付、数据库或产品容量验收。

- `engine-benchmark.json`：75查询／121.06秒的原始时序、实际模型SHA及样本信息；本轮没有重新部署模型。
- `bench.py`：实际执行程序，单实验240秒提交期限、40秒HTTP超时、最多3并发、priority=-100；不清NN缓存、不连业务数据库、不写账、不改服务配置。输入为当前目录`input.json`，请求服务器localhost8000/8002，输出当前目录`result.json`。
- `input.json`：由仓库`tests/data/panda1.sgf`用`katrain.cron.sgf.parse_game`提取的合法主线／初始摆子，不含解说。原谱来源及许可见仓库谱头；致谢PANDANET，保留SHA和源路径以复核。
- `economics.json`：在用户最终澄清前，以250手、5000等单位试算的历史探索，**已失效**，不得当成当前目录。
- `economics-300-move-v3.json`：最新300手／301位置、Plus期9030及周2107的派生数据。用户质疑保守成本命名后，已加入完整序列实测，保留29／99／299为候选，Pro／Max总量拟4／13倍；不是用户已批准的目录。
- `full-report-result.json`、`full_report.py`、`report-input.json`：补测公开305手棋谱24145，全部306位置串行500visits完成397.484秒。只读公开API取得棋谱，没有创建业务报告任务或写资金；实际脚本设20分钟提交期限、40秒请求超时、单并发、低priority，不重启或清缓存。

本次仅在新PROD `ucloud-v100`（117.50.177.254）运行约两分钟有界引擎查询。测试前后两引擎ready，结束GPU0%、1872MiB。程序已经结束，不驻留轮询或占用服务。

复现方法是将`bench.py`和`input.json`放到目标机器的独立临时目录，确认实际模型和负载后运行`python3 -u bench.py`，再保存result.json。这会实际占用GPU；不要为复现而默认重跑生产，更不要清缓存、重启或用错误IP。输入SHA、脚本SHA、请求id/final/turn/实际visits/模型身份都在结果或程序中留存。测量仍受已有NN缓存和同一棋局局部性影响，不是冷缓存或多用户端到端负载。

第一组75查询不含完整报告；后续补测完成305手的完整306位置序列，但不是含业务数据库／队列／前端的ReportTask验收。300手301位置的耗时是从该序列归一，30天满载仍仅是外推。
