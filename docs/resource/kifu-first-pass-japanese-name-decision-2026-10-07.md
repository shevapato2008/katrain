## 一、中文与繁中显示

- **中文 SGF 姓名：**清洗掉已明确识别的段位、空白等非姓名成分后，可按用户授权保留来源中文文本。保留实际 PB/PW、来源及有限 raw 范围；记作“来源中文原文/默认显示”。不能仅因汉字外观就断言中国籍、汉语原名、已核中文译名或批准人物合并。
- **非中文姓名：**已有可靠同人中文用名优先；合理检索仍未取得时可保留已核原名。Wiki API 403/超时记录为访问失败；可尝试正常文章页或一次可用搜索，无须反复修 API。说明“本轮未取得中文用名”，不写“没有中文维基/没有中文名”。
- **JP→TW 原样保留：允许作为首轮原文显示。**源语言仍 `ja`，输出逐码点等于本人日文全名；不把 `泉谷実／浜島久義／出雲栄次` 自动改成臆测的简繁形式，也不声称这些是台湾习称或规范繁中字形。即使 `染谷一雄／日下包夫` 恰好字形通用，也只按实际证据记录。
- 现有 `primary-orthographic-v1` 的中文分支和 [KBA Hanja 保留分支](../superpowers/plans/2026-10-07-kifu-official-hanja-preservation.md) 均不能承载日本来源。不得冒填 `chinese_origin=True`、`source_lang=ko` 或官方 person ID。**本次不扩展该门；先复用原文回退显示。**已核实 CN/TW 用名不得被原文回退覆盖。

## 二、JP→KO：批准正面规范生成，取消此分支对负面闭环的依赖

限定于**身份范围已核对、原名与本人假名有真实来源的日本棋手**，目标仅 `ko`。原名、假名可以来自官方档案、具名辞典或经过审核的专业棋手资料；必须保留真实来源角色。igorating 不是日本棋院官网，JP/EN 两页也不是两个独立发行者；CWI 生日不是该页明确发表的生日。只有罗马字、汉字猜音、模糊同名或读音冲突仍 HOLD。

国立国语院规定日本历史与现代人名按日语表记法处理；其假名表及细则提供转写依据。因此，规范生成的正确性可由本人读音和规则正面审核，无须先证明网络上不存在惯用名。[人名规则](https://www.korean.go.kr/front/page/pageView.do?mn_id=97&page_id=P000146)、[假名表](https://www.korean.go.kr/front/page/pageView.do?mn_id=97&page_id=P000108)、[日语细则](https://www.korean.go.kr/front/page/pageView.do?mn_id=97&page_id=P000129)。本次实际读取上述三页；完整规范入口另遇 403，未将其当作规则缺失。

最小准入条件：

1. **核输入与身份。**独立检查当前 owner 与原名、本人假名、姓/名边界及生平/棋历对应；复用既有已审身份证据，无需为翻译重查每盘棋。没有已审对应者只保留 raw 显示，不写人物级译名，更不改 FK。
2. **做有限冲突检索。**至少实际完成原名或已核罗马字＋围棋语境、候选韩文＋`바둑` 两类可用搜索；检查可见的有关结果及全部已知同人线索，复用已有 KBA/Wiki/Wikidata 捕获。未完成页面、403、超时如实保留；无需穷尽三个站点或将它们全部证明为负面。发现可靠惯用名则优先采用；已知相反用名或读音线索未解决则 HOLD。全部检索入口均失败时先保留原文，不签规范生成。
3. **核全部输出。**保留真实原名/假名正文、URL、定位、时间与 SHA；固定 `nikl-ja-ko-personal-name-v1` 及规范依据，逐名解释词首/词中、姓与名、促音、长音等适用规则。独立审核者逐个核对完整输出和已有名称碰撞，不能抽样替代这五个姓名的核对。规则及正文可跨批复用。
4. **诚实分类。**使用 `decision_kind=generated`，明确“依据日文读音规范生成”；不能记作 `conventional`，不声称韩语职业用名已发表。保留未完成来源查询及已发现线索，**不制造 `not_found_in_scope` 或旧 v1 `negative_closure`**。批准的只是显示值，不新增跨人物别名、人物链接或检索归并关系。

这是对 [2026-10-06 旧韩文政策](kifu-historical-japanese-korean-name-policy-2026-10-06.md) 的窄范围补充：旧负面闭环路径仍可使用，新路径以已核正面输入、规则、实际冲突检查和独立输出审核成立；其他语言及其他生成规则没有随之放宽。

## 三、现有门与最小落地边界

当前 `name_candidates.py` 的一般 `generated` 分支仍强制 `scope_status=not_found_in_scope`；本裁决不能让 partial JSON 自动通过。若实施新路径，只在**现有 evidence/candidate 校验**增加明确的正面规范分支，例如 `source_basis=normative_ja_ko_v1`、`scope_status=generated_from_original`，严格限定 `player`、实际 `ja` 输入、`ko` 输出及上述规则。输入/规则/检索记录/精确输出/producer 与独立 reviewer 由既有研究哈希和 `generated_review` 绑定，复用现有 preimage、冲突、TEST→PROD、undo；读端必须重验同一分支。不得以“scope incomplete 也放行所有 generated”的通用例外实现。

这仅需现有入口的限定条件与必要回归检查；不增加数据库结构、通用音译器、翻译服务或另一套签核流程。**该分支及读端未实现前，新路径候选继续 pending；CN/TW 原文首轮显示和旧规则已通过的批次可继续。**
