## 决定

**有条件批准有限批量方法；不批准“精确同名＋正常日期／段位＋抽样零错”直接关联整个来源。** 常规槽位不必逐盘人工寻找外部成绩表。一个独立审核者可以批准“特定人物 × 精确原文 × 有实证的来源范围 × 活动时期”的有限集合，再由机器展开链接。必要条件是：来源证据本身适用于该集合中的每个成员，人物映射有官方锚点，全量异常检查完成，独立抽查和所有异常审核通过，最后签署冻结的成员及上下文。

这项流程补充有理由：既有[精确关联政策](kifu-name-exact-link-policy-2026-10-02.md)已经允许复用有证据的整层映射，而 [Lee 剩余队列](kifu-name-lee-143-remaining-cohort-audit-2026-10-02.md)在当时没有这种依据，只能要求逐盘找赛事记录。后者不能升级为所有正常棋谱的永久要求。**可以降低重复查证成本，不能把缺失的整层归属证据换成抽样信心。** 旧五盘／58 盘等审批或待审范围不会由本文自动扩张；新方法须产生新的有限批准。

## 能批量批准的证据范围

每个目标先建立一次人物锚点；每个实际来源范围再建立一次映射依据。两者可供所有合格成员复用，十一种语言的名称证据仍分别审批。

1. **官方人物锚点及数据库目标。** 核对棋院／协会／主办方的人物详情、稳定人物标识、源语姓名、可得的出生／死亡／入段／活动年代，以及精确中文原文如何对应此人。需要时用可靠独立资料补中文写法或历史身份。完整保存正文、URL、采集时间、哈希及对应位置。核对目标数据库 ID 的完整前像、canonical、别名和旧名称冲突；旧译名不能作为人物证据。例如 Zhao 608 的旧英韩名错指曹薰铉，必须明确排除，不能通过继承旧值完成身份锚定。
2. **有界的来源归属依据。** 至少满足下面一种能覆盖整层的情形。其一，来源导出／索引有稳定人物键或有明确作用域的人员映射，字段语义及原文→人物关系经独立核实，各槽位机械验证自己确属该来源、版本及人员范围；不要求每盘另找成绩页。其二，可核验的棋手专辑／专业棋谱集对有限成员作出人物归属声明，以源文件、清单及导入变换把当前生产 SGF 逐成员绑定到它，人物姓名和执色语义明确。若生产谱不能直接绑定原文件，可复用已存在的完整棋谱比对路径，机械确认棋盘、根摆子、完整主线、人物同色及所有匹配候选一致，再独立审定整组。仅共同的前 60 手、交换黑白后的匹配、空／过短且不能唯一识别的棋谱、互相冲突的匹配不能进入整组批准。棋手专辑不是官方每盘记录，必须如实保留其权威范围及可能共享上游的限制。
3. **实际导入来源。** 捕获 `kifu_album_sources`、原始来源文件或可核验的导入清单、版本／批次／转换规则及生产 SGF 哈希。SGF `SO=https://19x19.com` 和 `data/kifu-album/19x19/` 只说明标签或收集路径，不能代替第二项。不得把一个宽泛目录默认为单一出版方、无业余棋手的职业全集或统一无误的命名空间。来源范围不能建立时，不得用抽查通过补齐；这部分保持 HOLD。
4. **完整范围，而非无限字符串许可。** 初始集合只用未经去空格、简繁转换、拼音转换、段位剥离的 exact canonical，以及当次真实 `NULL` FK。生产者按 `人物 × 实际来源／转换版本 × 有意义的时期` 分层，在分层前固定判据，不按看到的抽查结果拆出“好层”。近似名、别名、新身份、已有 FK 更正、其他 raw 写法和未来导入全部另批。

这里的“来源适用于每个成员”可以通过批量字段、原始文件清单或可复现的机器匹配证明，**不等于为每个成员再安排一轮人工外部检索**。没有正面来源范围时，才回到逐盘来源查证或明确不可归一的显示方案。

## 全量过滤、同名及异常

对拟纳入范围的每条记录执行机械核对；审核者读全部异常和分布，并审定过滤条件。Top-100 文件只有当前一方的 rank、日期、event、source 和 FK，缺对手、实际导入来源、根属性、SGF 哈希和完整 catalog，不能充当这个步骤的输入。补捕获须来自一个一致的数据库快照；原始源文件的独立获取另记时间及绑定关系。

- **同名边界：** 检查全 catalog 的 canonical／alias 以及来源人员索引，不只查这 71 行；结合官方原名、机构、年代检查同形异人和目录外已知同名。无全网同名并不是可证明的结论；来源明确的人员范围才是消歧边界。任何已知第二候选、目录 ID 错指、来源人员键复用或别名跨 ID 冲突均暂停相应人物范围，不能用多数匹配压过少数冲突。
- **日期、活动期和段位：** 校验日期真实且与根属性／导入约定一致；对照人物生卒、职业活动和有来源的升段时间。出生前／死亡后、入段前、离常规时期很远、升段序列异常均进入异常队列。入段前可能是少年或业余棋谱，退休后可能有表演赛；不能机械认定为另一个人，也不能自动批准。`1900-01-01`、缺失和不完整日期不作年龄反证，首轮 HOLD；需要其他明确来源补足。当前段位不能覆盖历史段位，空段位可保留，但不增加置信度。
- **SGF 及字段：** 检查双方 PB/PW、BR/WR、DT 和用于身份判断的赛事／轮次／结果根字段；检查重复或矛盾根属性、字段片段、控制字符、乱码、名称混结果／头衔、原文与存储字段不一致、自我对局、空／占位／程序对手。目标姓名正常而对手损坏也暂缓。双方执色冲突、已知完整棋谱副本的人物标注冲突必须显式保留。单纯赛事译名尚未完成不阻断人物研究，但不能用含混赛事作为人物依据。
- **可复用的异常判定：** 有实证的同一种导入编码或已知标题写法可一次审定解释规则和有限成员集合，不必把 809 个非简单段位都变成独立调查。不能在身份批次内改写 PB/PW、原始 SGF、日期、段位或其他元数据；如需派生修正，应走已有修正及显示审批。

[Zhao 分组](kifu-name-zhao-608-slot-partition-2026-10-02.md)提供直接反例：2,052 个 exact 槽位中有 8 个完整棋谱匹配但人物执色冲突，6 个仍会通过本文简单 source／date／rank 筛选。因此本来源已存在“外观看起来正常仍有身份冲突”的信号，不能排除这 8 个后就默认批准余下全层。要查明影响边界，或使用另一个有逐成员正面依据的规则形成新层。

该审计已有 **1,949 个完整同色匹配**的受控组，是可复用的批量证据线索，优先于再逐盘寻找 1,949 个网页。它尚未取得身份范围批准，比较未证明 HA/PL/AE 等全部上下文相等，亦可能与 19x19 共享上游；应在一个一致新快照上验证必要上下文、来源适用性、全部异常和现有八项冲突的排除，再独立签整组。本文不把这 1,949 计入新增批准，更不把它们加到 69,104 之外。

## 独立抽查、误差报告与停止条件

**零已知误合并是硬条件。抽样不能证明总体绝对零错误；任何有限抽样都不能代替上述整层人物与来源证据。** 以下是规模化前的附加质控，门槛中的 0.1% 是检出能力，不是允许错连比例，也不是产品覆盖要求的放宽。

1. 生产者先固定所有拟纳入成员、来源分层、异常和排除项。另一位审核者独立选样并记录随机种子及样本 SHA-256，禁止选择容易查到的棋谱或遇到未命中就换样。按身份、实际来源／转换版本、时期报告 `N_h`；覆盖最早／最晚、黑／白、段位缺失等实际有区分意义的边界。所有机器异常和已知矛盾逐项处理，不能只抽查异常。
2. 对本次拟批准总体作槽位级、不放回的简单随机抽样；可由同一外部赛季表或资料正文批量核对多个入样成员，不要求逐成员下载独立网页。正面样本至少核对人物、对手、日期／时期、执色以及可得的结果／赛事；使用独立于被检查导入链的资料。只核对本库与其源 SGF 相同不算外部人物确认。样本无法核实时记录 `unresolved`，不是 `correct`。
3. **抽查阈值：误配数和未解决数均为 0，单侧 95% 的总体误配率上界不高于 0.1%。** 有限总体按零误配超几何尾概率 `C(N-K,n)/C(N,n)` 计算界限。简便且保守的计划量是 `min(N, 2995)` 个随机槽位：大总体下零误配上界 `1 - 0.05^(1/2995) ≈ 0.09997%`；可以用有限总体精确计算减少样本。对仅用于估算的 `N=67,491`，要在假设至少 `K=68` 个错误时让零命中概率不超过 5%，需 `n=2,908`。这些数字未实际执行，不能写为本批通过。小总体可以直接核完，或用相同有限总体判据定样本量。
4. 补足每个身份至少 `min(12,N_i)` 个随机成员，每个有实际区分意义的身份／来源／时期层至少 `min(3,N_h)` 个；已抽中的可以复用。补样从该层剩余成员随机选择，另存定向边界样本，不把方便选取的极值样本计入概率估计。逐层报告 `N_h,n_h,e_h,unresolved_h`、单侧上界及加权点估计 `Σ(N_h/N)(e_h/n_h)`；零命中时点估计虽为零，置信上界仍非零。总体 0.1% 上界不意味着每个人／每个小层都达到 0.1%，必须如实展示稀疏层限制；其人物判断仍依赖全量的来源归属证明。
5. 任一误配、执色／同名矛盾或无法核实的随机样本，使该受影响来源规则／人物层停止扩展；不能只删掉失败样本再签剩余。检查同一问题是否跨人物、时期、导入版本，范围不明时暂停共享该规则的全部候选。查清根因，冻结新范围、处理受影响成员并重新独立抽查。其他已证明不受影响的来源层可继续。已在隔离副本应用的对应批次按条件撤销；发现事实冲突不得等待某个错误率超标才行动。

抽查不是 69,104 次人工逐盘核对。其主要收益来自一次审核官方人物锚点、批量复用来源范围、全量机器过滤和批量对照表。若来源证据或上述抽查成本无法承担，应减少当前拟批准范围并保留缺口，不能另选更宽松错误阈值来得到进度数字。

## 产物、审核与撤销

沿用现有受控文件和 v2 工件，不增加数据库表、签名服务或新的通用审计框架。每个范围至少保留以下四类材料：

1. 同时点 inventory／catalog／目标前像、全 raw 槽位集合、精确拟写集合与排除理由，及每个槽位的原始上下文、SGF 哈希、来源归属／匹配结果；所有数量可对账。
2. 每个人物官方锚点、来源范围与转换规则的正文证据、完整异常处理、分层统计、随机样本／未解决项、误差计算及实际限制；正文受控保存，仓库只存小型摘要与哈希。
3. 生产者先固定上述内容和时间；另一独立审核者按真实 agent ID、模型和时间批准最终载荷哈希。批准表述明确“审了人物与来源范围、全部异常和这些样本”，不得冒称逐盘读过外部记录。模糊同名、未知来源边界、执色冲突或根因不明交 Sol 定向裁定；其新判断再由独立 Sol／Astra 复核。本文是方法裁决，不能复制为一个尚未冻结工件的 `identity_review`。
