# 精确原名关联：独立裁决与有限试点

2026-10-02，独立代理 `/root/exact_link_policy_astra`，实际模型 `gpt-6-astra`，推理强度 `max`。审阅基线代码 `c224b6616321fa0ab9e284d616a7a2c081e8262f`；本裁决只评估方法，不批准任何具体身份、名称或棋局关联。

**结论：有条件 GO。可以机械生成精确匹配候选，由独立审核者逐身份审定有证据支持的完整适用范围，再机械展开为有限 v2 关联清单；不要求重复人工阅读每一盘正常棋谱。精确字符串相等、目录内唯一、自动异常检查通过，均不能单独批准身份关联。当前仅允许研究、待审工件和隔离副本试点；正式库写入仍为 NO-GO，直至既定全库十一语言 100% 门槛满足。**

依据为[设计的数据契约与归一流程](../superpowers/specs/2026-10-02-kifu-full-name-localization-design.md)、[实施计划 Task 4、6、7、10–12](../superpowers/plans/2026-10-02-kifu-full-name-localization.md)、[审核手册](kifu-name-review-runbook.md)和[有限生产写入裁决](kifu-name-wu-prod-write-decision-2026-10-02.md)。这些约定以身份/原始写法查证、精确棋局作用域写入，并未要求逐盘重复检索同一人物；来源查证、独立审核和全量发布条件仍全部适用。

主代理提供的只读统计为 173,025 盘、7,251 种棋手原文、876 个现有棋手 ID，仅 5 个 ID 已有棋局关联；535 个现有 ID 可与原文字面唯一匹配，涉及 138,889 个未关联黑白槽位、94,546 盘。目录内未见 canonical 碰撞。这些是**待审候选上限**，不是已确认身份数或合格覆盖率；本代理未重新查询生产库。既有 ID 和旧种子名称本身不构成来源核验。

审核单位及必备证据：

1. **冻结精确范围。** 初始规则仅接受未经去空格、简繁转换、大小写转换、段位剥离或别名归一的 `PB/PW == canonical_name`，且旧 FK 为 `NULL`、目标为唯一现有 `player_id`。保存规则版、生产清单及 catalog 哈希、目标身份前像；列出该原文在完整清单中的所有 `(album_id, black|white)`，包括已有连接和详情可访问重复谱。另存拟关联集合、已关联集合、排除/待审集合及各自哈希，使数量能够对账。已有非空 FK 的纠错、模糊匹配、赛事关联另行审核。
2. **逐身份的正面来源依据。** 独立核对棋院/可信围棋资料中的具体人物详情，保存 URL、访问时间、实际正文及 SHA-256、原名、机构或人物标识、生卒/活动年代等可得辨识信息，并说明该原文为何对应这个数据库 ID。目录和搜索摘要仅作线索。检查现有 canonical、别名和其他身份的潜在同名；目录内无碰撞不能排除尚未入库的同名者。身份来源不替代各目标语言的名称用法证据。
3. **全量计算、分层审查。** 对该原文的全部出现计算来源、年代/日期可信度、对手、赛事、段位、已有 FK、解析异常及自我对局等分布，保留每个异常槽位。独立审核者检查每个来源/年代等有实际区分意义的层，核对来源正文或可定位对局记录，确认该层确实属于此人；重点查看最早/最晚有效日期、稀有来源、对手或段位异常，并逐项处理所有异常。普通槽位可以沿用已审、来源支持的同一映射规则；只见几个样本正确或没有异常报警，不能支持剩余整层的归属。无法把依据延伸到整层时，应缩小范围、逐盘查证或保留待审。
4. **日期与来源边界。** 来源目录路径不证明国别、读音或身份。`1900-01-01` 已在高频候选中出现，疑似哨兵日期；先标为不可信并核对相应来源/导入约定，不据此认定年代冲突，也不全局删除真实 1900 年对局。缺失、哨兵、损坏日期须靠其他具体来源上下文补足，不能自动算通过。历史段位按该盘记录核对，不拿当前段位否定旧谱。
5. **独立决定与例外。** 审核者明确批准“此身份、此原文、此有限槽位集合及适用理由”，而非批准一个可无限复用的姓名字符串。记录实际 producer/reviewer ID、模型、时间、证据引用和例外清单。常规项由独立轻量审核者处理；同名、来源矛盾、无法确认的日期/对局、旧 FK 冲突升级 Sol，其新判断再独立复核。无法决定者保持待审；有明确依据时可只批准可区分的子集。任何抽查发现错误须暂停同一规则/来源层的扩展，回查已拟批准范围。

v2 工件可以机械生成，但批准来源必须独立：

- 生成器先产出不带批准签名的候选和有限映射载荷。载荷至少绑定目标前像、精确原文、规则版、inventory/catalog 哈希、全局原文槽位哈希、所选每个槽位的完整上下文哈希、排除项及证据哈希。独立审核者对这份确定的载荷 SHA-256 发出批准记录。
- 审核后的机械展开可在每个 `album_link.identity_review` 引用/复制同一真实的范围批准，前提是逐条检查它确属审核载荷列出的槽位，且目标、上下文和规则完全一致。不得捏造“逐盘看过来源”的结论、改写审核者或时间，也不得给未审身份填 `approved`。完整的原文槽位数组可只存一次，保留当前 v2 的 `raw_scope_sha256`，避免高频姓名工件平方级膨胀。
- **现有 v2 校验尚不证明上述审核绑定。** `_v2_scope` 校验每行上下文、全局原文范围、独立 ID/时间和来源摘要；`link_set_sha256` 等是可重算校验和，不能自行证明审核者批准过新增的范围。规模化前需用一个聚焦校验步骤核对独立批准载荷与实际展开清单，拒绝复制签名后扩展成员、改变 target/context 或替换证据。可使用受控审核文件及哈希，不需要新数据库表或签名基础设施。审核时间必须晚于所签载荷冻结时间。
- 十一语言名称仍逐身份 × 语言遵循原有来源研究和独立批准；生成名称仍需有限未命中闭环、原名/读音依据和规则。每条待写名称保留真实来源作者、实际名称前像与独立 `preimage_binding` 审核。身份映射批准不授予名称批准。

**导入前必须修复一处明确缺口。** 审核手册要求新增棋手/赛事链接在同一批次附齐十一语言已审核名称；基线 `name_candidates.py:614–619` 仅在 owner 含 `ref`、即新建身份时执行此项，链接到现有 `id` 可绕过。535 个现有 ID 正处于这个边界。在修复并独立复核前，不应用此类真实关联批次，即使 `ready/write_ready` 为真。最小回归应包括：现有 player ID 的 `NULL→ID` 链接仅附十语或漏掉该目标全部名称时拒绝；十一语完整、来源/前像与独立审批有效时通过；赛事现有 ID 同样检查，单纯更新已有链接身份的一小批名称仍可走原有有限名称流程。不得把旧 `verified`、另一个身份的十一语或目录名称当作本次目标的已审十一语。

试点按以下阶段推进，每阶段保留准确数量、哈希、未决项及检查结果：

1. **只读候选阶段：** 生成全部精确匹配及例外分布，逐身份开始审核。先选已有完整十一语言来源审批、存在未关联精确槽位且来源可核验的一个身份；若没有满足条件的身份，继续查证，不制造试点批准。上述统计中的 535 个身份不因本裁决取得批准。
2. **小型隔离试点：** 修复门槛后，在固定正式备份的隔离副本选不超过 100 个已审槽位，覆盖可用的黑/白、不同来源、最早/最晚有效日期，并确认疑似哨兵等排除项不会写入。同哈希工件依次 dry-run、apply、重试及条件撤销；确认仅预定 FK/名称改变、原始 SGF/元数据哈希和行数不变，已有 FK 不被覆盖，实际显示及搜索符合批准身份。聚焦检验陈旧快照、范围扩张和目标/上下文替换被拒绝；沿用现有原子失败/撤销测试，不重复建立测试体系。
3. **按身份扩展隔离演练：** 在恢复的副本或与前一批提交后状态匹配的新快照上，扩展到相同身份的全部合格槽位，再扩到少量独立已审身份。按测得的事务耗时、内存、工件大小和锁持有时间确定子批次，避免一次写入 138,889 个槽位。当前 importer 会持有多表写锁，并为每盘保存完整前后像；小样本通过不能推定最大批次可接受。每次关联改变 inventory 哈希，下一批须基于相应新状态重新绑定范围/前像并独立签署；可复用未变的来源研究，不能机械沿用旧范围批准。
4. **全量收口后生产：** 在正式等价副本完成当前正式快照及增量、全部可显示黑/白/赛事槽位 × 十一语的 100% 合格决策、零未决/无依据回退，并完成既定页面/搜索验收与恢复演练，才按 Task 12 使用同代码和同哈希工件进入生产。有限试点只报告进度；`KIFU_STRICT_NAMES` 关闭不能使写入不可见，旧显示路径仍可能立即使用 `verified` 名称。
