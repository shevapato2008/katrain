## A：可以立即扩大的正面来源批量

每人一次建立“官方原名／稳定人员编号／完整生日 → GoRatings 同名同生日人物页 → 同一站内 ID 的目标语姓名”对应链。保留原始正文、URL、访问时间、字节哈希、字段定位及真正返回语种。目标语页面须有该人物的实际姓名和专业上下文；不能只用榜单入口、URL 语言码、页面导航或搜索框回显。来源锚点及跨页对应已经独立批准且内容未变时可直接复用；不重复下载或为每个语言再找一篇人物报道。

GoRatings 可作为专业出版方的实际用名证据，不冒称官方棋院。四种页面仍是一个出版方；官方人物锚点提供另外的身份依据。**不要求 Wikidata 标签与四语全部逐字相同**；它是发现冲突的线索，不应把[153 人四语交集](kifu-name-goratings-crosslang-batch-2026-10-03.md)变成研究上限。已知身份／生日矛盾须审定，不能为扩大范围而丢弃；单纯已解释的标签拼写差异也不必反复阻塞已有正面正文。

同名多个官方记录、生日不完整／不一致、语言页 ID 不同、实际语言回退或未知身份冲突，均退出这条清洁批量路径。历史人物缺日精度生日可另以生平与专业资料定向审核，不能伪造生日，也不因未满足此快速路径就认定人物不可识别。

## B：`primary-orthographic-v1` 的准确边界

**首版只接受来源语言已核实为中文、官方原名为完整汉字的人名，目标为 `cn` 或 `tw`，不产生新读音、翻译词、假名或罗马字。** 中文来源的认定来自人物资料，不能来自 Han 字符外观或数据包路径。台湾目标固定台湾繁体；简中方向另有自己的来源及规则表，不把同一张表反向使用视为自动批准。

必须同时满足：

1. **原名与对象有已审对应。** 官方原名、人员键及必要身份事实可定位；`player` 目标另有正确对象绑定。`raw_player` 仅在已有独立批准的精确原文对应及有限显示作用域内使用，不凭同名把全部棋谱指给该官方人物。附带 `(大)/(小)`、年代、头衔或坏字段的值首版排除。
2. **逐字是明确正字关系。** 独立规则审核者核对固定版本的地区规范表、实际映射位置和人名适用性；Unihan 可交叉检查，不能单独充当人名规范。只收明确的一对一对应，保留原字与改字均须经过规则审核；表外、多个目标、保留原字分支、语义词组替换及地域分歧进入例外。不把通用转换器默认值变成批准表。Unicode 自身明确其简繁映射有上下文、地域及非正式性限制。[UAX #38 §3.7.1](https://www.unicode.org/reports/tr38/tr38-39.html)
3. **完整姓名再次审定。** 机器逐字拼接并记录位置／输入输出码点；独立审核者逐个检查完整结果，排除姓氏或词组误换。`胡子扬→鬍子揚`、未经核实的 `孔杰→孔傑`、`于→於`、`钟→鍾/鐘`、`岳→嶽` 均不能走普通批量。既有具体人名证据及 HOLD 优先于字符表，不能靠新规则抹掉。
4. **检查已知用名，不制造不存在声明。** 先批量对照已获批名称、已有来源索引和已知异体／冲突记录；命中可靠目标语实际用名即走 A。查到相反用名或人物不明者单独 HOLD。允许未获直接当地用例的清洁项作为规范生成名，不宣称已穷尽网络、没有惯用名或该字形是本人采用的法律姓名。
5. **全部成员明确且无未决碰撞。** 审核的是冻结的 `owner × 原名 × 目标语言 × 输出` 集合，不能只签一张字符表后自动批准任意新姓名。生成后的同形不合并人物，不新增未经审定的搜索等价关系。

这不是把[旧 387 名检查](kifu-name-china-roster-tw-character-review-2026-10-03.md)直接翻成 PASS：旧检查只证明固定参考表的相容性，还须满足上述人物对应、人名适用性、已知例外、完整输出和新批准要求。由于尚未执行这些检查，本文不报新增覆盖数。

**韩文或英文标准音译与纯字形不同。** 本人的源语读音、姓／名分词、具体罗马化体系和目标语规则都要核实；`Zeng` 不能被字典默认的 `ceng` 取代，日文汉字不能用普通话拼音读取。主五的此类 `generated` 仍执行既有 v1 严格来源闭环和独立输出审核；可以批量抓取及复用专业索引，但每名要保留真实检索结果、所有已知线索处置和精确输出。**不批准“只有汉字＋算法读音即可批量补 ko/en”，也不批准省掉主五全部语音生成查证的新通道。** 如要进一步扩大到不经既定查证的语音生成，属于需用户另行接受的政策提案，本次 HOLD；本任务不需要为此停止已获授权的 A、B 工作。

## 最小证据契约与实现保护

B 使用现有 `decision_kind: generated`，另以精确 `generation_rule_version: primary-orthographic-v1` 和专用证据类型区分；不得填 `conventional`、复用六语 `transliterated`，或伪造 `not_found_in_scope`／`reading`。最低载荷如下，使用现有受控审核封装及哈希，无需新签名服务：

| 载荷 | 必须绑定的内容 |
| --- | --- |
| 原名锚点 | `owner`、`original_name`、真实 `source_lang/source_script`、来源人员键、正文定位／哈希、已审对象或 raw 对应哈希；不同命名空间不能靠相等数字连接 |
| 规则 | `evidence_kind: primary_orthographic`、版本 `1`、源／目标脚本及地区、精确允许字符映射、各自规范版本和位置、全部排除条件；冻结后的规则内容哈希及独立批准 |
| 有限批次 | 每项 `owner/original_name/lang/display_name`、逐字映射记录、锚点／规则哈希，完整成员哈希、已批准名称快照及 catalog 哈希、碰撞与例外报告、实际抽查集合 |
| 审核及写入 | 实际 producer/reviewer ID、模型、带时区的时间和最终内容哈希；审核者与生产者分离，审核晚于冻结。沿用真实 `name_preimage_sha256`／`preimage_binding`，最终审核者与来源生产者及前像绑定者分别独立 |

同一独立审核者可审核规则与有限输出，不增加无价值的第三轮重复审核。既有已签人物证据不重签、不冒改作者；新规则和新成员必须取得自己的真实批准。新字符、变更输出、删除排除条件或扩大作用域使旧批准失效。

**实现须显式接通全部路径：** 在 `name_evidence.py` 增加严格的正字证据检查；`name_candidates.py` 仅为上述确切规则开专用 `generated` 分支，其余五语 `generated` 继续要求原 v1 闭环。`name_batch.py` 保存完整证据及有限批准，写入时再核目标、名称前像及已知用名快照。`identity.py` 的 `_qualified_name_rows` 目前仅对 `transliterated` 做持久化证明重验，其他 `generated` 直接通过；**新正字分支必须在这里及共用搜索读取处检查持久化的规则、锚点、成员和实际名称一致性**，不能仅让离线 validator 放行。`name_coverage.py` 沿用同一严格显示判定，并把这种名称计为 `generated`。

最低验证覆盖：一批合法 cn/tw 正字生成贯穿导入、显示、搜索与覆盖；向 jp/ko/en 或非中文／赛事扩张拒绝；任意映射／成员／目标／正文或规则哈希变更、旧签名、自己审自己、既有用名冲突均拒绝；持久化后篡改则显示／搜索／覆盖资格失效。继续保留现有十一语、前像、原子写入及条件撤销闸门。没有这些保护前，B 只能制作待审产物。

## 审核成本、搜索及赛事

按来源模板和语言制作有限表格，每批约 100–300 人；缓存正文只获取一次。**所有姓名／生日／站内 ID／显示字符串机械核对，所有完整输出由独立审核者逐值看过；碰撞及例外全量审，不抽样。** 使用现有 `NFKC→casefold→合并空白` 规则检查批内及已批准目录／别名，保留原字；合法同名须明确为不同人物，不能以名字作主键。

抽查只检验正文提取和批量展开：每个来源／解析模板首次使用随机抽 `min(20,N)` 份完整正文，加上全部异常脚本和边界；后续在模板及已有证据未变时抽 `min(N,max(10,ceil(0.05N)))` 份。规则表的所有映射首次逐项审核，每个输出仍逐值审核；抽查零错不声称总体零错。任一姓名字段错取、回退漏检或身份串行，暂停受影响模板批次、修复后重新检查，不能只删失败样本。这样节省重复打开网页的时间，保留主五的逐值判断。

`conventional` 与合格 `generated` 均可作为预存显示值，但数据库及证据保留其不同性质。搜索只在已审人物或已审有限 raw 范围内使用对应名称；正字表绝不能成为全库身份归并、自动 FK 或跨人物别名扩张规则。[身份批量边界](kifu-name-bulk-player-identity-policy-decision-2026-10-02.md)不变。
