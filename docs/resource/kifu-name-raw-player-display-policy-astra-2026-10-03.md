## 批准的语义与边界

| 问题 | 决定 |
| --- | --- |
| raw 显示批准了什么 | 指定语言、指定精确原始字符串、指定棋谱范围内的文字显示。`raw_player_id` 是字符串记录的键；不据此建立人物档案、统计生涯、合并人物或写入人物别名。可用审核元数据说明 `readable_unlinked`，无需在每张卡堆叠技术说明。 |
| 证据如何适用 | 已审人物资料可复用为原名、字形和读音的来源材料，但需另审这些事实是否能支持本批 raw 显示。来源中的 CWA/GoRatings ID 只定位该来源的人物，不能自动指认棋谱人物。署名与内容哈希须绑定新的 raw owner、精确字符串、语言、输出和适用范围。 |
| 同名异人 | 如果本批各处都适合相同的语言、读音和字形显示，无需证明它们属于同一个人。审核检查完整本批语境和全部异常，不要求穷尽世界上所有同名人。若已发现不同读音、源语言或个人用字，单个全局 raw 值不能覆盖这些相冲突的范围；先排除冲突槽位。不能证明共用值适用的部分继续 HOLD。 |
| 读音与个人罗马字 | 已发布的罗马字只证明来源中该人的拼法。采用 raw 规则转写时，须确认它可作为本批原文的语音/字形表示；个人自选英文名、别名、方言/历史拼法不得推广。姓氏多音及特殊名读音单列异常。六语保留 `transliterated` 与规则版本；不可改标该语言惯用名。主五语继续现有来源规则，不借六语捷径。 |
| 人物 ID | raw 显示只需要受控 raw owner，可以不创建 `kifu_players`，不需要 QID 或官方编号。以后建立人物身份及 album FK 仍走独立证据链；仅有官方编号也不能证明某盘属于该人。身份确认后由实体名称优先，缺实体译名仍算缺口，不能偷偷用 raw 名覆盖。 |
| 搜索 | 已审译名只展开为其精确 raw 字符串及已审槽位；不得展开其他原名、近似拼法或人物 ID。相同字符串下可能返回多人的棋谱，这是文字匹配集合，不能标为某个人的完整棋谱。与其他 raw/entity 名称发生冲突时保留现有拒绝自动扩展规则；直接原文文本检索可以继续。 |

**具体不能无条件搬用的现成值：** [五语复核](kifu-name-five-primary-chinese-professional-review-2026-10-03.md)只批准特定人物的日文 `彭筌` 及繁中 `於富霖、於浩然`，没有批准 `彭荃→彭筌` 或姓氏 `于→於` 的通用替换。[读音复核](kifu-name-secondary-six-33-anchor-independent-review-astra-2026-10-03.md)中的 `金茜倩→Jin Qianqian`、`曾志豪→Zeng Zhihao` 也应明确处理读音适用性。保留这些来源，不把它们改成字符串级 PASS；相应 raw 结论可以经过定向追加审核后成立，不能用已有个人 PASS 代签。姓名常见如王群、李亮、王超时，同名检查的目标也是显示是否冲突，无需先完成每盘人物识别。

## 当前实现的真实限制与最小适配

1. **复用表和事务。** 已有 `kifu_raw_player_values`、`kifu_raw_player_names`，`readable_unlinked` 可接受 conventional/generated/transliterated。[`strict_slot_approvals` 与显示解析](../../katrain/web/kifu/identity.py)已在 FK 为 NULL 时用 raw 名。[v2 bundle](../../katrain/web/kifu/name_candidates.py)支持新 raw ref、分类审核、完整原值出现清单、空 `album_links`；[导入器](../../katrain/web/kifu/name_batch.py)允许实际存在于棋谱的 raw owner。保留名称前像、目录/清单哈希、锁内重查、独立签署、碰撞检查及条件撤销。第一批不新增人物/身份图谱/数据库表。
2. **来源锚点只加一个显式分支。** [当前 `anchor_format: 2`](../../katrain/web/kifu/name_evidence.py)的双来源检查明定 `owner.kind == player`；直接改 owner 会使旧签署失效，补签也仍被类型闸拒绝。采用新的 `anchor_format: 3` 专用于这次 `raw_player + zh-Hans + pinyin-syllables-v1`：复用 v2 三来源对应检查及已有读音字段；额外绑定精确 `raw_value` 和独立审核的 `raw_display_scope_sha256`、原文语言/读音适用理由、已知拼法/多音异常处理。来源事实可以原样复用，原人物锚点保留原哈希，另签 raw 锚点。v1/v2 行为不变，禁止改成 v1 来绕过双来源限制。无需引入一套新签名体系或逐名重下载来源。
3. **增加最小的有限显示范围。** 现有原值声明的 `occurrence_album_ids` 要与完整 inventory 相等，但这个条件只约束导入时刻；当前运行时 raw 字符串会匹配日后新增的同名棋谱。首批在现有已签 bundle 的 raw owner 声明中增加 `raw_display_scope`：绑定 inventory、精确 `(album_id, black/white, raw_value, expected NULL FK)` 成员及审核实际依赖的语境字段/哈希；内容可由完整出现清单确定性生成。它允许全体或经审核的子集，**完整出现清单仍保留**。raw 锚点及主五语候选/研究记录都绑定同一范围。复用批次保存的不可变审核工件；页内显示与 `strict_slot_approvals` 通过同一 helper 检查成员、原文、当前 FK 及被绑定语境，避免把范围仅写在备注里。新出现/范围外/依赖语境变化的槽位回到缺口队列。暂不增加同一 raw 多套相冲突译名的存储能力。
4. **搜索使用同一个范围。** [当前 API](../../katrain/web/api/v1/endpoints/kifu.py)对译名得到的 raw 集合直接使用 `player_black/white.in_(raw_players)`，没有逐槽 NULL FK 条件，可能触达同名但已关联的另一个人。改成“精确 raw + 审核成员 + 对应槽 FK 为 NULL”，复用上面的资格 helper；同一盘若另一槽合格仍可返回。保持现有跨 owner 冲突拒绝，不写 `kifu_player_aliases`。直接原文搜索不被解释为身份查询。

这项范围适配不是要求为每盘重新找人物证据，而是防止审核有限语料后的显示决定自动扩散。源语言和读音可以在一个明确语料范围内批量审核；`source_path=19x19`、日期落在生日前后或目录零碰撞，单独均不足以承担这个理由。若以后证明某个文字转换真正无须语境，才另外批准其全局适用政策；首批采用有限范围即可交付。

## 完成指标

显示覆盖与身份覆盖分别报告。正式显示分母仍是当前可见列表与可访问详情 album 的并集 × 黑/白/赛事 × 11；raw 的证据、范围及运行时资格合格即可计入相应姓名显示覆盖，不因 FK 为 NULL 扣除。同一名字有 11 个记录但未对实际槽位生效，仍为零收益；范围外回退及证据失效仍算缺口。额外报告 `approved_raw_unlinked` 槽位数，不能把它混入已核实人物槽位数。

任务给定基线的身份率仍为 **3,213/346,050 ≈ 0.93%**，本批身份增量固定为 0。2,965 槽全获准时姓名显示覆盖最多增加约 0.86 个百分点，实际增量以克隆同一解析器的前后差为准。全量完成依然要求每语种黑/白/赛事都有恰当且可追溯的显示决定；占位/损坏提示不能拿来替代可读姓名的未决译名。100% 显示覆盖可以与未解身份并存，报告须如实写明两者。
