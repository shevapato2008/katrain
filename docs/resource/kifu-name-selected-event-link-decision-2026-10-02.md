## 最小存储与读取契约

保留 `kifu_event_selection_batches` 原工件及其 `event_id=None` 后像，**不改原批准内容，不把 `event_id` 从审核比较中直接删去**。更新时仅修改 `kifu_album_event_selections.event_id`，原 `batch_id`、选择原文、SGF 哈希、属性/索引、审核者/时间等来源字段均不变；`kifu_albums.event/event_id` 和 SGF 仍不变。

复用 `KifuNameBatch`、`KifuNameChange` 保存关联工件及完整选择行前/后像，无需新表或通用修订框架。该表主键是 `album_id`，须对这一明确目标补主键映射，不能沿用现有 `_image`/undo 的 `table.c.id` 假设。

共享读取核验只接受两种状态：

1. 当前选择行完整等于原来源批次后像，且 FK 为 NULL。
2. 当前行与原后像仅 `event_id` 不同；恰有一个仍为 `applied` 的新格式名称批次变更，其完整 `before_image` 等于原后像、`after_image` 等于当前行。重新核验该批次内容哈希、有限关联成员、独立身份审核及 target/ref 解析结果，证明这次 FK 转移；不能只信变更记录自报的后像。

两种状态均需原选择批次有效、实际 SGF 哈希先通过、精确 GN[1]/GC 来源规则仍成立。多条活跃证明、审批/工件损坏或任一字段漂移均不接受该选择。列表、详情、检索/total、清单和覆盖率使用同一核验，按页批量加载证明；名称撤回后显示仍按现有名称证据闸门形成缺口。

## 冻结前像、证据和独立审批

新增 `bundle_format=4`、`inventory_format=4` 与选择补充 `selection_format=2`，旧格式及哈希语义保持原样。新补充在现有来源字段之外纳入有效 `event_id`、原选择后像 SHA、关联批次/变更证明哈希；NULL 也明确计入。基础 album/source 哈希继续单独固定。关联、撤销或证明失效必须改变快照或产生明确漂移，旧 v3 工件不能授权新槽位。

每个 `selected_event` 成员及其独立签审范围至少固定：

- `album_id`、原选择 batch ID/完整 bundle SHA、完整选择行前像及 SHA（旧 FK 必须 NULL）、GN 属性/索引/原文、生产 SGF SHA；原 album 的 event/event_id/source/path/date/round/board、双方棋手/段位及来源关联上下文 SHA。
- 目标 `event_id` 或同批 ref、目标目录前像或创建声明、目录 SHA；该精确 `selected_raw` 的全局出现槽位 SHA及本批具体选取的成员。等值原文不自动共用身份；排除/待定成员及原因明确保留，不能从 `GNUGo3.8` 建立赛事别名。
- 实际 producer/reviewer ID 和模型，二者不同；生产/取证 ≤ 范围冻结 < 审核，批准结论和作用域 SHA。证据固定真实来源 URL、正文 SHA、相关摘录及逐成员身份匹配依据，明确年份届次、阶段、地域、赞助商或新旧赛事同名时的时期依据。原 GN/GC 一致性只证明选词来源。

沿用目标十一语名称各自独立批准、名称行前像和来源注册表要求；身份批准不能替代译名批准。带届次/阶段/轮次的描述仍需已审原文显示或组成部分模板，不能用赛事核心名抹去结构。新批次完整 canonical SHA另记于独立审核记录，apply 必须传入并核对该可信摘要。

## 应用、重试和撤销

- `validate` 离线；`dry-run` 只读。apply 在现有名称批次锁和一个事务中重查全部快照、SGF、原选择证明、目标/名称前像及活跃关联唯一性，任一成员失败则整批不写。所有选择/名称写入及撤销采用统一锁顺序；来源选择撤销不得与关联提交交错。
- 批次只含本次关联所需的赛事/原文名称及选中槽位。完整记录 before/after；新 ref 解析固定在已审核声明对应的变更记录中。原始选择工件不重签、不覆盖。同哈希重试必须核验已应用工件、成员当前状态和后像，才返回只读 `already_applied`；已撤销批次不能重放。
- **含新槽位的批次撤销采用整批条件撤销**：先验证所有当前行仍等于本批后像、来源 SGF/前像有效，且删除新建赛事/名称/证据不损害后来依赖；然后在同一事务中逆序恢复。任一后改或依赖冲突即整批拒绝，返回具体 ID/原因，不套用旧批次的 `partial_undo`。
- 先撤销身份关联，恢复选择 FK=NULL，再允许撤销原来源选择；有有效身份关联时，来源批次撤销拒绝。旧格式批次的撤销语义不变。首次实现不接受非空 FK 改绑；须先完成可条件撤销的旧关联，再以新冻结工件审核，不能直接改 ID 或改旧审计记录。
