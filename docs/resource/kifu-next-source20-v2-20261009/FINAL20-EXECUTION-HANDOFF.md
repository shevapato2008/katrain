# Final 20 execution helper handoff

The unsigned, locally validated transport is `final20-execution-transport.tar.gz` (SHA-256 `39ac10633e4738913e26dc68e6dffd594e80e5074948cbdd03bb0280133c50a6`). It contains only the two environments' bundle, format-2 inventory, 20-line research JSONL, registry, proposed manifest, and `final20-inner.py`/`final20-run.py`. The source bodies remain in this local directory for review and were checked for presence during preparation; they are not copied into the transport.

The proposed manifest SHA-256 is `5b3be29ff4cedfddc07ec515fe065613b5df5bc6d79fa61b7db1ebf506a427b3`. Canonical bundle SHA-256 values are PROD `ebc710e18a440e875a6e7d0d6fc3e86aaac647fc956f853440c942903622d1aa` and TEST `e13e4eb7a338450304141601cd7b3c89a500e59daf4e0fb4cf9fb55d633413d5`. The manifest also binds SHA-256 of both execution helpers.

Root must separately create `root-final20-execution-approval.json` in each extracted transport directory after reviewing these actual files. The helper requires exactly these fields and values: `reviewer_id: "/root"`, `allow_apply: true`, `manifest_sha256` equal to the proposed manifest file SHA, `bundle_sha256` mapping PROD/TEST to the canonical hashes above, and `image_ids` equal to the manifest's `required_image_ids` mapping. This approval file is deliberately absent from the tar.

After root approves and transports the files, execute `python final20-run.py ENV baseline`, then `dry-run`, `apply`, and `verify` in order for each environment. Each run uses the exact pinned r5 importer ID in the manifest and writes an environment/phase receipt in the same directory. The baseline and verify phases use read-only SQL transactions. They run a parameterized physical `SELECT * FROM kifu_albums` for the 20 owners, comparing every returned column across 609 linked album rows with each SGF replaced by its UTF-8 SHA-256. They also compare the complete non-target player name rows, 20 target 13-field CAS preimages, 614 owner game slots, and the original 80 versus final 100 strictly qualified language names. Only `apply` invokes the protected native batch writer; root alone decides if and when to invoke it.
