## 棋局范围批量核验

20 组的 26,015 槽全部来自 `19x19` 来源，均无自对局、重复记录、不可解析日期、出生前年份、五岁以下对局或指向别人的现有棋手外键。已有 **20 槽**分别指向本批认可的李昌镐、赵治勋、曹薰铉、林海峰目标 ID；没有相反外键。若新快照范围不变，新增回填量为 **25,995 槽**。每组的最早/最晚实际日期、来源分布和忽略当前外键后的 `frozen_scope_sha256` 都写入 JSON。

**39 槽**的日期是 `1900-01-01` 哨兵值。逐项查看了赛事和对手，均落在相应棋手的比赛、指导或活动语境；日期未知本身不是人物冲突。另有 **11 槽**早于职业入段年，赛事分别是少儿赛、院生赛、业余世界赛、指导棋或晋升赛，年龄与官方人物履历可相容；JSON 逐条保留棋局 ID、日期、对手和赛事。另有 **11 槽**以 `YYYY-MM-DD 00:00:00` 记录，均可解析成有效日期。上述槽位一并列为可回填，没有用哨兵日期计算年龄。

## 迁移顺序建议

1. 用 manifest 的目录 SHA、输入批次 SHA 和 20 个目标 ID 的现名做只读预检；同时查询实时棋局外键、翻译、别名及其他引用，遇到与冻结快照不同的引用即停在该组。
2. 在事务内先处理 3 个现有 ID 改名和陈诗渊新 ID，再将 7 个重复 ID 的全部引用迁至保留 ID。冲突的翻译和别名须逐项保留证据或留待审核，不能覆盖已有值。
3. 只把 `relation=plain_name` 的繁简/日文原名及旧 canonical 写法写为名字别名；段位和空白写法由解析规则处理。原始 SGF 文本保持不变。
4. 第一批完成后重新导出生产与测试目标环境的棋局和目录快照。按 JSON `raw_allowlist` 精确重算 20 个 scope 哈希；当前外键只能为空、目标 ID 或本批待合并 ID，别的 ID 即为冲突并停在该组。两环境分别给陈诗渊分配本地新 ID，不能复用另一环境的数字。
5. 预检一致后，可将仍为空的白名单槽位 `black_player_id`／`white_player_id` 回填到目标 ID；已有正确关联保持。`excluded_prefix_raw_values` 中的 42 个原文不得进入此操作，原始 SGF 文本保持不变。

冻结快照上没有需留 pending 的真实身份冲突。后续若新快照发生范围或外键变化，只隔离实际变化的组，不撤销其余已通过的组。
