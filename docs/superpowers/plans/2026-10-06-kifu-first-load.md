# 棋谱库首次加载与报告入口修复计划

**Goal:** Galaxy / kiosk 首次加载当前页 20 局；棋盘不等字体、图片或分析下载；没有真实完成报告时展示「查看棋谱」。

**Architecture:** 沿用已确认的布局。列表附带当前模型、SGF、2000 visits 与完整性校验后的 `has_analysis`，以及首条棋谱的 `preview`，复用到详情请求。逐页加载，其他业务页面按路由加载。专业分析数据以相同 SGF 与模型身份同步至测试主库。

**Tech Stack:** FastAPI / SQLAlchemy / React / Vite / Playwright。

## 验收与步骤

- [x] 聚焦失败测试：分页仍限制 20，首条 preview 对应第一页首局；旧 SGF / 旧模型 / 缺手 / 低 visits 不可标记有报告。
- [x] 后端：当前页集合查询报告可用性，不读取分析 JSON；返回首条 preview，保留名称翻译与隐藏谱的现有服务行为。
- [x] 前端：首条自动预览，列表 preview 复用；条件按钮路由到报告或棋谱回放，kiosk 同样区分；没有数据不展示默认 50% 的虚假分析。
- [x] 性能：其他页面按路由加载，首屏模块按入口预加载；棋盘先绘制可用素材的盘面，图片逐步补齐；让字体与图片下载不再阻塞棋盘绘制，保留字族、字重与现有素材。另启用 gzip / HTTP2，去掉已完成报告的重复下载。
- [x] 数据：同步已算出的最近 60 局到 home 主数据库，逐局校验 SGF / 模型 / 深度；不重复计算。
- [x] 验证：运行上述测试与生产构建，分别部署 home / ucloud web；真实浏览器冷缓存与站内首次进入实测 Galaxy / kiosk，保存截图与实际耗时。home 全新浏览器 HTTP2 首局 908ms，kiosk 清缓存 613ms；条件与完整证据见 `docs/operations/kifu-library-first-load-20261006.md`。

## 已确认原因

列表返回 20 条约 10 KB，home 本地约 450ms，详情约 29ms。浏览器从导航到列表请求开始约 3.85s，加载 Galaxy 时也下载了其他页面代码；中文字体首次下载约 10MB。当前选棋还需第二次详情请求，LiveBoard 等全部图片下载后才绘制。完成的 60 局仅导入了正式主库，测试主库未同步。CTA 未查询报告可用性。
