# Kiosk 教程字体与 19 路派生：独立计划审核 R1

结论：**需修改**。整体方向可行：源库和 Galaxy 默认读取不变、RK 在原始云响应之后派生、完整 19 路载荷统一供屏幕与实体状态机消费、隔离 worktree 集成到 published develop，均符合本次要求。下述六项修订后可做第二轮计划复核；不要求新平台、付费模型、逐题人工长文或无关全量回归。

审核对象：[实施计划](../plans/2026-10-24-kiosk-tutorial-font-19x19.md) 与 [只读调查](2026-10-24-kiosk-content-investigation.md)。源码基线 `faacf2597c0904edfbb56c016b7f7d496abaf03d`。本轮只读源码和 `/tmp/kiosk-small-content-20261024.json`，另写本报告；未实现、修改源库或发布。

## R1 — 固定代理实际可验证的来源摘要契约（P1）

**位置：**计划“对外契约”和“资格与转换权威”第 4 条，Task 2。

`public_step_output()` 仅暴露 playable fields 和当前 locale，不暴露 DB `content_sha256`、`raw_source` 或所有翻译（`katrain/web/tutorials/ogs_course.py:121`）。因此“固定来源摘要清单”目前还不足以让实现者确定云 server 与旧云后的 RK proxy 如何得到相同摘要。若直接使用导出的 DB hash，RK 将全部保留；若退化为只检查 `source_id`，则失去内容变化防护。

最小修订：

- 明确 OGS 规范化结构摘要字段，例如 `source_id / lesson_id / step / page / size / initial_player / stones / letters / shapes / viewport / exercise`，以及统一的 JSON 规范化方式。不得包含运行时 `book_id / figure_id`、截图准备状态或代理拿不到的字段。
- 另验证**实际显示的 locale 文案**：有效语言的 title、instruction、choices 对应已审核摘要；requested language 的 fallback 按现有规则处理。未审核语言或文案变化保留原题并说明，不以“英文曾审核”替代当前正文校验。
- Tsumego 用原始 SGF 的 SHA-256 固定题意和答案；同时检查 API `boardSize / initialBlack / initialWhite` 与 SGF 根一致。导出没有 `hint`，它来自 `PL` 的“黑先/白先”时应明确这一约束，不能默默把一份不同初始 JSON 交给同一 SGF 证书。
- 同一个输入在 server 和 proxy 上得到相同资格结论。按现有计划增加聚焦断言即可：结构变化、当前文案变化均失效；无关截图/DB ID 不使证书失效。

`ProblemDetail` 当前没有 metadata 字段且作为 response_model 使用（`endpoints/tsumego.py:63,286`）。计划已正确要求不被过滤；落实时还须保持省略 variant 的响应形状不变，避免新增 `board_variant: null` 意外改变默认契约。

## R2 — 把语义许可写成可执行的局部目标证据（P1）

**位置：**计划“资格与转换权威”第 4–5 条、Task 2 第 3 项。

现有表述在原则上正确，但“审查候选语义”尚未定义最低正向依据。实际很多 SGF 只有“黑先 吃子题/手筋题/死活题”，既不能按类别批量放行，也不应因文字简短只交付四个手选例子。552 / 657 仅是几何候选数。

最小修订是在清单/审计结果中记录 `semantic_family` 与可复核证据引用，并按源 SHA 展开到每个 source；一个题族可共享审查说明，逐源只记目标、叶节点事实和差异原因。建议最小正向证据：

| 题义族 | 最低正向依据与边界 |
|---|---|
| 一步局部提吃 | 固定初始对方目标棋块；正确终点完整提掉该目标，失败终点未达相同目标；目标的邻接和全部气保持。新增远处空点不能在这一手提掉目标，因此这类可形成明确的局部证据。 |
| 短局部提吃序列 | 在上述目标之外，核对整棵树中实际交互范围及所有成功/失败终点；不能仅以“某个叶子发生提子”认证。 |
| 解除当前打吃 | 固定初始己方一气棋块，核对正确终点该组存活且已解除打吃、失败终点被提或目标未达。此证据**不是活棋证明**，不得用于需要征子延伸或全局逃跑判断的题。`129993` 的黑 `fe/ee` 只有 `ed` 一气，正解 `ed` 救出，两个失败分支均由白 `ed` 提掉该组，是具体可复核的例子。 |
| 计气、棋块、打吃选择题 | 明确所问的目标棋块或源盘全部棋块，重算相关局部量，并核对实际 choice key 与正文；不能只复制原答案值。 |
| 连接、切断 | 指定所问初始棋块/连接点，记录终点连接关系与成功/失败分支；不能仅按 connect/cut 课名认证。 |
| 两眼、封闭角空、对杀、枷等 | 需要各自明确的目标与终点局部不变量；在本次实际审核后纳入，缺少证据时写明具体缺口。不得把几何等价改称此类题义已经证明。 |

清单必须区分“边界/棋规确实不等价”“明确全局题义”“源格式/内容有问题”和“本次尚未确认局部目标”，不能把尚未审核写成已证明不可扩。完成时交付全部 879 + 691 小盘逐项结论及精确计数，并对可认证题族实际批量覆盖，不把四个代表题当作全部交付指标。

将调查中已有明确反例写入计划：OGS pages 1–2 的“任意空点”、31–33 终盘、35 盘宽教学、468–479 全局胜负、1574–1579 全盘单官均保留；劫/劫材和征子保留。局部封闭区域计目与全盘胜负应分开判断，不能只凭 `territory` 关键词永久拒绝。

机械证明应继续诚实限定为**已列出的完整源树及局面**的等价，不宣称它穷尽新增空间中的所有围棋战略或自由试下。

## R3 — 以本次真实格式限定转换与执行支持面（P2）

**位置：**计划“资格与转换权威”第 2–3 条、Task 2 的“全部 SGF 点属性/压缩点/节点 setup”测试。

本轮独立扫描 879 个小盘 SGF：根和节点总属性仅 `GM FF CA AP SZ GN AN SO GC C AB AW PL B W`；非根仅 `B W C`，无 pass、非交替落子、节点 setup 或 AE。691 个 OGS 小盘的 puzzle 树也没有非根 null/pass。现有训练题前端并不是通用 SGF 执行器：只用根 PL/初始 JSON，`findChildMove()` 和 `getAIResponse()` 只接受有坐标的 move；节点 setup、pass 不能由“后端已变换”自动获得支持。

最小修订：

- 明确本次必需支持上面的真实 SGF 集合及 OGS 当前完整结构：初始棋子、全部正确/错误子树与顺序、letters/shapes 的坐标键、目标点、先手和 viewport 处理。
- 若实现选择支持 LB/AR/LN/压缩点等已知属性，按各自语法完整转换；否则明确保留原题。未知坐标属性、矩形棋盘、非根 setup/pass 等必须有可审计的拒绝原因，不静默复制，也不以此要求新造完整 SGF 引擎。
- 对 API 初始 JSON、SGF 根 setup、SZ、PL 的一致性做资格检查；保持 SGF 注释/转义与正确失败标记，不用重建主线替代原树。
- 原生 19 路继续原样消费，不因新转换器支持面有限而拒绝原先可读内容。

这既补上执行边界，也删除当前不必要的泛化工作量。

## R4 — 补齐训练预览与普通撤回状态（P1）

**位置：**Task 3 的文件范围与完整旅程验收。

有两处实际源码缺口：

1. `TsumegoUnitListPage.tsx:161` 独立请求详情，并在 `:305` 用其 boardSize 渲染选题预览。只改做题 hook 会出现选题时小盘、进入后 19 路的不一致。把该页请求、缓存和代表预览断言纳入 variant 读取范围；Galaxy 的默认 hook 仍读原题。
2. `useTsumegoProblem.ts:647` 的普通 undo 用 `stones.slice(...)`，无法补回此前被提的棋子；undo 也没有取消已排队的 AI 回复。现有失败分支快照恢复解决的是**错手恢复**，不覆盖普通撤回。不能把当前代码直接写成“撤回完整状态已复用”。

最小修订是增加一个聚焦实现任务：普通撤回取消待应手计时器，并从初始派生局面加剩余走子重放或恢复完整快照，保持棋子、提子、currentNode、nextPlayer、hint 与 moveHistory 一致。保留现有实体模式不提供主动退一手的诚实禁用说明，仍用重摆同步；不新增实体撤回产品流程。

验证至少包含“非终局正确提子后退一手”和“应手尚未到来时退一手，之后不会幽灵落子”；沿用已有错手恢复、reset、换题取消测试，不追加无关状态机重构。

## R5 — 把具体前端预览移到对应 API 接线之前（P2）

**位置：**Task 3 当前先写 API/接入，最后才生成可视预览。

这与用户要求的 Foundation-First 顺序不符。纯函数可作为最小共享基础先行，但“原 N 路题：原因”、派生 19 路标记、选题预览和可用实体按钮是实际用户状态，不能直到后端接完才首次审阅。

最小修订：在 Task 3 开头用固定契约的临时 API fixture，给出一个已派生 19 路与一个保留原尺寸的 1024×600 真实 React 预览；核对必要提示、标记和触控空间，向主 session 交付具体结果。既有批准布局可沿用；如有新的布局选择，由主 session 取得用户确认后再接对应 endpoint。随后用真实派生载荷替换 fixture，删除生产中的任何模拟入口。无需新增设计系统或全状态重拍。

## R6 — RK 同源发布显式包括资格 JSON（P2）

**位置：**Task 6 当前写“完整受控运行 Python 和同源 full/strict static”。

本功能的资格权威位于新建 `katrain/web/content/kiosk19_policy.json`。沿用只复制 Python 的运行时发布清单会让 API 返回 200 却全部退回原题；仅核对构建 SHA 或 health 无法发现。

最小修订：将该 policy JSON、包初始化文件与 Python 模块明确列为同源运行时必需资产，一起进入候选包、逐文件 SHA 清单和备份/恢复集合。部署后同时检查原生 19、真实已批准派生例、明确保留例，以及对应 source/policy 摘要。失败时恢复上一套完整 runtime/static/policy/env，避免混用版本。发布前复核并发部署的实际版本，确认候选包含已在设备上的已发布更新。

现有发布范围可保留：feature → published develop → Smartbox main 子模块 → RK；不因通用 server-deploy 模板擅自部署两台云主机，不 reset/force 其他工作树，不重做实体标定，不把状态机模拟称作真实摆盘端到端验收。

## 无需扩大范围的事项

- 字体修复沿用公共字体变量和已有字号扫描即可；只有实测发现缺口才改公共机制。继续保护 Galaxy 品牌英字和棋盘几何字体。
- API 仍由显式 variant 参数决定，proxy 在旧云原始结果之后派生；源导出与管理路径保持原始。这一设计可批准。
- 审核和测试聚焦于两个内容载荷、实际局部题族、捕获/分支/复位和同源 RK 发布；不要求通用 SGF 平台、证明所有自由棋局、逐题人工长篇认证或新增全量回归。

本报告的结论是计划可执行性审核，尚未认证任何题为可上线派生，也未声称已有实现或设备验收通过。
