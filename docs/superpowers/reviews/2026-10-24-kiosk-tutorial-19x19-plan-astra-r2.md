执行口径固定如下，不构成新的设计任务：

- 新增的具体修订约束控制整个实现任务清单。Task 2 旧文字中“全部 SGF 点属性/压缩点/节点 setup”应理解为本次支持集合与不支持格式的明确拒绝验证，不能据此重新扩大为全部 SGF 功能实现。
- OGS `choice` 派生仅改变一致的棋形显示，仍在屏幕选择答案；实体落子可用性继续限定为 `puzzle`。原有 pass/remove/finish 保留原尺寸和原操作，不暗示实体盘能自动回答这些题。
- 从冻结源制作 Tsumego 审计输入时，保持 API camelCase 字段与源字段的统一规范；当前导出没有的 `hint` 只能按现有导入器的 PL→“黑先/白先”规则取得或核实，不能用缺失值制造运行时全量摘要失配。
- 计划批准不是对具体 policy 条目的安全认证。实际接受数量、完整分支等价、语义证据、字体真实渲染及完整旅程仍由既定聚焦验证与实施后独立代码/视觉审核确认。审计结果不能把“未确认目标”写成已经证明不可扩。
- 发布继续限定为已授权的 feature → published develop → Smartbox main 子模块 → RK；备份与恢复按完整 runtime/static/policy/env 一套处理。保留并发工作树、现有设备数据和标定，不因模板扩大到云发布，也不把模拟状态机测试称作实际摆盘端到端通过。

计划现在具备可执行的内容权威、转换范围、前端顺序与发布边界，可进入已授权的切片实现。
