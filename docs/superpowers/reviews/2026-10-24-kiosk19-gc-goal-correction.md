# Kiosk19 完整 GC 目标审核修正

2026-10-24，发布前修正。源数据库、SGF、答案和源导出均未改动。

首轮训练题认证核对了根 C 和提吃后置条件，却遗漏了 GC 中更具体的目标。根 C 的泛称“吃子题”不能覆盖 GC 的对杀、连接、分断或命名反击要求。独立 Astra Max 复核全部 167 个接受源的 GC 和全部节点 C，并复核 112 个接受 OGS 的完整中英正文；本轮额外目标缺口为以下四题。

| ID | 完整 GC 的具体要求 | 本次处理 |
|---|---|---|
| 66104 | 黑△和白△对杀，判断谁胜 | 提掉一颗白子的证书不足以证明对杀胜负，留原 |
| 81717 | 黑棋怎样走才能连接 | B[el] 后原黑块仍未同组，不以改 certificate family 冒充连接证明，留原 |
| 81740 | 黑棋怎样走才能分断白棋 | 没有固定切断目标分量和连接点的证书，留原 |
| 82153 | 如何反击白▲错着，走出必要过程 | 未能确认命名反击的完整局部目标，留原 |

四条固定来源记录均为 `available=false / objective_unconfirmed`，已移除原 goal、certificate 和派生 offset，并给出对应具体中文原因。

其余 163 条训练源的完整文字与已验证目标一致：162 条直接提吃，129993 只证明解除当前打吃。163 条中 150 条 GC 只有类别、难度与正确率元数据；13 条有补充说明，逐项已读：两题“吃掉互相打吃的白棋”、一题“一步计算力001”、九题“一步吃掉白棋”、一题“白吃棋”。这些说明与实际固定目标和步数证书一致，未将 generic 类别当作充分证据。

防止重犯的规则是审核 **完整 GC、根 C、全部分支 C 的合取目标**。具体 GC 目标未经独立审查或没有对应可执行证书时保留原题；不能退回泛称根 C 或 category，也不通过关键词自动给正向许可。

政策逐接受源新增 `semantic_review`，固定完整根 GC 值列表、所有节点 C 值列表与实际 goal 的规范 JSON SHA-256，并注明本轮完整目标审核。运行时缺少该审核证据或摘要不符即留原。摘要只绑定已审文字，不是自动语义证明。没有新增通用目标抽取器或棋力引擎。

验证：四个真实例先失败后通过；缺少完整题面审核证据留原，以及未审语言不算“已批准但失败”的回归通过。`tests/web_ui/test_board_variants.py` 共 57 passed，Python 文件 Black120 通过。
