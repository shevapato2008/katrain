## 根因与现有能力

- `scripts/import_kifu.py:200` 与 `katrain/web/kifu/catalog_backfill.py:519` 只自动合并 **SGF 字节完全一致** 的记录。跨来源的名字、段位、规则和赛事标签不同，导致此局哈希不同并保留两行。按主线匹配的选项只报告候选。
- `katrain/web/kifu/provenance.py:63` 的现有 `mainline_signature` 明确只作候选证据，忽略摆子和 PL，不能直接升级为自动去重依据。
- 现有 `KifuDedupBatch` / `KifuDedupChange` 已支持记录指针、来源前后像、SGF 哈希与撤销；应复用，避免删除记录。列表已统一排除重复指针，修复共享数据即可同时服务两套前端。
- 但 `catalog_backfill.py:521` 的已有指针校验及 `import_kifu.py:206` 的重复内容再导入路径都假定指针两端 SGF 必须完全一致。仅写入 `25055 → 140858` 会违反这两个路径的现有假设。需要为有明确审定证据的同局跨来源指针增加相应校验，并保留原有精确去重规则。
- `endpoints/kifu.py:220`、`kifu/library.py:81` 只在 SGF 字节一致时共享分析。这个限制应保留：同局来源可能有不同贴目、规则或缺失摆子，展示去重不能授权复用另一份引擎输入的分析。
- 旧 ID 的详情读取按原记录返回，能保留历史引用与原 SGF。不要为了去重迁移分析任务、段位快照或赛事选择到另一份 SGF。

### 未进入精确日期/身份小集合的原因

下列按 **完整操作匹配组** 分类；上表 227 是按日期与身份继续拆分后的子组，二者不能直接相减。

| 完整操作组的身份情况 | 组数 |
| --- | ---: |
| 双方有序身份 ID 完全一致 | 777 |
| 有序键相同，但含未解析原名 | 17 |
| 未解析别名或原名不同 | 893 |
| 至少一方现有身份 ID 不同 | 197 |
| 有序人物键黑白倒置 | 1 |

所有组都超过 40 手，短开局碰撞没有解释这个差额。197 组表示现有身份记录不一致，不能据此断言实际是不同人，也不能自动改 FK。

777 个双方身份一致的长序列组中，209 组日期精确一致；其余 **568 组** 应作为下一批重点候选（548 组有星阵版本）：109 组只是精确度不同且相容，117 组年份冲突，75 组同年但月/日冲突，261 组存在缺失或无法按保守日期语法解析的值，6 组相同的非精确/未解析日期。仅分隔符或补零能解释的「不同原日期」组数是 0。显式 Yoda 别名只增加一组，得到 778 组，不改变额外 568 组。

因此不能把身份、日期差异整体当成格式问题自动略过。用户指定的星阵标准决定 **已证实同局后** 的主记录选择；它不能替代同局证明。

### 会误合并的现有证据

- 58756 / 172787 同样 211 手，但前者没有后者的四颗初始让子；65749 / 172790 同样 216 手，但前者没有后者的五颗初始让子。两组都必须排除落子序列直接合并。
- 仅日期与同色双方人物键匹配共有 1,560 组，其中 1,335 组包含不同完整操作；例如 4 / 8635 都是 2022-08-05 芈昱廷对金明训，但为 95 / 104 手、操作不同。它们可能是不同对局或不同长度记录，日期加棋手不能单独证明重复。
- 不区分黑白的日期人物键有 1,874 组；其中 363 组有双方颜色倒置，也只能候选。不得通过排序人物名丢弃黑白语义。

## 建议的最小修复与数据守卫

1. 为审定的同局去重增加一个有界、默认只读的输入包：逐组明确 canonical ID、成员 ID、两端原 SGF 哈希、完整操作指纹、日期/有序身份/贴目/规则等证据与审定理由；优先星阵 canonical，保持确定的同来源择优规则。先支持已确认的 25055/140858，再审定全库候选；不能对 1,885 组直接批量执行。
2. 复用 `KifuDedupBatch` / `KifuDedupChange`，保留原记录，仅设置经审定的 `duplicate_of_id` 并将全部来源关联聚合到主记录。跨来源匹配必须使用例如 `reviewed_same_game` 的来源方法，不能误记为 `exact_sgf`。避免运行会同时修改大量名称身份的综合 backfill。
3. 在一次事务内锁定目标行、重新验证成员/SGF 哈希/原指针/来源完整前像；canonical 存在且可见、没有自指/环/链、不得碰其他批次指针。固定更新白名单，只改成员指针与所需来源链接，完整记录撤销前像。批次键唯一，重复执行幂等；任何漂移整批回滚。
4. 调整上述 importer/backfill 两个精确 SGF 假设，使已审定跨来源指针可以被验证；分析接口与报告可用性继续保持精确 SGF 绑定。原 ID、原 SGF、外部历史引用均保留，不迁移、不删除。
5. 调用现有 `maintain_after_write` 刷新预备搜索；事务提交后验证两套前端使用的列表中只剩主记录、总数按确定成员数减少、旧 ID 详情仍可读、来源齐全，撤销能恢复。只跑相关指针/来源/重导入/搜索与分析隔离测试。

实时 FK 清单：`kifu_album_sources`、`kifu_album_event_selections`、`kifu_album_rank_snapshots`、`kifu_analysis_jobs`、`kifu_dedup_changes` 的 album/pointer 字段，以及 `kifu_albums.duplicate_of_id`。分析落子通过 job 间接关联。没有必要硬删除；硬删除会扩大到这些依赖与现有历史引用。

审查前必须重新采集完整前像和引用清单，不把这次快照当作未来写入许可。本次调查没有执行数据修复。
