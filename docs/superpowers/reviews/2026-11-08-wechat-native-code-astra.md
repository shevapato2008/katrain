## 已解决的重要发现

- 原客户端按当前 AppID/通知地址拒绝旧订单冻结参数，导致超时单不能恢复。独立隔离 PG + 真实客户端复现后已修复：重试保留完整原请求，同一签名商户约束仍严格成立。
- 微信秒级 `success_time` 与本地微秒级创建时间比较会误拒同秒付款。独立复现后已按创建秒下界处理，冻结有效期采用秒精度。
- 网络前固定的 `now` 可能在查单返回后启动已到期创建，并重新显示过期 QR。现已用单调经过时间推进，查询后、锁等待后、实际 POST 前和回执均重新判断；最后 POST 要求剩余超过 80 秒，防止微信最短一分钟钳制延长冻结截止。
- 微信慢查单不再阻塞已有复盘资金结算：采用独立 server 任务、有界批量/经过时间预算和逐单短事务，失败轮转不饿死后续单。
- 手机下单前缺跨屏指引已补齐。关闭新收款后订单记录仍可打开，旧单恢复不依赖新购 capability。

## 安全与账务结论

请求签名与实际发送的编码路径/查询和 JSON 字节一致；固定官方 HTTPS origin、TLS 校验、禁止重定向、忽略环境代理。成功响应包括 204 空正文均先按原字节验签；响应与通知执行 ±300 秒窗口、固定公钥 ID 校验；非法签名探测和 AES-GCM 篡改均拒绝。非 2xx、404、倒计时和关闭弹窗均不产生付款或关单事实。三种官方 Native `code_url` 示例保留原文，不错误限定 host/path。

本地冻结 SKU、整数金额/CNY、商户、AppID、订单号、通知地址和有效期。用户→订单锁序、唯一交易号/权益/账本引用及同事务提交保护重复通知、查询和跨用户交易号竞争；失败回滚不留下部分到账。取消意图持久化、未知结果继续确认，晚成功不可被取消/过期降级；外部网络不持有账务事务或行锁。合法通知提交后才返回无正文 204，锁竞争返回可重试失败。关闭新收款后既有单仍可验签到账和查询补偿。

默认模式仍为 `disabled`；秘密使用文件且不进入配置 repr、前端或候选 Git 内容，overlay 只给 Web 只读挂载。mock 的独立 TEST 数据库检查保持有效。盒端新增取消复用云身份绑定路径，不发放本地权益、不进入离线队列，身份切换丢弃迟到响应。
