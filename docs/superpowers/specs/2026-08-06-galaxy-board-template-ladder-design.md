# Galaxy 统一棋盘模板与升降级对弈设计

> 日期：2026-08-06
> 状态：用户已确认
> 范围：galaxy 整体视觉基础、统一棋盘页模板、galaxy 升降级对弈旅程，以及后续 kiosk 升降级旅程的边界
> 既有审计：`superpowers/tracks/galaxy-ui-redesign/design.md`

## 1. 已确认的产品决策

1. 采用“A · 平衡棋盘优先”作为 galaxy 棋盘页统一模板。
2. 直播详情页是第一个视觉样板；确认后，模板复用于对局中、研究、死活题、复盘和棋谱库。
3. 保留现有 `board.png`、`B_stone.png`、`W_stone.png`、四边坐标、星位、最后一手标记和棋盘暖光材质，不重新绘制棋盘。
4. 保留现有帆船 `logo-white.png` 和当前 MUI 模块图标，只统一尺寸、颜色与容器。
5. 品牌显示改为“智星盒 / StellaBox”；界面、用户服务协议和隐私相关品牌文案都同步使用“智星盒”。
6. “智星盒”使用龙藏行楷；其余中文使用霞鹜文楷；`StellaBox`、数字、英文及其他语言保持当前字体。
7. 所有横屏档位只允许折叠左侧全局导航；右侧棋局信息栏不折叠。
8. galaxy 契约稳定后，再为 1024×600 触摸屏单独设计 kiosk，禁止直接套用 galaxy 桌面布局。

本文件中的确认决策覆盖早期设计稿、审计文档和未提交 S0 worktree 中的冲突内容。

## 2. 统一棋盘页结构

横屏结构固定为：

```text
顶栏 52px
┌──────────┬──────────────────────────────┬──────────────┐
│ 左侧导航 │            棋盘              │ 右侧信息栏   │
│ 可折叠   │      唯一连续伸缩区域         │ 固定宽度     │
│          │                              │ 模块牌       │
│          │                              │ 可滚中段     │
│          │                              │ 固定动作区   │
└──────────┴──────────────────────────────┴──────────────┘
```

### 2.1 顶栏

- 高度 52px，全宽，不占棋盘列内部高度。
- 左侧依次显示现有帆船 logo、龙藏行楷“智星盒”、原有字体“StellaBox”。
- 右侧只放全局状态与语言。
- 页面标题、返回按钮和页面级操作不得进入顶栏。

### 2.2 棋盘列

- 棋盘正上方不得出现标题、面包屑、返回按钮或工具条。
- 容器使用 `display:grid; place-items:center; padding:10px`，棋盘按可用宽高的较小值完整居中。
- 不修改既有棋盘绘制资产与语义；只改变提供给棋盘组件的容器几何。
- 不得依赖祖先 `overflow:hidden` 裁掉超出的棋盘来“适配”窗口。

### 2.3 右侧信息栏

- 宽屏 380px，标准屏 340px，窄屏 320px。
- 从上到下为：模块牌、业务主体、显示开关、行动区。
- 只有中段可滚；模块牌与底部主要动作始终可见。
- 右栏承载当前棋局信息和操作，在所有横屏档位保持可见，不提供折叠按钮。

### 2.4 模块牌

- 是棋盘页唯一的“我在哪里 / 如何返回”组件。
- 包含 40×40 返回按钮、标题、副标题和可选状态 chip。
- 直播页显示赛事/对手/手数/直播状态；其他棋盘页替换业务内容但保持同一几何。

## 3. 左侧导航折叠与响应式

### 3.1 横屏（宽度 ≥900px）

- 每个横屏档位都有同一个左栏折叠按钮，位置和语义一致。
- 折叠是完全收起，不保留 64px 图标条；只留下不小于 44px 的展开触控目标。
- 宽屏（≥1536）首次默认展开为 240px。
- 标准屏（1200–1535）首次默认展开为 216px。
- 窄屏（900–1199）首次默认收起；展开时作为覆盖式导航，不重新挤压或缩放棋盘。
- 用户操作后的展开状态按设备持久化，但跨越 `<900` 与 `≥900` 时按当前结构重新解释。
- 宽屏和标准屏收起左栏后，释放的全部宽度交给棋盘列。

### 3.2 竖屏（宽度 <900px）

- 不渲染左侧导航，改为底部导航。
- 棋盘以满宽正方形完整显示，右侧信息栏下沉到棋盘下方成为纵向内容。
- 主导航最多直接展示五个入口，其余入口进入“更多”，不得因小屏直接消失。
- 棋盘边长低于 500px 时坐标默认关闭，但开关仍保留并与实际渲染状态一致。

### 3.3 几何验收

- 1440×900 标准档：目标棋盘约 828×828，右栏 340px。
- 1024×768 窄档：左栏默认收起，右栏 320px，棋盘必须完整、居中且无横向裁切。
- 900×700 边界档和 430×880 竖屏档都必须单独实测。
- 检查 1536、1200、900、430 四个宽度档以及各断点前后 1px。

## 4. 视觉系统

### 4.1 字体

| 内容 | 字体规则 |
|---|---|
| “智星盒” | 龙藏行楷，仅用于这三个品牌字 |
| 其他中文字符 | 霞鹜文楷 Regular / Medium |
| `StellaBox`、数字、英文、其他语言 | 保持改造前实际字体栈 |

- 霞鹜文楷分片必须只覆盖中文/CJK 字符范围，不能接管拉丁字母、数字或其他语言。
- 不再引入霞鹜文楷等宽字体；数字保持原样。
- `font-synthesis:none`，避免为中文合成假粗体。
- 字体只能从 galaxy 作用域加载，kiosk 构建产物中不得出现这些字体文件。
- 早期 S0 的 49MB 仓库体积和约 511KB 中文首屏下载是上界；按“中文字符专用”重新分片后必须重新测量并记录真实预算。

### 4.2 品牌与图标

- 直接复用 `/assets/img/logo-white.png`，不得用字符、临时 SVG 或重新绘制图形替代。
- 直接复用现有 MUI 模块图标，不为视觉统一重新设计图标集。
- 模块图标统一为 24px 图形和 40px 控件容器；选中态只改变容器/语义颜色。
- 图标按钮必须有 `aria-label`，可点击元素必须使用 `button` 或 `a`。

### 4.3 色彩、间距与控件

- 沿用现有暗色与玉色体系：`#0f0f0f`、`#252525`、`#1a1a1a`、`#4a6b5c`、`#5d8270`、`#2f4539`。
- 红、黄、绿、蓝只表达错误、警告、成功和信息，不作为装饰性主色。
- 主行动 48px，普通/危险/安静行动 40px，小按钮 32px。
- 卡片圆角 14px，控件圆角 8px，返回按钮圆角 5px。
- 同一操作网格内按钮等高等宽；每屏最多一个实底主行动。

## 5. 状态与数据边界

### 5.1 通用状态

- 加载：保留布局占位，按钮内显示进度并禁用，避免布局跳动。
- 错误：说明发生了什么并提供可执行的重试，不泄露运维命令。
- 空态：提供下一步行动，不只显示“暂无数据”。
- 禁用：说明原因；禁用控件的 tooltip 必须仍可触发。
- 网络重试不得把旧数据伪装成新数据。

### 5.2 升降级对弈

- 视觉阶段读取现有契约，不擅自改后端权威边界。
- 设置、对局中和结算必须共用同一阶梯档位来源；不得回退读取与阶梯不同步的 `users.rank`。
- `provisional`、`counted=false` 和未认证档位是整屏状态，不是一条弱提示。
- 当前 `_CERTIFIED_RUNGS` 为空时，不得把任何对局显示为已计入。
- 断网结算、同步队列、恢复/重试继续由已有后端和同步逻辑负责；前端只展示真实状态。
- 如视觉预览需要 Fixture，必须与生产代码隔离，并在真实接口集成后删除。

## 6. 组件边界

最小共享基础只包含当前切片需要的组件：

- `GalaxyTopBar`：品牌和全局状态。
- `GalaxySidebar`：现有导航项、真实 MUI 图标和横屏折叠状态。
- `ModulePlate`：返回、标题、副标题、状态。
- `BoardPageShell`：棋盘列与固定右栏的几何、滚动边界和响应式换层。
- 按钮尺寸与字体 token。

`BoardPageShell` 不读取直播、升降级或研究业务数据。页面把业务节点传入模块牌、中段和固定动作区，避免共享壳层变成业务巨型组件。

## 7. 用户旅程交付顺序

1. **最小 galaxy 共享基础**：字体、真实品牌、现有图标容器、顶栏、模块牌、左栏折叠和按钮 token。
2. **galaxy 直播详情页样板**：使用真实直播数据，完成统一棋盘模板和 1440×900 视觉确认。
3. **galaxy 升降级旅程**：设置 → 开局 → 对局中 → 结算/重试，接入已有真实后端。
4. **其余 galaxy 棋盘页**：复用已确认模板，只迁移各页业务内容。
5. **galaxy 内容页与剩余响应式**：首页、对局 hub、列表页和断点回归。
6. **kiosk 升降级旅程**：以 1024×600 触摸屏重新设计，复用稳定的数据契约而非 galaxy 布局。

共享状态未稳定时不得同时铺开多个未完成切片。

## 8. 视觉与功能验收

每个视觉切片在同一目标 viewport 保存：

1. 参考截图；
2. 实现截图；
3. 并排图；
4. 叠加图或差异图。

逐项记录构图、几何间距、组件层级、字体、色彩材质、真实图标/图片资产、文案和状态语义差异。自动化布局测试通过不等于视觉通过；用户明确确认前不得进入该切片的后端阶段。

自动化至少覆盖：

- 左栏展开、收起、持久化、窄屏覆盖和键盘操作；
- 棋盘在目标 viewport 完整显示、居中且不被祖先裁切；
- 右栏中段可滚，模块牌与底部动作固定；
- 加载、错误、空、禁用、`provisional` 和 `counted=false`；
- galaxy 与 kiosk 两种构建，且 kiosk 构建不携带 galaxy 字体；
- 真实浏览器下的滚轮、触控目标和断点前后布局。
