# Galaxy 统一棋盘模板与升降级对弈设计

> 日期：2026-08-06
> 状态：用户已确认
> 范围：galaxy 整体视觉基础、统一棋盘页模板、galaxy 升降级对弈旅程，以及后续 kiosk 升降级旅程的边界
> 既有审计：`superpowers/tracks/galaxy-ui-redesign/design.md`

## 1. 已确认的产品决策

1. 采用“A · 平衡棋盘优先”作为 galaxy 棋盘页统一模板。
2. 直播详情页是第一个视觉样板；确认后，模板复用于对局中、研究、死活题、复盘和棋谱库。
3. 保留现有 `board.png`、`B_stone.png`、`W_stone.png`、四边坐标、星位、最后一手标记和棋盘暖光材质，不重新绘制棋盘。
4. 保留现有帆船 `logo-white.png` 和当前 MUI 模块图标，只统一尺寸、颜色与容器。
5. 品牌显示改为“智星盒 / StellaBox”；界面、用户服务协议和隐私相关品牌文案都同步使用“智星盒”。
6. “智星盒”使用龙藏行楷；其余中文使用霞鹜文楷；`StellaBox`、数字、英文及其他语言保持当前字体。
7. 所有横屏档位只允许折叠左侧全局导航；右侧棋局信息栏不折叠。
8. galaxy 契约稳定后，再为 1024×600 触摸屏单独设计 kiosk，禁止直接套用 galaxy 桌面布局。

本文件中的确认决策覆盖早期设计稿、审计文档和未提交 S0 worktree 中的冲突内容。

## 2. 统一棋盘页结构

横屏结构固定为：

```text
顶栏 52px
┌──────────┬──────────────────────────────┬──────────────┐
│ 左侧导航 │            棋盘              │ 右侧信息栏   │
│ 可折叠   │      唯一连续伸缩区域         │ 固定宽度     │
│          │                              │ 模块牌       │
│          │                              │ 可滚中段     │
│          │                              │ 固定动作区   │
└──────────┴──────────────────────────────┴──────────────┘
```

### 2.1 顶栏

- 高度 52px，全宽，不占棋盘列内部高度。
- 左侧依次显示现有帆船 logo、龙藏行楷“智星盒”、原有字体“StellaBox”。
- 右侧只放全局状态与语言。
- 页面标题、返回按钮和页面级操作不得进入顶栏。

### 2.2 棋盘列

- 棋盘正上方不得出现标题、面包屑、返回按钮或工具条。
- 容器使用 `display:grid; place-items:center; padding:10px`，棋盘按可用宽高的较小值完整居中。
- 不修改既有棋盘绘制资产与语义；只改变提供给棋盘组件的容器几何。
- 不得依赖祖先 `overflow:hidden` 裁掉超出的棋盘来“适配”窗口。

### 2.3 右侧信息栏

- `≥1536px` 为 380px，`1200–1535px` 为 340px，`900–1199px` 为 320px。
- 从上到下为：模块牌、业务主体、显示开关、行动区。
- 只有中段可滚；模块牌与底部主要动作始终可见。
- 右栏承载当前棋局信息和操作，在所有横屏档位保持可见，不提供折叠按钮。
- `<900px` 时右栏不再是固定侧栏，而是在完整棋盘下方变成全宽信息段。模块牌位于该段顶部，
  中段和动作区按自然高度排列；页面的棋盘后内容区负责纵向滚动，底部导航固定。此时动作区要求
  **可滚动到达**，不要求始终固定在 viewport 内。

### 2.4 模块牌

- 是棋盘页唯一的“我在哪里 / 如何返回”组件。
- 包含 40×40 返回按钮、标题、副标题和可选状态 chip。
- 直播页显示赛事/对手/手数/直播状态；其他棋盘页替换业务内容但保持同一几何。

## 3. 左侧导航折叠与响应式

### 3.1 横屏（宽度 ≥900px）

- 每个横屏档位都有同一个左栏折叠按钮，位置和语义一致。
- 折叠是完全收起，不保留 64px 图标条；只留下不小于 44px 的展开触控目标。
- 宽屏（≥1536）首次默认展开为 240px。
- 标准屏（1200–1535）首次默认展开为 216px。
- 窄屏（900–1199）首次默认收起；展开时作为覆盖式导航，不重新挤压或缩放棋盘。
- 停靠模式只使用一个存储键 `galaxy.sidebar.docked.expanded.v1`：`≥1200px` 首次默认 `true`，
  用户折叠/展开后写入并在宽屏与标准屏之间复用。
- `900–1199px` 的覆盖式导航是临时 UI 状态：首次进入、刷新、路由变化和从其他断点进入时均为关闭，
  **不写 localStorage**。点击遮罩、按 Escape、再次点击按钮或进入 `<900px` 时关闭；关闭后焦点回到
  展开按钮，打开时锁定背景滚动并把键盘焦点限制在导航内。
- 从窄屏进入 `≥1200px` 时恢复停靠模式存储值；进入 `<900px` 时卸载左栏并关闭所有覆盖状态。
- 宽屏和标准屏收起左栏后，释放的全部宽度交给棋盘列。

### 3.2 竖屏（宽度 <900px）

- 不渲染左侧导航，改为底部导航。
- 棋盘以满宽正方形完整显示，右侧信息栏下沉到棋盘下方成为纵向内容。
- 主导航最多直接展示五个入口，其余入口进入“更多”，不得因小屏直接消失。
- 棋盘边长低于 500px 时坐标默认关闭，但开关仍保留并与实际渲染状态一致。
- 应用根仍不滚；棋盘后的移动内容区是唯一纵向滚动容器，必须能滚到动作区末端，并为固定底部导航
  预留安全高度。899px 横向窗口也使用这一规则，不回退到被压缩的三列结构。

### 3.3 几何验收

- 1440×900 标准档：目标棋盘约 828×828，右栏 340px。
- 1024×768 窄档：左栏默认收起，右栏 320px，棋盘必须完整、居中且无横向裁切。
- 900×700 边界档和 430×880 竖屏档都必须单独实测。
- 检查 1536、1200、900、430 四个宽度档以及各断点前后 1px。

## 4. 视觉系统

### 4.1 字体

| 内容 | 字体规则 |
|---|---|
| “智星盒” | 龙藏行楷，仅用于这三个品牌字 |
| 其他中文字符 | 霞鹜文楷 Regular / Medium |
| `StellaBox`、数字、英文、其他语言 | `-apple-system, BlinkMacSystemFont, "Segoe UI", Helvetica, Arial, sans-serif` |

- galaxy 根节点必须暴露当前语言，例如 `data-language="cn"`。霞鹜文楷只在 `cn` 与 `tw` 两个中文
  locale 作用域内进入字体栈；`jp`、`ko`、`en` 等 locale 即使包含共享汉字码位也使用原字体栈。
- 霞鹜文楷分片只保留中文 locale 所需的 Han、CJK 标点和相关中文字符，删除拉丁字母与数字字形；
  因而混排字符串中的英文和数字会落到上面的原字体栈。
- 不再引入霞鹜文楷等宽字体；数字保持原样。
- `font-synthesis:none`，避免为中文合成假粗体。
- 字体只能从 galaxy 作用域加载，kiosk 构建产物中不得出现这些字体文件。
- 早期 S0 的 49MB 仓库体积和约 511KB 中文首屏下载是上界；按“中文字符专用”重新分片后必须重新测量并记录真实预算。
- 字体分片由版本化脚本和固定输入字体生成，不手工编辑产物；仓库保留 SIL OFL 1.1 许可与字体来源说明。

### 4.2 品牌与图标

- 直接复用 `/assets/img/logo-white.png`，不得用字符、临时 SVG 或重新绘制图形替代。
- 直接复用现有 MUI 模块图标，不为视觉统一重新设计图标集。
- 模块图标统一为 24px 图形和 40px 控件容器；选中态只改变容器/语义颜色。
- 图标按钮必须有 `aria-label`，可点击元素必须使用 `button` 或 `a`。

### 4.3 品牌文案替换边界

- 在 `src/legal/terms.ts` 中把产品名、协议标题、“弈航账号”和“弈航团队”等产品团队称呼同步改为
  “智星盒”“智星盒账号”和“智星盒团队”；同类 UI/i18n 产品品牌键一并更新。
- 不改注册公司法定名称、版权持有人、开源作者署名、SIL OFL 文本或第三方许可证。实施前先列出全部
  `弈航` / `BoardNavi` 命中；若某一处是法定主体而不是产品称呼，停止该处替换并记录待产品确认。
- `BoardNavi` 作为旧产品英文名替换为 `StellaBox`；代码内部稳定标识、数据库值和 API 枚举不因品牌改名而改名。

### 4.4 色彩、间距与控件

- 沿用现有暗色与玉色体系：`#0f0f0f`、`#252525`、`#1a1a1a`、`#4a6b5c`、`#5d8270`、`#2f4539`。
- 红、黄、绿、蓝只表达错误、警告、成功和信息，不作为装饰性主色。
- 主行动 48px，普通/危险/安静行动 40px，小按钮 32px。
- 卡片圆角 14px，控件圆角 8px，返回按钮圆角 5px。
- 同一操作网格内按钮等高等宽；每屏最多一个实底主行动。

## 5. 状态与数据边界

### 5.1 通用状态

- 加载：保留布局占位，按钮内显示进度并禁用，避免布局跳动。
- 错误：说明发生了什么并提供可执行的重试，不泄露运维命令。
- 空态：提供下一步行动，不只显示“暂无数据”。
- 禁用：说明原因；禁用控件的 tooltip 必须仍可触发。
- 网络重试不得把旧数据伪装成新数据。

### 5.2 升降级对弈

- 设置、对局中和结算必须共用 `GET /api/v1/ai-ladder/status` 的阶梯来源；不得回退读取与阶梯
  不同步的 `users.rank`。
- 现有设置契约为 `GET /api/v1/ai-ladder/status`，关键字段是 `view_state`、`placement_state`、
  `current_opponent`、`recent_ranked_results`、`net_score`、`pending_settlement` 与
  `provisional_play_allowed`。
- 现有开局契约为 `POST /api/v1/ai-ladder/start`。客户端只提交座次与计时：`color`、
  `time_enabled`、`main_time`、`byo_length`、`byo_periods`；19×19、中国规则、贴目 7.5、无让子、
  档位和配置快照由服务器决定。成功返回 `session_id`、`game_id`、`opponent` 和开局前 `status`。
- 对局中以会话状态的 `game_type="ai_ladder_ranked"` 和冻结的 opponent/rung 快照为准；对局页不开放
  AI 分析、改规则、改贴目、改让子或改强度。
- 现有设备同步契约 `POST /api/v1/ai-ladder/settlements` 保持幂等，继续由后端/同步队列负责，
  不由页面直接代替。

### 5.3 升降级状态与动作矩阵

| 阶段/状态 | 展示 | 允许动作 |
|---|---|---|
| status 加载 | 保留卡片几何的 skeleton | 开局禁用 |
| status 401/403 | 登录/权限错误 | 返回、重新登录 |
| status 503/网络/坏响应 | 玩家可理解的错误 | 重试 |
| placement | `completed_games / 5`、当前对手、规则 | 满足开局门禁时开始 |
| placed | 当前档位、净胜分、最近五局、当前对手 | 满足开局门禁时开始 |
| `pending_settlement=true` | 结算处理中，旧档位不伪装成最新 | 开局禁用、重试查询 |
| 对手认证且可用 | 正常对局 | 可开始；最终是否计入以后端回执为准 |
| 对手未认证且服务器不允许临时对局 | 不可挑战及原因 | 开局禁用 |
| 对手未认证但服务器允许临时对局 | 整屏“不计入升降级”状态 | 可开始，但主按钮降级且再次说明不计入 |
| 已结算 `counted=true` | 晋级/降级/净胜分/定级进度 | 返回或再来一局 |
| 已结算 `counted=false` | 明确“不计入”及玩家可理解原因 | 返回或按原因重试，不改变展示档位 |

`provisional_play_allowed` 只回答“能否开局”，不能回答“是否计入”。为避免前端根据私有认证集合猜测，
galaxy 升降级切片在视觉确认后需要补两个最小公开契约：

1. `status.current_opponent.counting_eligibility: "eligible" | "ineligible"`，并在 `ineligible` 时提供稳定的
   `counting_reason` 枚举；
2. `GET /api/v1/ai-ladder/settlements/{game_id}`，返回
   `{ state: "pending" }` 或
   `{ state: "settled", game_id, counted, reason }`。页面用它确认本局是否计入，再刷新 `status` 获取
   权威档位与净胜分。

这两个字段/端点是已识别的契约缺口，不在纯视觉样板阶段实现；进入 galaxy 升降级后端阶段前先冻结
枚举与错误映射。前端不得依赖 `_CERTIFIED_RUNGS` 或其他私有实现名。

如视觉预览需要 Fixture，必须与生产代码隔离，并在真实接口集成后删除。

## 6. 组件边界

最小共享基础只包含当前切片需要的组件：

- `GalaxyTopBar`：品牌和全局状态。
- `GalaxySidebar`：现有导航项、真实 MUI 图标和横屏折叠状态。
- `ModulePlate`：返回、标题、副标题、状态。
- `BoardPageShell`：棋盘列与固定右栏的几何、滚动边界和响应式换层。
- 按钮尺寸与字体 token。

`BoardPageShell` 不读取直播、升降级或研究业务数据。页面把业务节点传入模块牌、中段和固定动作区，避免共享壳层变成业务巨型组件。

## 7. 用户旅程交付顺序

1. **最小 galaxy 共享基础**：字体、真实品牌、现有图标容器、顶栏、模块牌、左栏折叠和按钮 token。
2. **galaxy 直播详情页样板**：使用真实直播数据，完成统一棋盘模板，并在 §8 的全部目标 viewport
   视觉确认；共享壳层在这一步稳定后才允许复用。
3. **galaxy 升降级旅程**：设置 → 开局 → 对局中 → 结算/重试，接入已有真实后端。
4. **其余 galaxy 棋盘页**：复用已确认模板，只迁移各页业务内容。
5. **galaxy 内容页与剩余响应式**：首页、对局 hub、列表页和断点回归。
6. **kiosk 升降级旅程**：以 1024×600 触摸屏重新设计，复用稳定的数据契约而非 galaxy 布局。

共享状态未稳定时不得同时铺开多个未完成切片。

## 11. 实施计划拆分
