# 棋谱库棋手与赛事十一语言全量本地化设计

## 目标

正式库全部棋谱在十一种设置语言（`en cn tw jp ko de es fr ru tr ua`）下，都能显示恰当的棋手姓名及赛事信息，支持原文和各语言别名检索同一棋谱。棋手名与对局时的段位分开；正式赛事有独立 ID。原始 SGF 和 `kifu_albums` 的原文元数据始终保留。实施分批次，但交付门槛是全量覆盖，而不是只完成首批样本。

“全量”按**每条可展示棋谱 × 十一语言**验收：已知棋手显示该语言的审核名称或经批准的规范转写；确实未知的棋手显示本地化的“未知棋手”；正式赛事显示本地化名称并组合年份、赛季、轮次；泛称、对局描述、程序名与空赛事按其实际语义显示或隐藏，不伪造赛事实体。每张卡必须有可追溯的显示决策，不能靠未说明的 SGF 原文回退蒙混过关。

## 5% 只读抽样

2026-10-02 从正式库用 `id % 20 = 0` 固定选取 8,651 / 173,025 盘（约 5.00%），只读取姓名、段位、赛事、轮次、日期、来源路径与实体 ID，没有改动数据库或导出 SGF 内容。七类来源均按约 5% 进入样本：`19x19` 7,514 / 150,306、`CWI_1950_1978` 809 / 16,179、`CWI_History_Full` 237 / 4,735、`Go_Seigen` 45 / 891，以及三个历史名家包共 46 / 914。样本位于本机 `/tmp/kifu-5pct-20261002.csv`，不纳入仓库。

| 项目 | 抽样发现 |
|---|---:|
| 黑白双方姓名槽位 / 原始不同写法 | 17,302 / 2,729 |
| 明确中文段位接在姓名后的槽位 / 不同写法 | 156 / 129 |
| 去掉这类段位后的不同姓名写法 | 2,606 |
| 有独立 `BR/WR` 的槽位 | 14,877 |
| 不为空的赛事实值 / 不同实值 | 8,514 / 6,251 |
| 赛事字段为空 / 年份在开头 / 超过 40 字符 | 137 / 1,604 / 110 |
| `GNUGo3.8`、泛称“段位赛”“个人赛”等 | 至少 170 |
| 姓名为 `Unknown` 等占位值 / 混入 `]BR[` 等 SGF 片段 | 68 / 2 |
| 样本已关联黑方 / 白方 / 赛事实体 ID | 66 / 99 / 61 |

全库另有 7,251 种原始棋手写法和 50,222 种原始赛事实值，现有 876 位棋手、22 项赛事并非完整身份库。Top 100 个去段位棋手写法只覆盖约 30% 的全部姓名槽位；Top 100 赛事实值只覆盖约 13% 的棋局。全量工作不能只翻译高频条目。

样本暴露三个需要特别处理的边界：`崔珪昞]BR[九段` 看似以“九段”结尾，实际是损坏的 SGF 片段，不能当正常姓名拆分；个别独立 `BR` 写成“白九目半胜”等结果文字，不能直接显示为段位；`冠华弈手杯职业棋手训练赛赵兴华执白中盘胜李莹` 把赛事、双方、结果混写在 `EV` 中，不能把整句作为正式赛事翻译。抽样中也有 `GNUGo3.8` 及泛称，不能为它们建立赛事 ID。损坏值经对照原始 SGF 和可靠外部资料可确定时，以有证据的派生修正显示；无法确定时显示本地化“姓名资料有误”或隐藏坏赛事，并记录原因，绝不原样显示字段片段。

[SGF FF[4] 规范](https://red-bean.com/sgf/properties.html)分别定义 `PB/PW` 为姓名、`BR/WR` 为段位、`EV` 为赛事、`RO` 为轮次。[日本棋院吴清源资料](https://www.nihonkiin.or.jp/player/htm/ki001001.htm)将姓名和九段分开；[俄罗斯围棋资料](https://rusgolib.gofederation.ru/GoSeigen.html)提供“Го Сэйгэн”作为俄语名称样本。

## 方案选择

1. **分层归一、逐语言物化（采用）**：一次解析与识别原始棋手/赛事，翻译或规范转写只存实体与少数未归入实体的原始说明。卡片按 ID 和语言批量查名称，未知与冲突走显式待审队列。能逐批校验，最终覆盖全量。
2. **把每盘原始 `PB/PW/EV` 直接机器翻译十一遍**：实现快，但约 52 万余个赛事文本输出会重复且互相矛盾；姓名、段位、比赛届次、结果容易误译，跨语言去重也无法依赖。
3. **纯人工逐条翻译所有原始值**：专名质量可能高，但 50,222 种赛事字段大量是年份、轮次、自由叙述或垃圾值，直接逐条人工处理成本不成比例；仍必须先做结构化分类。

## 数据契约

1. **对局原文不可变**：`kifu_albums.player_black/player_white/black_rank/white_rank/event/round_name/sgf_content/source_path` 维持导入值。分离后的姓名、历史段位和赛事解析结果作为派生字段及实体引用保存；不会把棋手现今段位写回旧对局。
2. **棋手身份**：沿用 `kifu_players`、`kifu_player_aliases`、`kifu_player_names`。对每个非占位棋手原始写法生成候选，只有无歧义且有证据的匹配可自动关联；同名异人、程序名、SGF 损坏标记进入人工审查。不能消歧但原名可读的写法进入独立的“原始姓名十一语言显示”层，只翻译该写法、不声称属于某个人，且不与其他人的搜索结果合并；待人工确认身份后再迁入实体。全量译名按 `(player_id, lang)` 或 `(raw_player_value_id, lang)` 唯一，并记录来源、生成规则、审核状态及版本。翻译的显示名称仅在身份已确认且别名冲突检查通过后加入跨语言搜索别名。
3. **赛事身份和原始说明**：真实赛事沿用 `kifu_events`、`kifu_event_aliases`、`kifu_event_names`；年份、赛季、届次、轮次是组合参数，不随每年另建赛事实体。为不能归入赛事的原始 `EV/GN` 建一个受控的“原始说明分类与十一语言显示”层，按不同原文只存一次；分类至少区分正式赛事、泛称、对局说明、程序/来源标签、空值和坏数据。不同类型不可互相当别名。
4. **来源及译名证据**：建立可版本化的来源清单（棋院、主办方、同语言专业围棋资料、维基百科同语言条目、Wikidata），以及实体或原始写法 × 目标语言的证据记录。记录检索过的来源、候选原文/别名与查询词、时间、命中/未命中、URL 或页面标识、核名判断及审核人。已有通行译名时采用它；找到可信的目标语实际用名即可停止负面检索并进入独立审核。原有 `cn tw jp ko en` 五语在自行生成前保持严格的规定来源闭环；新增 `de es fr ru tr ua` 六语可在专业来源加互补百科或 Wikidata 检查构成的、如实标明限制的合理范围未找到用名后规范转写。自行生成前还须确立原名、读音或所属语言及其证据；`source_path` 不是姓名国别或读音。生成的名称记录规则/模型版本，且状态与已有名称分开。查询只能证明在所列范围内“未找到”，不能声称绝对不存在。机器生成候选须经该语言独立审核后才能上线。任何无法安全决定的名称进入待审队列，不能静默标为已核实。最终覆盖门槛要求待审队列中没有会导致卡片原文回退或错认身份的项目。
5. **段位显示优先级**：若 `BR/WR` 是合理段位，用独立字段；缺失时用姓名末尾可确定的段位；两者有效但不一致时显示独立字段并记录冲突；独立字段明显是结果文字或占位符时不用它，改用末尾段位或显示空段位。API 用空字符串阻止前端 `??` 再暴露无效原文。含 `]BR[` 等字段片段的姓名不自动切割，列为损坏数据。
6. **赛事显示门槛**：只有实体已关联且该语言名称已获准显示，才组合如 `JapanPromotionTournament,1934,Fall` 的本地化“大手合·1934 秋”；否则从原始说明的已审本地化层取值。现有无条件把该模式显示为 Oteai 的路径必须修正。空、程序或来源标签可不显示赛事，但须记录分类，不再把 `GNUGo3.8` 作为赛事名。

## 全量处理流程

### 1. 完整清单与分类

对全库做只读、可重复的不同姓名/赛事实值清单和频次统计，按来源、年代、脚本类型、是否含段位/年份/轮次/结果分层。把 5% 样本的异常规则固化为测试；再用全库清单找样本未覆盖的格式。不能扫描磁盘 SGF 目录来绕过现有数据库。

### 2. 身份与赛事归一

从既有五语言旧表、官方棋院人员/赛事目录、CWI、现有审定种子建立别名候选。规范化只做确定性处理（空白、全半角、明确段位和年份组件），保留原始值；同名碰撞用国别、年代、对手、来源核对，无法确定则待审。赛事的自由说明与真实赛事分开，先建立可解释的解析模板，再人工处理长尾。每批 dry-run 输出准确的旧 ID→新 ID、冲突及卡片影响，再写入。

### 3. 十一语言生成与审核

先把约 5 万种原始赛事实值按正式赛事身份、年份届次等结构成分、泛称及说明归并，再按身份或真正不同的说明 × 语言查证，避免对每一盘或每个年份重做检索。批量导入专业来源中各语言既有专名。每个身份或未归一写法 × 目标语言先查官方棋院、赛事主办方、该语言专业围棋资料；有实际用名与身份依据即可进入独立审核，不做无意义的全站负面检索。没有正面用名时，原有五语查完规定来源；新增六语使用有版本的合理检索范围，至少含一个目标语专业来源及一个目标语百科或 Wikidata 精确字段检查，明确记录未查渠道、未遍历页和已知线索的处理，再考虑自行转写/翻译。若候选互相冲突，先人工核对身份、使用语境和来源权威性，选定通行名；排除候选的理由必须入证据记录。Wikidata 的标签只是发现线索，不单独构成权威证明。[Wikibase API 文档](https://www.mediawiki.org/wiki/Wikibase/API)支持按实体和语言读取标签，[Wikidata 查询文档](https://www.wikidata.org/wiki/Wikidata:SPARQL_query_service/queries/examples)说明语言标签查询，可用于批量发现候选；棋院和赛事主办方资料仍须核对身份与名称。共享同一来源和检索规则的批量条目可复用查询模板，但每个发布名称须能指向自己的命中或未命中证据。自行转写前先用专业来源确立原名/读音/语言；不能根据数据集来源猜测发音。每个自行生成值附查询日志和规则，按语种审核。赛事通用组成部分（年份、赛季、轮次、团体/个人等）用十一语言模板；剩余专名/说明按同一来源先行流程处理。按“出现次数 × 风险”排序审核，但最终仍逐类处理到全库无未决显示项。不同语言的译名、别名、来源与审批日志可追溯。产品语言代码与资料语言标签需显式映射：`ua→uk`、`jp→ja`、`cn→zh-Hans`、`tw→zh-Hant`（保留实际地区/脚本标签），入库仍存产品代码。Wikidata 的默认标签、多语言 `mul` 和回退返回值不得视为目标语言已有译名，证据记录实际返回语言。

### 4. 安全写入与回滚

新增独立的身份/译名批次，不复用会做去重和来源变更的现有 `backfill_catalog` 默认路径。每个批次带输入清单版本、审核摘要和唯一键；在同一数据库事务内记录每个改动的前后值。只做符合预期的 NULL→ID 或明确审核批准的更正，不覆盖冲突；撤销时仅恢复当前值仍等于本批写入值的记录。批次作用域必须是已审的原始写法/对局 ID，不因 `batch_size` 小就扫描并写全库。生产写入前备份，测试环境先演练。

### 5. 列表切换与性能

保留 `GET /api/v1/kifu/albums?lang=` 的分页响应，每页约 20 盘。服务端在已查出的当页 ID 上批量读取姓名、赛事及说明译名，避免 N+1；`(identity_id,lang)` 与 `(raw_event_id,lang)` 索引支撑即时切换。前端换语言后重取当前页、保留查询与页码，并忽略旧语言的迟到响应。搜索与显示语言解耦，所有经审别名都应得到同一集合；全量增加数据后做生产体量的 11 语言 P95 延迟验证，优化当前每次重算的语言无关 COUNT。

## 验收与发布门槛

- 对全库全部可见棋谱，逐语言统计黑方、白方、赛事显示决策：有来源的约定名称/经检索与审核的自行转写或翻译/本地化通用值/已核实的派生修正/有原因的损坏值提示或隐藏/应隐藏的空或程序标签之和为 100%；未经说明的原始值回退为 0。未知棋手和无赛事有本地化提示或按设计隐藏，不混作实体。每条自行生成的译名必须能回溯“查过哪些目标语言资料，为何判定未找到通行译名”。
- 每个非占位、未损坏的棋手原始写法都关联一个经审核的身份，或带有明确人工判定的不可归一理由及十一语言原始姓名显示值；损坏姓名与赛事坏数据要有派生修正证据或明确的本地化错误/隐藏决策；每个原始赛事实值有分类，真实赛事有独立 ID。别名冲突、段位冲突及混入结果的事项有可追踪处理记录。
- 抽样 5% 的全部类别、各来源和年代均进入回归集；十一语言都检查姓名、赛事、年份/轮次、段位，`吴清源/Go Seigen/Го Сэйгэн` 搜索等价。原始 SGF 与元数据校验不变。
- 分批在测试环境验证，再把相同代码和已审数据批次部署正式环境；每批可 dry-run、重试与按前像撤销。代码经独立审查通过后才发布数据。全量覆盖率未达门槛时明确报告缺口，不宣布交付完成。

## 已确认的译名政策

用户允许规范转写：五种原有语言先完成严格来源范围查证；六种新增语言可在有记录、独立审核的合理范围未发现当地用名后按来源语原名与读音转写。所有转写都注明范围限制和规则；未查证条目不得冒充最终译名。
