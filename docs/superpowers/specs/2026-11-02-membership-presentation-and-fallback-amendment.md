# 会员展示与积分回退修订

2026-11-02。用户在双端 v3 视觉预览后提出本次修订，优先于原 v3 及其两轮业务评审中与下文冲突的展示、扣费来源和候选价格约定。其余额度、模型、事务、权限、TEST 隔离及发布约束继续有效。不重做旧计划或创建 worktree。

## 用户确认的方向

- Galaxy 与 Kiosk 都不向用户展示“标准单位”或内部整数请求量，包括说明、购买确认和错误状态。用量分别显示本期、本周剩余百分比及到期／恢复时间。
- 不把两个百分比取最小值称为总体剩余，因为分母不同；底层授权仍用本期与本周实际剩余请求量的较小值。预留计入不可用，界面可合并表述为“已用及分析中”。
- 套餐行名改为“普通报告”，以日均约 1／4／13 盘帮助选择；按每盘 300 手、含初始局面换算。日均只是 30 天预算除以 30，**不新增每日上限或每日发放**。本期和自然周上限保留，高级报告消耗约 4 倍。
- 会员优先，会员不足时自动使用现有 API 积分；不再要求单独选择钱包作为兜底来源。该指示替代旧稿“不自动回退钱包”。

## 自动选择来源的边界

1. 一次规范化 operation 的完整预算仍由服务端按固定模型、深度与实际完整棋谱计算。会员的本期与本周均足够覆盖本次完整预算时使用会员；否则整次使用钱包，**不把一次 operation 拆成部分会员、部分钱包**。剩余的零散会员量可供之后较小请求使用，不清空、不转积分。
2. 开始分析前，在已有报价／开始操作处一并显示“优先会员；额度不足时本次消耗 X 积分”。用户的一次开始操作接受该次已展示的回退费用，不新增一个每次都要选择来源的弹窗。自动回退不等于自动购买积分、自动扣人民币或发起续费。
3. quote 保留用户、环境、完整棋谱、模型／深度、价格版本、失效时间、来源策略与允许扣积分上限。事务内重检两项会员量；并发导致不足、但钱包费用仍被原报价覆盖时，可原子选择钱包。费用超出原报价或权限／账号条件改变时重新报价，不能用回退策略静默提价。
4. 钱包不足则阻止分析，显示充值或等待会员恢复。账号、权限、会员读取或钱包服务未确认，不能视为会员已用尽而绕过校验扣钱包。原账户 generation、旧响应丢弃、操作幂等、退款回原来源／原周期、失败结果不可读、worker fencing 等要求不变。
5. Free 仍使用原有每周一份普通报告资格及 P3 前置；本次不将其改成通用额度或修改领取事实。这里只改付费会员与购买钱包的来源优先级。
