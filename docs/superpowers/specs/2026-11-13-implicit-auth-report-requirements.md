## 2. 已口头确认的账号交互

### A1：采用一个唯一公开用户名

- 最新决定是：**用户名唯一，同时用于公开展示和用户名密码登录**。
- 本次不拆出另一个可以重名的昵称，也不添加展示后缀。此前关于“重复昵称”的讨论已被此决定替代。
- 后台继续使用既有 UUID/内部账号标识关联会员、积分和棋谱；公开界面不展示手机号或冗长内部 ID。

### A2：手机号验证码是统一入口，同一弹窗完成

| 验证后的情形 | 用户看到的操作 | 应有结果 |
| --- | --- | --- |
| 手机号已关联完整账号 | 无需再次填写用户名 | 登录原账号 |
| 手机号尚未关联账号 | 同一弹窗补一个唯一用户名，点击“继续” | 按下面的名称分支处理 |
| 用户名可用 | 不跳转独立注册页面、不要求首次设置密码 | 后台完成隐式注册、生成账号 UUID、按既有规则一次性发放 50 积分，并登录 |
| 用户名已存在，且该旧账号尚未绑定手机号 | 才显示原账号密码框 | 密码验证成功后，将已验证手机号绑定到原账号并登录；保留原 UUID、会员、积分和棋谱 |
| 用户名已存在，但账号已绑定另一个手机号 | 简短提示并提供原账号登录入口 | 不在该流程中覆盖原绑定或合并账号 |
| 过去自动生成、尚无公开用户名的手机号账号 | 同一弹窗补唯一用户名 | 在原账号上补全，不另建账号、不重复赠额、不改动其原有资产 |

- 新号真正创建和赠额发生在用户填写用户名并确认继续之后；验证手机号后不先创建一个无名账号再合并。
- 旧账号绑定必须同时证明该手机号的控制权和旧账号密码；用户名相同本身不构成绑定授权。
- 尽量复用这次有效的短信验证证明，不让用户无故重复收码；过期或失效时提供直接重新验证入口。
- 查询名称可用并不等于最终占用成功；提交时发生重名冲突应能在同一弹窗修改后继续。
- 保留现有用户名密码登录方式。新手机用户首次不强制设置密码，之后可设置；后续密码入口是否已有、如何复用，在设计/计划时一并核清。
- 普通登录、旧账号绑定与原账号补全均不重复发放注册奖励。

### A3：界面保持简洁

- 不堆叠流程解释、技术术语、计费说明和重复提示。
- 新用户只在需要时补用户名；只有用户名已存在时才显示旧密码。
- 50 积分采用成功后的简短提示，不占满登录表单。
- Galaxy：登录/补全保留在真实 Galaxy 页面背景上的弹窗，网页默认匿名访问，不放“访客登录”按钮。
- Kiosk/launcher：保留访客入口及已有账号入口。
- 验证码、密码等仅在当前表单内暂存；关闭、切换账号或验证失效时清理，并明确可恢复的下一步。

## 3. 复盘分析进度与中断恢复

必须逐项区分“当前分支已实现”“其他工作区只有计划”“尚有缺口”和“运行时待验收”。其他会话的计划文件存在，不代表代码已经实现或部署。

独立只读核查已找到：

| 项目 | 当前源码结论 | 本次处理 |
| --- | --- | --- |
| 每步分析结果和进度入库 | 已有 `ReportTaskMoveDB` 和逐局面事务提交 | 保留，不重建底层；后续只做必要验收 |
| RK/浏览器关闭，云端继续分析 | 报告列表、创建和重试走云端；重新进入会按 `user_game_id` 读回任务 | 源码支持，尚未实机断电验收；不当作缺失功能重写 |

### R2：分析进度显示在所属棋局右侧，独立于对局卡片

- 在复盘列表选择某历史棋局，点击普通报告或高级/深度报告后，进度直接出现在该棋局右侧，始终能看清所属对局。
- 应能看出当前报告档位、已完成/总步骤及直观进度；具体文案、进度条或布局由设计稿比较后确认。
- 最新视觉追加：**对局卡片在左、普通/高级报告块在右，报告块位于对局卡片边框和背景之外，不能放进卡片内部**。保持原对局卡片宽度和紧凑高度，七英寸 1024×600 下仍能同时看到约三张；不能为两档进度加宽卡片、挤掉其他对局。
- 已取得 RK3562 实机复盘截图：屏幕 1024×600、DPR 1；原左预览 296px，右列表 680px；对局卡片实际为 **624×74px**，右侧原有 48px 删除槽位与 8px 间隔。此前稿子的 676×104px 不是实机原卡片尺寸，已由这次实测取代。新稿继续保留对局卡片 624×74px；删除入口须保留且易找到。
- 用户查看 v3 后追加：**恢复原有 74px 行高及 8px 行间距**，不能让两个报告块撑高每条对局；每档报告只占一行，完整名称与进度并排。
- 最新反馈取代 Kiosk 圆环方案：**Kiosk 改用矩形横向填充进度**，沿用此前 Galaxy 普通/高级报告块的展示方式。每档完整名称与百分比在同一行，名称缩小到14px；保留轻微充电光效，填充只能随真实手数变化。两档独立存在，普通完成不能遮住高级运行。
- 为容纳完整报告名称，设计将 Kiosk 左侧棋盘预览收紧到约 224px，列表扩大到约 752px；对局卡片仍为 624×74px，右侧独立报告区约 120×74px，两行各 34px、间隔 6px。v5 只替换 Kiosk 进度表现，不再增加卡片间距，也不改 Galaxy 稿。
- 右侧紧凑报告区以非交互状态/进度展示为主；发起、查看、继续、重试保留在左侧具有足够触控尺寸的“分析报告”菜单中，不把 34px 状态行当作小触控按钮。
- Kiosk 预览固定为 **1024×600 的产品画布**：大电脑窗口中居中，不能随浏览器拉大；小窗口仅整体等比缩小，不能以响应式重排冒充七英寸屏幕。
- 未生成、完成、失败或中断态保留必要操作；非运行态停止流动。动效不伪造完成比例，低动态偏好下仍须能靠文字与填充量看懂状态。
- 普通报告已完成时，仍须看得见该棋局高级报告正在分析，不能被“已完成”状态盖住。
- 设计覆盖必要状态：排队、分析中、中断待继续、继续中、完成、失败可重试。
- 设计预览可模拟这些状态，但不得把模拟动画描述成真实服务器进度。

### R3：已完成步骤可靠保存，重启后继续

- 每完成一步，将该步分析结果及对应进度持久化到数据库，而不是仅放在内存或仅依靠进度数字。
- 盒端中断后再次进入时能找到原云任务和已完成步骤；云端若一直正常运行，应直接显示最新进度或完成结果，而不是让用户重新发起分析。
- 必须分别核查：①RK3562/浏览器离线，云端任务是否继续；②执行分析的服务/进程重启，是否能从数据库恢复。
- UI 关闭或盒端关机后，重新进入列表应正确关联原任务，不能只因为前端状态丢失就重复提交。
- 续算和重试沿用既有计价与账务规则，不因恢复过程重复扣费；具体预留、退款、重试边界在后续实施计划中明确。
- 真正的断电恢复仍需后续针对性测试/设备验收，不能用代码存在或设计动画代替。

**待用户确认的加强范围：** 是否还要求“执行分析的云端 worker 自身重启/中断后，收费任务也保留断点继续”。这是当前收费生命周期的新增行为，会涉及预留、退款与恢复幂等；不能在核查盒端关机需求时默认重写。设计稿会单独标出该拟议状态，待整体确认后才决定是否进入计划。

## 4. 跨平台对局的来源标签

### S1：复盘卡片来源必须正确

- 用户反馈：跨平台对弈的对局在复盘列表卡片上仍被标为“自由对弈”，这是错误分类。
- 核查实际平台接入、来源写入、历史记录持久化、列表 DTO 和卡片映射；不能只改一个固定字符串。
- 用户语音提到“星阵/星阵镜”。已从平台常量核实 `golaxy=星阵`、`fox=野狐`、`ogs=OGS`；名称不能互相混用，原本未开放的平台也不能在设计中伪装成可对弈。
- 设计中区分自由对弈和跨平台对弈，并在有可靠数据时体现具体平台。
- 旧记录来源不完整时，不能凭对手名字推断平台；诚实的回退标签在设计阶段确认。
- 如果现有正确实现已在其他已发布代码中存在，只做必要核实与集成判断，不重复开发。
