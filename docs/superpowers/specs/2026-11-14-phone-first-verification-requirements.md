# 手机号赠额提示与四棋类公开用户名需求

状态：用户于 2026-11-14 确认四棋类范围，并明确“开始实施吧”。按更新后的计划继续审核、开发与发布。

## 1. 首次验证手机号与50积分

- 首次验证手机号可领取50积分，包括新用户注册和旧账号首次绑定。
- 账号或手机号任一已领取过赠额，就不重复发放；不是每次登录或每次绑定都送。
- 绑定前显示简短提示：“首次验证手机号送50积分，已领取不再赠送。”
- 成功后按服务端实际结果提示；只有真正发放了赠额，才能显示已赠送50积分。
- 旧账号的会员、积分、棋谱及账号归属保留；重复请求、失败和重试不能导致重复到账。
- 历史已绑定但未领过赠额的补领方式尚未由用户单独确认，本次不得擅自批量补发或新增补领流程。

## 2. 手机验证码登录与旧账号兼容

- 手机号已关联账号：验证码验证后直接进入原账号，不重复取名、不重复注册或赠额。
- 手机号尚未关联账号：同一弹窗填写唯一公开用户名，确认后后台完成隐式注册并登录，不跳转独立注册页、不强制首次设置密码。
- 填写的用户名属于旧账号：验证原账号密码后才能绑定已验证手机号，保留原账号及资产；用户名相同不等于允许合并账号。
- 既有用户名密码登录方式保持兼容。

## 3. 四种棋类共享账号和公开用户名

用户明确确认：范围为围棋、国际象棋、中国象棋、五子棋，不能仅修复某一个棋类。

- 四种棋类使用同一套注册、登录及账号身份信息。用户无论从哪个入口注册、登录或绑定手机号，切换棋类后仍是同一个账号，并取得同一个公开用户名。
- 此处“名字”指用户自己填写的公开用户名或昵称，不是实名，也不是后台用户ID。
- Galaxy网页界面与Kiosk盒端界面均适用；检查各棋类实际提供的界面，不能只修一个前端或一个页面。
- 首页称呼、账户栏、玩家名称、对阵大厅、对局卡片及复盘列表等用户可见名称位置，都应一致展示公开用户名。对局卡片是用户特别强调的验收位置。
- UUID、数字主键及自动生成的内部账号名仅用于内部识别、授权和数据关联，不能代替公开用户名展示；也不能以完整手机号作为公开名称回退。
- 已有账号和已经绑定手机号的账号同样必须正确显示，无需重新注册；不能仅保证新账号正常。
- 保留合法的历史用户名。确实没有公开名称或暂时无法读取时，显示简短的本地化状态，不暴露内部编号，不编造昵称。
- 显示名称修复不改变账号ID、登录凭据、会员和积分归属，不通过新建账号或按昵称合并来解决。
- 对局记录中属于站内账号的玩家名称，应按可信身份关联展示；外部平台棋手名、对手身份及历史对局内容不得被错误覆盖。

## 4. 简洁界面与语言保留

- 登录、注册及绑定界面保持简洁，只保留必要输入、状态和简短提示，不堆积说明文字。
- Galaxy登录、注册保持弹窗及Galaxy页面背景；网页默认可作为访客浏览，不增加盒端式访客登录入口。
- 保留盒端访客入口。
- 保留Galaxy/Kiosk已有11种语言；相关新增或修改文案应完成对应翻译。其他棋类与盒端启动器保留各自已有语言支持。

## 5. 开发与部署约束

- 用户已恢复执行；按本需求及更新后的开发计划推进，不扩大到未确认的历史补领或账号重构。
- 恢复执行后，沿用 Writing Plans、独立Astra Max审核、subagent-driven-development和最终独立代码审核流程，验证聚焦本次行为。

- 不自动执行真实短信、支付或付费分析验收；保留现有支付、短信和会员配置。
