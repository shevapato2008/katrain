# 配置体检 + 报错追踪（2026-09-27）

总设计 §10 第 7、8 项。范围与架构由独立 Opus 代理代 Fan 裁定；视觉与代码各审一轮，发现全部已修。

## 配置体检

- **来源**：web / cron / admin 各自把「对自己生效配置的结论」写进 `process_health_reports`（每进程一行，启动即写、之后每 10 分钟覆盖；首写失败 30 秒后重试）。只写检查项 id、级别和固定模板文案，不写配置值（有哨兵密钥测试）。cron 镜像只复制 `katrain/cron/`，所以 cron 有自己的一份检查代码。
- **规则**：数据库是 SQLite → 有问题；计费闸开且每周免费报告 > 0 → 有问题；媒体存本机 → 注意；数据库 / MinIO 密码含 `CHANGE_ME` → 有问题；cron 分析引擎地址为空 → 有问题、容器内指向回环 → 注意；翻译密钥为空 → 注意；三进程构建版本不一致 → 注意，版本 unknown 不算一致。规则自身出错 → 未知，不算正常。
- **明确不查**：SECRET_KEY（能上报即已过启动闸）、外部服务连通性（KataGo /health 会报假绿）、Grafana；删掉了审查指出会误报的「云端引擎为空」与恒真的「运行模式」。
- **诚实显示**：没有行 = 从未上报（计入有问题）；超过 30 分钟 = 上报已过期，结论隐藏只留时间，汇总里单独提示；构建版本在镜像构建时由 `KATRAIN_BUILD_SHA` 注入（compose `args`）。

## 报错追踪

- 每个进程在根 logger（web / admin 另挂 `uvicorn.error`）装一个 ERROR 级 handler：`emit` 只把截断到 8 KB 的原文放进 1000 条的有界队列（满即丢弃计数），不做正则、不写库、不抛异常；独立线程每 5 秒脱敏、聚合，经一条连接（语句超时 2 秒、连接超时 2 秒、隐藏 SQL 参数）逐组原子 upsert 进 `error_groups`。
- 指纹 = 进程 + logger + 异常类型 + 脱敏并把数字折叠后的模板 + 最内三帧「文件:函数」。上限 5000 组，30 天未出现即删除；已解决的再出现会自动重新打开。cron 的报错带当前任务名。
- 管理页按最近出现排序、可按状态与进程筛选；「标记已解决」与审计同一事务。页面显示每个采集器的心跳（上报时间、最近写库、丢弃、卡住），任一采集器不健康时不说「没有报错」。侧栏角标：24 小时内出现过的未解决分组数、配置体检的问题数，每分钟刷新。告警渠道未选，v1 只做后台内提示。
