# 用户与计费 + 审计日志（2026-09-27）

总设计 §10 第 4 项。Fan 委托独立 Opus 代理代为裁定范围与视觉；四图与实机验收留到最后一起。

## 裁定（独立代理）

- v1 做：用户列表（id / 用户名前缀 / uuid 搜索，20 人一页）与详情（余额、预扣、账本 50 条一页、额度只读、兑换记录）；积分调整；兑换码批次生成与列表；审计日志页。不做：充值订单页（没有任何创建订单的入口，表为空）、编辑额度、封号 / 改密码 / 改 is_admin。
- 积分可加可扣：扣是追加负数行，条件 UPDATE 保证余额不为负；|金额| ≤ 12000；原因 ≥ 5 字写进审计；弹窗里重新输入用户名与金额，服务端再核一遍；幂等键为每个弹窗一个 UUID（`admin_adjust:{key}`），废弃原来按秒的 ref_id。同键同请求重放返回「已处理」，同键异请求 409。
- 兑换码每批 ≤ 200 个、面额 ≤ 12000、有效期必填 ≤ 365 天；完整码值只在生成响应里出现一次（附 CSV），之后列表打码，审计里不写码值；批次以到期时刻识别（同批共享，微秒级唯一），用途写审计。
- 审计与业务写入同一事务：`billing.apply_adjustment` / `add_redeem_codes` 不提交，路由写完审计后统一 commit，失败整体回滚；`grant` / `generate_redeem_codes` 行为不变。
- 生产不做成只读：护栏靠重新输入确认；页头与弹窗标题显示红色「生产环境」。
- 返回字段为显式白名单，不含密码哈希、令牌与完整码值。
