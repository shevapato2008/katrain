## 已作的决定

- **基准点校正默认关闭**（原型默认开启）。依据 Fan 的硬规则：几何用 LED 绝不自动闪，只能由用户手动选择/触发。选「每手校正」后，每次拍照前点亮一圈空位基准灯，仍只在操作员点拍照时发生。模式在会话第一帧写入 manifest 后固定。
- **每手校正的单帧单应**写入该帧 `geometry_correction`，复核与冻结按该帧自己的 M 贴标签；暂存目录每次新建，所以回退只到开局标定（`frozen`），不跨帧沿用「上一帧成功值」。
- **撤回只撤最新一帧**，初始帧不可撤；已结束的会话不能再追加或撤回，但可读、可冻结。
- 蓝灯提子是纯引导，不产生训练帧：提子后那一帧仍只带「下一手」的红/绿灯，标签语义不变。
- 「本机部署与诊断」子菜单在第 5 段接入前保持禁用（悬停提示「开发中」），不放假页面。

## 自动推进的裁定（独立代理，2026-09-27）

- 顺序改为 5a → 3 → 5b；自己另起模型加载会多出一道要删的信任边界，且帧证据需要登记里的 model id/sha。
- 自动推进只替代「确认」这一下：保存的就是稳定窗口里最后一张被判定的帧，不再另抓。
- 自动帧 `qa_status="camera_matched"`，`capture_trigger="camera"`，记录 model id/sha、阈值、期望步与 board hash、识别出的 361 点、missing/extra（须为空）、稳定帧数与时长、图像 sha（须等于被判定帧）。人工帧 `capture_trigger="operator"`，卡住后人工确认加 `auto_stalled`。校验器只接受这两种 qa_status。
- 冻结默认接受 camera_matched；冻结摘要按 qa_status/trigger 计数，训练配置可筛。
- 判定：黑白识别与期望局面**完全一致**（不含 LED 类），连续 ≥5 帧、≥1.0 s 且窗口内帧帧相同；不采用 kiosk「唯一多出的子恰好是下一手」的放宽规则。
- 不一致从不拍；8 s 稳定不一致时叠加差异并给出人工确认。断开/几何变化/撤回/结束/测试点亮/换模型/出错自动暂停，恢复要点。初始帧永远人工确认；同一局面只自动拍一次。
- 与每手基准点校正互斥（否则等于系统自动为几何闪灯），前后端都拦。stones2 模式允许。无已加载核对的当前模型时不可用（409 + 原因）。
- 默认手动确认；界面必须显示实时差异与稳定倒计时；推进方式可在会话中切换（逐帧记录）。

## 实现中偏离裁定之处

- **自动推进保存的不是「被判定的那一帧」**：指示灯模式下，拍照时要先把引导灯切到下一手，再抓新帧；被判定的帧亮的还是当前手的灯，存下来会让 LED 标签错位。改为：稳定判定后走正常拍照流程，**写入前对这张新帧再识别一次**，黑白棋子与 SGF 完全一致才发布，否则 409、不落盘。证据里记 `verified_saved_frame: true`。
- 诊断直接用 `InProcessAdapter`（viewer 模式）而非 `VisionService`，停止用 `stop()` + `is_alive` 判定是否确认退出；超时即保持 `stopping` 并继续拦截，不改 kiosk 生产的 `VisionService.stop`。
- 修通 imgsz：`StoneDetector` 以前不把 imgsz 传给 Ultralytics 后端（始终 960），模型登记里的「加载后核对输入尺寸」因此形同虚设。现在只对 ultralytics 生效，默认 960 不变，ONNX/RKNN 不动。
