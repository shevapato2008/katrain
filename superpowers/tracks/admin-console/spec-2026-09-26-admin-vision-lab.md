# 视觉实验室：采集、训练与诊断规格（2026-09-26）

## 目标与次序

在独立后台中支持 Mac 本机采集棋谱训练帧、测试机 YOLO11 训练与版本管理、Mac 拉取模型并观察识别流水线。按三个顺序垂直切片交付：**采集与数据集 → 训练与模型 → 本机部署与逐帧诊断**。每个切片先经 `claude-design` HTML 和 `ui-ux-pro-max` 优化，再做隔离 Fixture、同视口四图及独立 GPT-6 Astra max 视觉裁定；之后冻结契约、接真实服务并删除 Fixture。正式界面不得含模拟业务数据。

## 共同边界

- 使用现有独立 admin Bearer 身份。Mac 相机与采集目录只在 `KATRAIN_ADMIN_ENV=local` 且显式启用时可用，管理进程显式绑定 `127.0.0.1`；公开 Galaxy、kiosk 路由不承接后台令牌。测试机无相机时要诚实显示不可用。
- CameraHub 与 kiosk 在同一 Mac、同一 Unix 账号/HOME 下需要进程间设备租约；不同账号部署需另核实共享锁目录，不能冒称已协调。占用时返回冲突，不抢占或暗中重试；LED 串口也不能双进程共享。相机断开、未标定、磁盘失败、会话过期均有明确状态。相机预览通过带 Bearer 的请求读图，不把令牌塞进 `<img src>`。
- 测试机 SSH、上传数据、启动训练、下载模型、push、部署和真实数据库写入沿用逐次授权；本地设计/Fixture 不构成授权。真实服务未核实时不能展示“在线”或“上传成功”。
- 数据集、训练、模型 manifest 固定 ID、生成时间、输入哈希、类目、几何/标定来源和实际参数，用户能判明真伪与追溯。对未冻结草稿不训练，对校验失败文件不部署。有限大小、可取消、原子发布，失败保留旧可用版本。

## 切片 A：Mac 采集与数据集

1. 后台连接 Mac 本地摄像头，看到真实设备/LED/空盘标定状态、同一帧的原图和 warped。连接只由显式操作触发，退出可释放租约。
2. 导入本地 SGF，复用 `build_steps_from_sgf` 得到步数、落子与提子真值；操作者逐手摆放并确认后拍照。采样帧、SGF、几何、步数、时间和采集条件写入受控本机目录，重启可恢复；覆盖旧帧必须显式确认。
3. LED 引导模式只在一次性暂存目录中复用 `run_capture`（首版 `fiducial_mode="off"`），不得让它直接修改后台持久会话；无 LED 模式从新鲜相机帧直接采集，使用独立的 `stones2` 数据路径，不伪造红/绿 LED 类或“13 点 LED 标定通过”。无 LED 空盘几何可复用 `lock_geometry_from_frames`，并记录来源。采集须以相机序号及单调时间戳验证帧确实晚于操作员确认/LED 指引；超时返回的旧帧不得发布。训练集/验证集按 manifest 中的 SGF 顺序或整盘隔离，不按重拍后的文件名排序，也不随机拆连续帧。
4. 后台独立采集协调器串行处理采集、导谱、标定与断开：先验证模式、19×19 SGF、顺序、SGF 哈希与几何版本，成功取得并校验新帧后写唯一不可变图像及校验值，最后原子替换 manifest。显式重拍只替换目标条目，不删后续帧；失败时原 manifest 和已引用图片保持不变。坏 manifest 要报错，不得当作新会话。
   采集会话 ID 与 SGF 哈希分开；同一棋谱可以新建独立会话，采集不同模式或标定条件，单会话的模式/SGF/几何仍固定。
5. 样本检查显示实际叠框及异常；只有通过必需检查、类目一致、文件哈希完整时才能冻结不可变数据集版本。冻结必须检查每张图可读、标签有限且归一化、类别 ID 合法、训练/验证两侧非空和全部文件哈希；不能仅依赖旧 `validate_dataset()["valid"]`。上传测试机是独立确认操作，必须校验目标空间、逐文件 SHA-256、断点/失败状态，远端回执与本地 manifest 对照；未获远程授权时保持“待上传”。

## 切片 B：测试机训练与模型版本

1. 仅已冻结并校验的真实数据集版本可创建训练运行。展示队列/运行/失败/取消/完成、实际 epoch、日志、验证指标、产物校验和设备占用；版本列表指向不可变模型文件与训练参数。
2. 首版训练只显式选择单张 3090。现有 `led-safe-blur` 使用进程内 monkeypatch，多 GPU DDP 子进程未验证，不许仅因测试机有 2×3090 就标称双卡可用。若后续实测解决再启用双卡。训练不得抢占关键 KataGo 资源。
3. 复用 `train_model.py`、`prepare_dataset.py` 与自动标注，但训练 manifest 记录实际 `imgsz`、模型输入、类目顺序、增强、seed、GPU、代码版本、数据集哈希及 best.pt 哈希。不能将合成指标当真实运行指标。

## 切片 C：Mac 模型部署与逐帧诊断

1. 在后台选择一版校验通过的模型拉取到 Mac，兼容性检查通过后显式激活；模型版本与上一版保留，可一键回滚。下载中断或加载失败不得替换当前模型。
2. 对**同一帧、同一模型和几何版本**展示原图/标定叠图、warped、YOLO 原始模型框（模型 NMS 之后、业务去重之前）、业务去重后框、纠偏前棋盘、纠偏后棋盘与最终稳定棋盘。每格标明帧序号、时间、模型哈希、标定版本与来源，禁止七格各跑一次推理后冒称同一帧。
3. 复用现有 `StoneDetector`、棋盘状态/时序逻辑；在业务去重前导出不可变诊断快照，不改变现有识别结果。推理超时、相机断开、几何过期显示真实错误，隐私与资源预算有界。

## 验收与停点

- HTML/Fixture 同视口设计与实现对照，独立视觉评审代 Fan 做睡前设计裁定；Fan 明早保留复核权。
- 本地聚焦测试覆盖关键行为、最可能回归点；相机、LED、训练进程与文件操作以注入 fake 测失败/取消/恢复，硬件和测试机真实验收单独记录，不以 fake 结果替代。
- 🛑 每一次远程连接、上传/写入测试机、启动真实 GPU 训练、模型下载、push 与部署仍由 Fan 当场单独授权。无法取得授权不跳过，可继续不依赖外部状态的下一个本地设计/Fixture。
