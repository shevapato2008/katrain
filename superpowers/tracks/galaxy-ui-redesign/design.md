## 1. 三条不可协商的规则

这三条是本文的骨架，其余条款都是它们的展开。

### R1 · 棋盘页上，棋盘正上方不许有任何东西

模块名、返回按钮、状态提示、工具栏，一律进**右边栏顶部的模块牌**或右边栏内容区。

**为什么**：棋盘是正方形，边长 = `min(可用宽, 可用高)`。棋盘上方每占 1px，边长就少 1px，
面积按平方掉。右边栏的宽度本来就是固定支出，往里面放东西不额外收费。

**实测**（1440×900，真浏览器）：按本文布局棋盘边长 **828**；
按今天的布局（240 左边栏 + 500 右边栏 + 约 40px 顶部横条）棋盘边长 **700**。
边长 +18%，面积 **+40%**。

### R2 · 只有中间那一列可以被拉伸

顶栏 52、左边栏 240/216/64、右边栏 380/340/320 —— 全是定值。窗口变化时它们按 §7 的档位切换，
但在任一档位内都不随宽度连续变化。棋盘拿走全部余量。

**为什么**：两侧定宽，中间才有唯一确定的余量。否则窗口一动四条边同时动，没有一处能对齐。

### R3 · 能滚的永远是内容，不是页面

`.x-app`（应用根）`overflow:hidden`。滚动只发生在三个地方：右边栏内容区、内容页正文、左边栏导航区。
**任何一个可滚区域的父链上都必须有 `min-height:0`**，否则 flex 子项不会收缩，内容会溢出被祖先裁掉。

**为什么**：整页滚动会把顶栏和棋盘一起卷走。而 flex 里少一个 `min-height:0`，
表现不是"出现滚动条"，是"内容被静默裁掉"—— 今天 galaxy 就有两处这样的裁切（§11）。

**验收方式**：`overflow` 相关改动一律按用户级 CLAUDE.md 的「承重结构实测」在真浏览器目标视口下量，
**先把数据造到会溢出**再量。jsdom 对布局事实无权作证。

## 2. 壳层

```
┌──────────────────────────────────────────────────────────┐
│ 顶栏 52   智星盒 StellaBox              引擎状态 | 语言    │
├────────┬──────────────────────────────┬──────────────────┤
│ 左边栏  │                              │ 右边栏 340        │
│  216   │        棋盘 / 内容            │ ┌──────────────┐ │
│        │                              │ │ 模块牌 ← 标题 │ │
│ 导航    │                              │ ├──────────────┤ │
│ (可滚)  │      ← 唯一被拉伸的一列       │ │ 内容 (可滚)   │ │
│        │                              │ ├──────────────┤ │
│ 身份块  │                              │ │ 主行动        │ │
└────────┴──────────────────────────────┴──────────────────┘
```

### 2.1 顶栏（52px，全宽）

- **左**：品牌 `智星盒`（龙藏行楷 30px）+ `StellaBox`（10.5px，字距 .26em，玉亮色）
- **右**：全局状态（引擎就绪点 + 文字）、当前语言
- **不放**：模块名、返回按钮、任何页面级操作。那些属于模块牌。

### 2.2 左边栏

导航区可滚（`flex:1; min-height:0; overflow-y:auto`），身份块 `flex:none` 永远贴底。

八个一级入口，顺序固定：`首页 · 对局 · 研究 · 死活题 · 复盘 · 直播 · 棋谱库 · 教程`。

> **「首页」是新增项。** 今天 `/galaxy` 不对应任何导航项，只能点左上角 84×84 的 logo 进去
> （`GalaxySidebar.tsx:71-84`）；logo 移到顶栏之后必须补一个显式入口。

### 2.3 模块牌 —— 全站唯一的「我在哪 / 怎么回去」

一个组件，两个位置：

| 页型 | 位置 |
|---|---|
| 棋盘页 | 右边栏顶端 |
| 其余页面 | 内容区顶端 |

结构固定：`[返回（印）] [标题 + 一行副标题] [可选状态 chip]`，下方一条玉深色细线。

**永远不出现在棋盘上方。** 这是 R1 的直接推论，也是这个组件存在的理由。

## 3. 令牌

### 3.1 颜色 —— 全部取自 `src/theme.ts`（zenTheme），一个新色都不加

| 用途 | 值 | theme.ts |
|---|---|---|
| 底色 | `#0f0f0f` | `background.default` |
| 纸面（卡片 · 顶栏 · 边栏） | `#252525` | `background.paper` |
| 凹槽（棋盘区 · 轨道 · 输入） | `#1a1a1a` | 新命名，theme 已在画但没命名 |
| 玉 · 玉亮 · 玉深 | `#4a6b5c` / `#5d8270` / `#2f4539` | `primary.main/light/dark` |
| 胜 · 负 · 警示 · 提示 | `#30a06e` / `#e16b5c` / `#e89639` / `#5b9bd5` | `success/error/warning/info` |
| 字：主 · 次 · 失效 | `#f5f3f0` / `#b8b5b0` / `#4a4845` | `text.primary/secondary/disabled` |
| 细线 | `rgba(255,255,255,.06)` | ≈ `divider` |
| 棋盘木 · 线 | `#d9b26a` / `#42351f` | 棋盘组件内既有值 |

**玉色是唯一的强调色。** 红黄绿蓝是**语义色**，只用来说明状态，永远不拿来当强调、不拿来做主按钮以外的实底。

### 3.2 字体

| 角色 | 字体 | 用在哪 |
|---|---|---|
| 品牌 | **龙藏行楷** Long Cang | 只有 `智星盒` 三个字 |
| 全部界面文字 | **霞鹜文楷** LXGW WenKai | 其余一切 |
| 数字 | **霞鹜文楷等宽** LXGW WenKai Mono | 时钟、比分、净胜分、坐标、手数 —— 一切成列对齐的数字 |

三支均为 SIL OFL 1.1，允许内嵌、子集化与商业分发，需保留版权与许可声明。

**楷体在小字号下笔画软、没有强竖线，撑不住界面**，所以整套骨架反过来做硬：
直角、细线、严格对齐的网格。软的字写在硬的格子里 —— 这是这套界面的审美主张。

排版尺度（楷体需要比无衬线更多的行距）：

| 层级 | 字号 / 行高 | 字重 |
|---|---|---|
| 品牌 | 30 / 1 | — |
| 页标题 | 24 / 1.3 | 700 |
| 模块牌标题 | 18 / 1.3 | 700 |
| 卡片标题 | 15 / 1.4 | 700 |
| 正文 | 14.5 / 1.75 | 400 |
| 标签 | 11.5 / 1.5 | 400 |

**落地要点**：`theme.ts:34-46` 现在声明的是 `Manrope`，但仓库里既没有字体文件也没有任何地方加载它 ——
今天 galaxy 实际一直用系统字栈渲染。**所以「改版前」的截图并不是 `theme.ts` 声称的样子，它是系统无衬线。**

改这版必须同时做三件事，缺一不可：
1. 字体放进 **`src/galaxy/assets/fonts/`**（由 Vite 打包、只进引用它的 chunk）
2. `@font-face` 写在 **galaxy 作用域的样式文件**里
3. 改 `theme.ts` 的 `fontFamily`

> **不要放 `public/`，不要写进 `src/styles/theme.css`、`global.css`、`index.css`。**
> `vite.config.ts` 只切 `outDir`，没有覆盖 `publicDir` —— `public/` 会被原样拷进**两个** dist，
> 字体会跟着进 SBC kiosk 镜像；而那三个 css 是 `main.tsx:3-5` 无条件导入的，两套构建都吃。
> kiosk 用的是自己的 `src/kiosk/theme.ts`（SANS/SERIF/MONO），它渲染不到 WenKai，白背这几 MB。

> **kiosk 不受影响**（复核过）：`KioskApp.tsx:125` 用 `kioskTheme` 包裹，MUI 的嵌套 `ThemeProvider`
> 传对象时是**整体替换**父主题，不是合并；`zenTheme` 只被 `AppRouter.tsx` 与 `ZenModeApp.tsx` 引用。
> 所以改 `zenTheme.typography.fontFamily` 到不了 kiosk 正文。
> 「kiosk 要不要也换霞鹜文楷」是独立问题，不阻塞这里。

### ⚠️ 正文字体的未决问题：固定子集在生产里不成立

设计稿里 WenKai 只有 **170KB**，因为稿子的文字是写死的，可以按实际用字做一次性子集。
**生产不是这样**：界面要出 11 种语言，还要渲染用户名、赛事名、棋手名这些运行时才知道的字符串。
**一个冻结的字符集必然出豆腐块** —— kiosk 已经为缺字形付过一次学费（表现是「乱码」）。

生产必须二选一，**这一条需要产品拍板**：

| 方案 | 代价 | 风险 |
|---|---|---|
| **A. `unicode-range` 分片**（Google Fonts 的 CJK 做法，切成 ~100 片按需加载） | 首屏只拉命中的几片；构建要加分片步骤 | 分片边界处会有短暂 FOUT |
| **B. WenKai 只用于品牌与标题，正文留系统字栈** | 几乎零成本 | 「一律使用霞鹜文楷」没有完全兑现，需明确告知 |

**在拍板之前不要偷偷退回系统字栈然后声称做完了。** 若走 B，必须在本文与设计稿里写明正文没有换。

#### 2026-08-06 实测：A 可行，但**分片必须按频次切**

用 `LXGWWenKai-Regular.ttf` 真跑了一遍子集化（全部为 woff2、单字重）：

复现：`uv run --with fonttools --with brotli python
superpowers/tracks/galaxy-ui-redesign/measure_font_budget.py <LXGWWenKai-Regular.ttf>`

| 子集 | 码位 | 体积 |
|---|---|---|
| 中文界面实际用到的字 | 737 | **318.8 KB** ←首屏地板 |
| 10 个启用语种的界面用字合计 | 1835 | 807.9 KB |
| 上面 + CJK 前 3500 字 | 5057 | 2375.0 KB |
| 整套字面 | 46490 | **24534.5 KB** |

边际成本约 **0.44 KB/字**。三条结论：

1. **「按界面用字做一次性子集」是最差解**：单字重就要 808 KB，**而且照样在用户名上出豆腐块**。
   贵和不可靠同时占了。谁要这么实现，先看这张表。
2. **分片顺序是成败关键，不是实现细节。** 同样切 40 片、同样覆盖「界面用字 + 3500 常用汉字」、
   同样的切片方式，**只差排序**：

   | 切法 | 中文页命中片数 | 首屏拉取 |
   |---|---|---|
   | 按码位序（最容易写出来的那种） | **33 / 40** | 1951.2 KB |
   | 按频次序（常用字排前面） | **6 / 40** | **324.6 KB** |

   常用汉字在码位上是散的，按码位切几乎每片都命中，分片白做、还多了几十个请求。
   **按频次切才能落到 324.6 KB——离 318.8 KB 的理论地板只差 2%。**
3. 所以 **A 推荐**：首屏约 325 KB，`font-display:swap` 下不挡渲染，分片各自独立缓存，
   且任意运行时文字都不会缺字形，字面兑现「其余一律霞鹜文楷」。
   需要一份汉字频次表来定分片顺序（通用规范汉字表一级字表 3500 字即可）。

#### 2026-08-06 落地实测：分片真的按需加载，但账要记对

S0 把 A 实现出来了（`scripts/build_wenkai_chunks.py`，234 片 + 品牌 + 数字 = 238 文件 / **49 MB**）。
真浏览器实测：

- `document.fonts` 注册 236 个 face，**单页只下载 12 个** —— unicode-range 按需加载成立
- `document.fonts.check('16px "LXGW WenKai"')` = true；拉丁串 48px 宽度
  WenKai **656.9** ≠ 系统 sans **616.4** ≠ Long Cang **541.3** —— 字**真的在渲染**，
  不是「声明了但静默退回系统字栈」
- kiosk dist **22892 KB vs 基线 22896 KB**，`wenkai-*` 命中 0 个 —— 隔离成立

**⚠️ 上面那张表的 325 KB 是「单字重」的数，别当成首屏总量。**
页面同时要 400（正文）与 500（标题），实测首屏 **12 个请求 / 约 511 KB**。

**两件仍需产品拍板的**：
1. **49 MB 进不进仓库。** 这是自托管全字面的固有成本。要压的话把覆盖面收窄即可 ——
   因为兜底是**真的 CJK 字栈**，分片没覆盖到的字会落到 PingFang/系统楷渲染，
   **是换个字形，不是豆腐块**。所以覆盖面是「质量 vs 体积」的取舍，不是「对 vs 错」。
2. **首屏 511 KB 值不值。** 可行性已经不是问题了。

> 子集化命令（供品牌与数字这两支使用，它们的字符集确实是封闭的）：
> `pyftsubset LongCang.ttf --text='智星盒' --flavor=woff2`
> `pyftsubset LXGWWenKaiMono-Regular.ttf --text='0123456789:.+-/%' --flavor=woff2`
> 全量 CJK 单支 25MB，**不要整份分发**。

### 3.3 间距与圆角

- 间距基数 8。卡片内边距 20/22，卡片间距 14，页面内边距 30/36（xl 34/48，md 24/26）。
- 圆角：卡片 14 · 控件 8 · 返回印 5。
  今天有**三个圆角来源**（`shape.borderRadius:8`、`MuiButton` 硬编码 `'8px'`、`MuiDialog` `'12px'`），
  收敛成这三档。

## 4. 按钮与控件

### 4.1 三个高度，没有第四个

| 类 | 高 | 用在哪 | 规则 |
|---|---|---|---|
| **主行动** | 48 | 开始对局 · 下一题 · 保存 | 玉色实底。**每屏至多一个**，位置固定在右边栏底部或内容区末尾 |
| **次行动** | 40 | 停一手 · 悔棋 · 数子 · 打开 · 复盘 | 描边。右边栏内用两列等宽网格，同网格内宽度必须一致 |
| **危险** | 40 | 认输 · 清空 | 红色描边，**永远不用实底** —— 实底只属于主行动 |
| **安静** | 40 | 退出对局 · 全部 | 无边框。用于「离开」而不是「操作」 |
| **图标** | 40×40 | 上一手 · 下一手 · 首尾 | 正方，与次行动同高。**必须写 `aria-label`** |
| **返回（印）** | 40×40 | 每个有上级的页面 | 方形 5px 圆角 + 玉色细边。**全站只有这一种**，且只出现在模块牌左端 |
| **小** | 32 | 列表行内 · 分段控件 | 只在卡片或列表行内部出现，不做屏级动作 |

**开关瓦片与动作按钮共用一套度量**：40 高 · 8 间距 · 两列。
右边栏里「一格」永远是同一个大小，不管格子里装的是按钮还是开关。

### 4.2 词表 —— 同一个动作，一种写法一个图标

| 动作 | 写法 | 图标 |
|---|---|---|
| 放弃一手 | **停一手** | 斜杠圆 |
| 退回一手 | **悔棋** | 回转箭头 |
| 终局点目 | **数子** | 四格 |
| 认输 | **认输** | 旗 |
| 离开本局 | **退出对局** | 出门箭头 |
| 回上一级 | **返回**（仅图标，`aria-label="返回"`） | 左箭头 |
| 清空 | **清空**（不是「清除」） | — |
| 取消 / 确定 | **取消** / **确定** | — |

**一个动作只能有一个 i18n 键。** 今天「取消」有五个键（`cancel`、`research:cancel`、
`report:cancel`、`auth:cancel_btn`、`common:cancel`）外加两处写死；「清空/清除」有两个中文词。
新增字符串走 `katrain-i18n-expert` skill，11 种语言一次补齐（`cn≠tw`、`jp≠ko`，占位符原样保留）。

### 4.3 无障碍下限

- 可点击的东西必须是 `<button>` 或 `<a>`。**不要用 `<Box onClick>` 当按钮。**
- 图标按钮必须有 `aria-label`。现成的好样板：`components/live/PlaybackBar.tsx:148-182`，
  那是今天整个产品里唯一一处每个按钮都写了 `aria-label` 的控件组。
- 可禁用的控件外面套 `<Tooltip>` 时必须包一层 `<span>`，否则禁用时提示语消失 ——
  最需要解释「为什么点不了」的时候恰好没有提示。
- 触摸目标统一 **44**。今天有 44（`AiLadderStatusCard.tsx:282`）和 48（`PlaybackBar.tsx:31`）两套。

## 5. 棋盘页布局

右边栏自上而下顺序**固定**，四个棋盘页都用这个顺序，只换中间的内容块：

```
模块牌  →  本页主体信息  →  显示开关  →  行动  →  主行动 / 离开
```

| 页 | 「本页主体信息」是什么 |
|---|---|
| 对局中 | 双方与用时 · 本局阶梯（对手档位 / 净胜分 / 是否计入） |
| 研究 | 胜率与目数差 · 候选着法三手 · 摆子工具 |
| 死活题 | 题目要求 · 判定反馈 · 本单元进度 |
| 复盘 | 本局结果 · 当前手讲评 · 失误清单 |

**能滚的只有中段**，模块牌和底部动作始终可见。

棋盘容器：`display:grid; place-items:center; padding:10px; background:凹槽色`。
棋盘组件自身不改 —— `components/Board.tsx:95-102` 已经是
`ResizeObserver` 量 `Math.min(width,height)-8`，正是「撑满中间那一列」要的算法。
**要动的是喂给它多大的框，不是它自己。**

## 6. 状态语义

**状态必须诚实。加载、错误、空态、重试不得伪装成成功。**

| 状态 | 表达方式 |
|---|---|
| 加载 | 按钮内换 `CircularProgress`，文案不变，按钮 `disabled`。**只有这一种写法** |
| 错误 | 说清发生了什么 + 怎么办。不道歉，不含糊。面向玩家，不漏运维文案 |
| 空 | 空屏是行动邀请，不是"暂无数据" |
| 禁用 | MUI 内置处理 + 必要时一行说明为什么。**不要用 `opacity:0.3` 自制** |
| 不计入 | **整屏状态，不是一行提示**：相关数字变灰、最近五局变灰、卡片描边、主按钮降级 |

最后一条尤其重要：`_CERTIFIED_RUNGS` 目前是空集，41 档全部 `provisional`，
**今天每一局都记 `counted=0`**。「不计入」不是边缘情况，它现在是常态。

## 7. 响应式

**收的顺序：左边栏 → 右边栏 → 换层。永远不先动棋盘。**

断点用 **MUI 自带的那一套**，一个自定义值都不加。理由：galaxy 今天仅有的一处响应式判断
（`TsumegoProblemPage.tsx:45` 的 `breakpoints.down('md')`）就在 900，
把它从页面局部特例提升成全站规则，比另起一套数字更容易落地。

| 档 | 宽度 | 左边栏 | 右边栏 | 棋盘边长（实测） |
|---|---|---|---|---|
| **宽** xl | ≥1536 | 240 | 380 | 受高度约束 |
| **标准** lg | 1200–1535 | 216 | 340 | 受高度约束（1440×900 → **828**） |
| **窄** md | 900–1199 | 64 图标 | 320 | 受宽度约束（1024×768 → **620**；900×700 → **496**） |
| **竖屏** | <900 | 底部标签栏 | 落到棋盘下方 | 满宽（430 → **418**） |

规则细节：

- **左边栏先让位**：它是路标，不是内容。收成 64 的图标条，标签隐藏，`title` 保留。
- **右边栏后让位**：它装的是这一局正在发生的事，比导航更该留着。
- **<900 是全站唯一一次「列变层」**：棋盘按满宽正方吃掉上半屏，右边栏内容落到下方成为可滚的一层，
  左边栏落到底部成标签栏。**模块牌仍在「右边栏」的顶端 —— 它换了位置，没换归属。**
- **内容页（无棋盘）的两列在 <1200 就合成一列**，比棋盘页早一档。
- **禁止「宽度不够就整块消失且没有替代入口」**。今天有两处这样做：
  `LivePage.tsx:111` 的赛事列表在 <900 消失，`HvHLobbyPage.tsx:310` 的好友面板在 <1200 消失。

实现方式建议用 **容器查询**（`container-type:inline-size` 挂在应用根上），
断点读应用自身宽度而不是 `window`。这样组件在任何嵌套层级下都按自己真实拿到的宽度重排。
