# 星阵 8D 与 `rank_8d@4` 固定筛选实验设计

日期：2026-07-24

## 目标

验证用户提出的假设：星阵 8D 的棋力可能接近修复后的 HumanSL `rank_8d@4`。本轮只取得 5 个
有效结果并报告，不做二分、自动确认或产品档选择。

## 固定配置

- 我方：`rank_8d@4`，b18 主模型、humanv0、canonical PIKL HumanSL 搜索配方。
- 对手：星阵“8段/星美鹿”，真实 API wire level `2800`。该映射同时存在于
  `GOLAXY_AI_LEVELS` 和核心 ladder 表，并由跨表一致性测试锁定；不得使用展示 Elo 替代。
- 棋盘：19 路，中国规则，贴 7.5 目，无让子。
- 有效局颜色：B/W/B/W/B。
- 目标：恰好 5 个有效结果；完成后停止。

## 额度与失败策略

- 使用独立 quota ID 和独立 append-only JSONL 账本，不与星阵 9D 实验合并。
- 最多预留 9 次可能计费尝试；每次远端调用前先落盘 reservation。
- 不可判定局不进 5 局分母，并以原颜色补局。
- token、7002、429、断连或无法证明配置身份时立即停止，零自动重试。
- 只访问本机 KataGo HTTP `http://127.0.0.1:8000`；星阵请求使用既有客户端。

## 实现方式

扩展现有 fixed-screen runner，使单档实验参数化，但保持 fail-closed：棋手字符串必须被既有
HumanSL parser 接受；星阵 level 必须由 `GOLAXY_AI_LEVELS` 中期望名称“8段”解析为 `2800`；目标局数、
颜色、quota 上限和输出目录在预声明中固定。旧的星阵 9D `@5/@6` 路径及测试必须保持不变。

## 验证与报告

- 单元测试覆盖参数解析、8D/2800 绑定、五局调度、不可判定原色补局、额度上限和旧模式回归。
- 启动前完成只访问本地 KataGo 的语义/模型 attestation，不消耗星阵额度。
- 运行后核对 reservation/result 一一对应、胜负与颜色，并记录账本 SHA-256。
- 结果更新到同目录 `EXPERIMENTS.md`，明确 5 局只是小样本筛选。
