## 4. 解析、归并与五语言规则

### 4.1 SGF 与棋局

- 原始字节与元信息归档；解析后的 UTF-8 SGF、原始哈希、规范化哈希分开记录。
- 清理派生展示字段，保留 PB/PW、BR/WR、EV/GN、DT、RE、RO、SO 等原值和依据。不把五语言翻译覆盖回原始 SGF。
- 列表接口的比赛名、日期、结果可能比下载 SGF 更完整，须一并保存。优先采用有效 SGF 字段；缺失时由对应来源元信息补充派生字段并标明依据，冲突不静默覆盖。重复 GN 仍按现有经审核规则处理，不能把 `GNUGo3.8` 程序名当赛事名。
- `吴清源九段`、`吴清源9p` 等经规则和上下文确认后关联同一棋手；当时段位仍随该盘保存，前端分别展示。
- 修复须有确定性依据；不让模型猜补落子、结果、日期或损坏坐标。
- 不修改已有棋局的 SGF、主键和深度分析绑定。来源上同 ID 内容变化进入修订待办，不静默覆盖。
- 精确规范 SGF 相同可复用现有棋局并追加来源；只有主线相同、元信息不同的情况进入重复候选。

### 4.2 棋手名称

1. 先匹配无歧义的已有棋手 ID、别名和当前合格五语名称；中文可用原名，不反复联网核名。
2. 新身份先保留中文默认名；没有可靠中文对应时保留清洗后的原名并记录方法，不伪造中文身份。
3. 维基百科同一人物的目标语言页面存在时，直接用页面标题中的姓名，去掉消歧后缀；同时保存页面链接及人物关联依据。
4. 缺少页面时参考棋院、棋协等资料；仍无对应译名则直接翻译或规范转写，按 `generated_first_pass` 记录，不冒充权威惯用名。
5. 同名、身份冲突、只有占位词、文字损坏未能可靠清理的记录进入隔离队列，不阻塞其他棋局。

### 4.3 赛事名称

- 复用赛事类型 ID，例如“应氏杯”；同届比赛复用届次 ID，轮次不新增赛事实体。
- 年份、届数、轮次、赞助商等尽量拆解；没有明确赛事类型的说明可以作为原文标题翻译，不强行归到已知赛事。
- 已知赛事基础名和已验证模板优先复用；新增冠名和说明直接翻译，保留数字、年份及轮次语义。
- 检索和翻译按独立棋手/赛事或原文标题进行，不逐盘重复调用。

### 4.4 审核与资料存储

- 已合格名称复用和确定性解析不再逐条调用模型审核。
- 对新生成的五语名称做一次结构校验和一次独立审核调用；有明确问题才重试或隔离，不无限循环核查。
- 生产者与审核者使用不同调用身份和请求 ID；同模型的两个独立调用可以区分角色，但不声称是人工审核。
- 页面 URL、语言、页面标题、获取时间、内容摘要/哈希、采用名称、翻译方法、提供方/模型/提示词版本、审核结论均持久化。网络不可达记录为不可达，不写成“没有惯用译名”。
- 复用现有名称表、研究证据表、批次表；为自动增量新增明确的资格规则，不能伪造旧 Codex agent 的签名或把 `status=verified` 当成唯一放行条件。

## 5. 服务器翻译服务可行性

### 5.1 Codex 订阅并非技术上不能用，但不作为推荐运行依赖

OpenAI 官方文档支持 `codex exec` 用于脚本和定时工作，也说明远程登录及 ChatGPT 管理认证的高级自动化方式；同时推荐自动化默认使用 API key。订阅认证不能直接当普通模型 API key 使用。[非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)、[认证](https://learn.chatgpt.com/docs/auth)。

这不等于确认当前账号、工作区及此类长期翻译负载均已获准。若选订阅方案，还要核对适用条款、仓库/运行环境限制、认证续期与额度；CLI 缓存令牌只交给官方 CLI，不转换成自建 HTTP 接口。**本次没有复制任何账号凭据，也没有在服务器登录 Codex。**

### 5.2 三个选择

| 方案 | 可行性与代价 | 本次建议 |
| --- | --- | --- |
| 千问 API + 维基/棋院查询 | 仓库已有 DashScope 调用基础；支持联网搜索及结构化输出，但具体地域、模型、余额、权限待测试 | **推荐首选，只实现一种生产提供方** |
| DeepSeek API + 查询 | 官方已有 JSON 输出和独立 Search/Fetch 文档；仍需验证本账号可用性、语种效果和费用 | 首选不可用或样本明显更优时选它，不预先并建第二套服务 |
| Codex CLI + 订阅认证 | 有官方远程、非交互机制；依赖账号认证、计划额度和运行约束 | 可作为人工维护/疑难核对方式；若用户坚持，再单独验证是否适合作为自动服务 |

千问依据：[联网搜索](https://help.aliyun.com/zh/model-studio/web-search)、[结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。DeepSeek 依据：[JSON 输出](https://api-docs.deepseek.com/zh-cn/guides/json_mode/)、[网页搜索与抓取](https://api-docs.deepseek.com/zh-cn/guides/search/)。文档查阅日期为 2026-10-19；尚未做付费调用或翻译提供方的服务器连通性试验。Context7/OpenAI Docs MCP 本轮访问失败，使用上述官方网页核对。

## 6. 数据发布契约

### 6.1 最小持久状态

建议新增两张小表，复用现有 cron 运行日志，不再建设另一套调度平台：

| 表 | 责任 |
| --- | --- |
| `kifu_ingest_batches` | 批次 UUID、发现模式/游标、包哈希、状态、两环境回执、计数与时间 |
| `kifu_ingest_items` | 唯一 `(source_key, external_id)`、原始/规范哈希、暂存文件引用、处理阶段、失败原因、重试时间、两库目标映射 |

已有棋谱仍存 `kifu_albums`；棋手/赛事名称仍存现有 catalog 名称表；多个来源仍用关联表表达。运行包保存标准化记录、名称及证据的逻辑引用，不能直接复制测试库整数主键去正式库。

### 6.2 原子发布与旧翻译保护

当前部分原文赛事首译绑定**该原文的完整出现范围**。新增一盘相同原文的棋，即使先隐藏，也可能令旧证据的范围不再匹配，导致历史卡片丢译名。

因此：

- 新谱在库外暂存，完成网络处理后才进入短数据库事务。
- 同一事务发布棋局、来源、身份关联、五语名称和受影响原文范围的新版本；旧证据保留。
- 续签仅限原文、译名和旧成员上下文没有变化的情形；变动则重新处理，不能放宽所有历史校验。
- 提交前在事务内验证受影响历史卡片的五语读取资格不下降；该校验失败整批回滚，不得先提交再修复。
- 网络查询和模型调用不占用数据库事务或写锁。

### 6.3 测试到正式

- 测试成功是正式同步的前置条件；通过后自动同步的默认方案待本次讨论确认。
- 发布包不可变，同一 `batch_uuid + payload_sha256` 重放不新增数据；同 UUID 不同哈希拒绝。
- 目标端按来源 ID/精确内容、已确认身份及别名解析目标主键。冲突不强行覆盖；保持原有公开谱和已核实译名。
- 推荐独立受限 SSH 发布账号，固定接收命令读入包，只有必要表权限；测试 cron 不持有正式超级用户密码或 MacBook 的通用 SSH 私钥。
- 正式失败只重试同步阶段，保留已验证测试结果；部分批次故障不停止其他可独立发布的棋局。
- 区分 `test_published/test_verified`、`prod_published/prod_synced`：published 表示数据库已提交，verified/synced 还要求实际 API 验证通过。API 超时留在待验证阶段，只重试读取，不重复导入；此时正式验证未过不能报告“双库已完成”。
- 提交后发现真实数据错误时，先停止该批继续推进，再依据变更日志做有前像/后像条件的补偿事务；不能声称原事务仍可回滚，也不能因一次网络超时撤销有效数据。若已有并发修改，隔离并报告冲突，不强行覆盖。
- 回滚针对本批插入/变更与前像，检查并发变化，不整库恢复或覆盖后续正常业务。

## 7. 调度、重试与来源分页

- 复用 `katrain-cron` 的调度、运行日志、暂停及手动运行能力；每小时一次，启动后补查一次，最多一个任务实例。
- 跨实例使用测试数据库 advisory lock；生产接收端另有批次事务锁及唯一约束。暂停增量不影响直播、报告、翻译等既有任务。
- 不复用原爬虫的 `progress.json`，不修改历史全量爬虫的恢复行为。
- 保留现有抓谱请求间隔：单谱 2–5 秒、翻页 5–10 秒；连续错误有次数、时间上限，失败下轮重试。
- **先核对来源排序。** 不以遇到第一条旧棋谱、较小 ID、旧比赛日期作为停止条件。
