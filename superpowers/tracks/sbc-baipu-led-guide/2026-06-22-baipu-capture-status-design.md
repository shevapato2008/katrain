# 摆谱右侧采集状态设计

**日期：** 2026-06-22
**状态：** 已实施
**Track：** `sbc-baipu-led-guide`

## 1. 目标

操作者在实体棋盘摆谱时，不应依赖顶部的小号统计文字判断进度。右侧操作区需要持续显示当前待摆手数，并在拍摄写盘成功后显示后端实际保存的图片文件名。

## 2. 状态来源

- “当前待摆”直接由会话状态 `k` 和 `steps.length` 派生，不创建重复计数器。
- “最近保存”只使用 `POST /api/v1/baipu/capture` 成功响应中的 `result.path`，取路径 basename 展示。
- 前端不得根据手数或本地帧计数推测文件名。初始空盘帧、重拍和历史 manifest 都可能让手数与文件序号不相等。

## 3. 交互

- 右侧下一手色片增加“当前待摆：第 N 手”。
- 主操作按钮上方增加“采集记录”信息块。
- 尚无成功结果时显示“最近保存：尚无”。
- 初始自动采集成功后显示其真实文件名；每次确认落子并写盘成功后更新为该次响应的真实文件名。
- 采集失败、capture disabled 或悔棋不清除、不覆盖最后一次成功记录。
- 文件名使用等宽字体，便于操作者核对连续编号。

## 4. 错误和兼容性

- 后端未返回 `path` 时，成功流程保持现状，但不更新最近文件名。
- 路径提取同时兼容 `/` 和 `\\` 分隔符。
- 不新增后端接口，不读取 manifest，不改变现有采集和推进时序。

## 5. 验证

Playwright 必须验证：初始成功响应展示真实文件名；第 N 手确认后展示该响应的文件名并推进至 N+1；显示值来自后端路径而非手数推算；失败时保留最后一次成功记录。TypeScript 构建、定向 ESLint 和 kiosk 2D 构建必须通过。
