# 影子重复框去重（shadow-dedup）设计

2026-09-23。起因：RK3562 白天侧光局里「检测到疑似落子」弹了 19 次，其中 H5 一个点 16 次、D7 2 次，
而那两个点上什么都没有（Fan 现场确认）。证据全部在
[`../evidence-2026-09-23-daylight-game/`](../evidence-2026-09-23-daylight-game/)。

## 1. 根因（已复现）

光从棋盘左侧来，每颗子右边拖一道深色影子。部署模型 `go4_s.rknn` 会把「棋子右半 + 影子」**再框一次**，
框心比真子偏出约半格（实测中心距 0.56–0.75 格）。

`stone_detector.dedup_detections` 现行判据是「两框中心距 < 较小框平均边长 × 0.5」，约 0.47–0.55 格。
影子框刚好落在这个半径外，于是活了下来，走两条路变成假子：

1. **置信度 ≥ 0.40（H5，0.41–0.45）**：视差校正把它的中心推到 G5/H5 分界线（第 6.5 列）附近。
   越过 6.5 的那一帧，它直接落进空着的 H5（`board_state._assign_occupancy_aware` 取整）。
   此后每帧它离 H5 都是 0.61–0.63 格，小于 `STICKY_RADIUS = 0.65`，被粘滞分配一直吸在 H5 ——
   **自我维持**。注意不是「溢出到邻点」：低于 `SPILL_MIN_CONFIDENCE = 0.6` 的撞点框本来就会被丢弃。
2. **置信度 < 0.40（D7，0.32）**：进不了盘面，但 `cell_top` 把它取整到空着的 D7，
   `AmbiguousPromoter` 连续 12 帧看到它，就升级成疑似落子卡片。

两条路都在**去重之后**才发生，所以在去重处拦住影子框，两条一起断。

复现（线上日志坐标 + 真实框尺寸 + 线上视差参数 `nadir=(19.612, 9.0)`，`k=0.989689`）：
- 帧 1：影子框原始 (13.69, 6.364) → 校正 (13.642, 6.5006) → **H5 = 黑**；
- 帧 2：原始 (13.71, 6.33) → 校正 (13.662, 6.467)，本应丢弃，但上一帧 H5 有子 → **粘滞保持 H5 = 黑**。

## 2. 判据：按重叠比例（Fan 提出）

**IoMin = 两框交叠面积 ÷ 较小框面积。** 不用 IoU：同一对 H5 框 IoMin 0.37–0.44，IoU 只有 0.2 左右。

用**棋谱真值**给每个框贴标签后实测（12 帧同一局面；真值 = 从日志重放的 111 手 + 3 次提子，
加上被判「不该黑走」而没进棋谱、但实物在盘上的 O17；与识别结果只差一帧 C14 漏识）：

| | 数量 | IoMin |
|---|---|---|
| 真子框 vs 真子框（有重叠的） | 2762 对 | **最高 0.233**（J2+J3，框约 1.1 格宽，框边互压） |
| 会成假子的影子框 vs 它贴着的真子框 | C9 / D8 / 线上 H5 | **0.326–0.44** |

最初按「中心距 < 0.8 格 = 重复」分组得到的「重复框最少 0.30」有循环论证之嫌（IoMin 与中心距强相关），
已用真值重算，结论不变。

**定值：`DEDUP_OVERLAP_MIN = 0.27`**，落在 0.233 与 0.326 之间。余量两侧各只有 0.04 / 0.06，且只来自一局
一种光照 —— 落地前必须过 §5 的标注集验证闸。

## 3. 规则

对**两个棋子类框**（黑/白之间也算，沿用现有「一颗子被读成两种颜色」的分组）：

```
重复  ⇔  中心距 < 0.5 × 较小边长                      （旧规则，原样保留）
      或 ( IoMin ≥ DEDUP_OVERLAP_MIN
           且 较大边长 ≤ DEDUP_MAX_SIDE_RATIO × 较小边长 )  （新增）
```

- 保留置信度高的那个（现行贪心顺序不变）。实测 103 个重复对里只有 1 对是「更偏离交叉点的那个框置信度更高」，且两者都不算偏（0.33 对 0.22）。
- **判定只加不减，结果不保证单调**：判定条件是旧规则的超集，但扫描是贪心的 —— 旧规则里被 B 吞掉的 C，在 B 自己被新条款并进 A 之后会活下来（例：三个 50 px 框排在 x = 100 / 130 / 150、置信度递减，旧规则留 100 与 130，新规则留 100 与 150）。12 帧实测复活 0 个；标注集闸把「复活、又不在任何标注上」的框计为不通过。
- **LED 类框不用新规则**：两盏相邻的灯同时亮时框会互压，吞掉一盏会让熄灯验证出错。LED 仍按旧规则、只在同类内去重。
- **`DEDUP_MAX_SIDE_RATIO = 2.0`**：IoMin 以小框为分母，一只手被读成一个大框（比棋子大好几倍）时 IoMin 对它下面的每颗子都是 1。限定大小相近才合并。实测影子对边长比最高 1.58（p95 1.44），真子相邻对最高 1.21。
- 没有框（bbox 全 0）或平均边长 ≤ 0 的检测，两条规则都不参与（沿用）。面积为 0 但平均边长 > 0 的框（如高为 0）照旧参与中心距规则，只是不参与新条款（没有面积就没有重叠比例）。

## 4. 性能约束

`dedup_detections` 用均匀网格只查 3×3 邻格（RK3562 上 O(k²) 版在 213 子时要 86 ms）。
新条款的「可能相撞」半径是两框能相交的距离，最大可达最大框的宽/高，所以网格边长要从
`0.5 × 最大平均边长` 改为 `max(0.5 × 最大平均边长, 所有框的最大宽/高 + 2 × 框心偏离 bbox 中点的最大值)`，否则会漏查。
四个后端（rknn / onnx / ultralytics / split_decode）输出的框心都是 bbox 中点，线上偏离量恒为 0；
加上它，是为了让「与 O(k²) 参考实现逐对象一致」对任何 `Detection` 都成立（这个数据类不强制框心在中点，测试里的框是手搓的）。
差分测试（对比 O(k²) 参考实现）要随规则同步更新，它是这个优化正确性的唯一闸。

代价（本机实测，板上约慢 11 倍）：真实帧（122 框）0.15 → 0.45 ms，折算到板上中位约多 3 ms，对照整帧中位 504 ms。
一个异常大的框会把整批的格子撑大（旧的 `0.5 × 最大平均边长` 本来就有这个性质）：270 框里混一个 160 px 的框，0.57 → 2.56 ms；
混一个 1056×20 的框，2.46 → 12.4 ms。检测只在画面静止的帧上跑（手在盘上移动的帧进不了检测），
12 帧里最大的棋子框 82 px，所以不为它另建索引；上板复测时看去重耗时（`detect − pre − npu − post`，
不是 `post` —— 后者是后端自己的解码，不含去重）。

## 5. 落地前的验证闸（标注集）

home-ubuntu `data/go4_split`：209 张 1056² 校正图，YOLO 标签由棋谱自动推出（`black/white/led_red/led_green`）。
板上用部署模型导出去重前的全部框；本机用**分支上的 `dedup_detections`** 与**基线提交里的同一个函数**分别去重
（不用脚本自带的规则副本 —— 那样量的是副本，不是要上线的代码），按标签贴真值：

- 匹配：标签与框一对一、不分颜色（黑白本来就在同一个去重组，颜色读错不是去重的事），距离近的先配，半径 = 0.5 × 标签边长；
- 有效：图数 = 209，且旧规则下的召回 ≥ 0.95。否则判 `INVALID` —— 没识别出子的数据，证明不了「没多吞子」；
- 通过：
  1. 真子框 vs 真子框 IoMin 最大值 **≤ 0.25**；
  2. 没有一个标注是旧规则看得到、新规则看不到的（逐个标注比，不比总数，免得一丢一补相互抵消）；
  3. 没有「新规则保留、旧规则丢掉、又不在任何标注上」的框（见 §3 的复活）。

不是 PASS：停，报数给 Fan，不合 develop、不上板。

这道闸只能证明**不多吞真子**，证明不了 0.27 在别的光照下还拦得住影子（标注集里未必有侧光影子）。
后者要靠上板的侧光局。

## 6. 不做（本轮）

- 弹窗改造（不遮棋盘、棋盘上标出疑似点、「不是落子」按钮 + 用户否认样本的 ZNCC 比对）：另起切片，先出 mockup 给 Fan 确认。
- 参照帧的三处缺口（按格拍参照、否决上限、低于门槛路径）：去重落地后看残余弹窗再定。
- A15 那类孤立假框（不贴任何真子，IoMin = 0）：去重管不到，本局没进过盘面（置信度 0.22–0.28）。
- 影子框置信度反超真子、且校正后越过分界线时，保留的是影子框，子会被「挪」到邻点：H5 的第 1 帧位置（校正后 6.5006 列）就会这样，第 2 帧（6.467 列）不会。实测从未发生：103 个重复对里只有 1 对是「更偏离交叉点的那个框分更高」，且两个框都不算偏（0.33 格对 0.22 格）；会成假子的影子框（偏 0.56–0.75 格）没有一个比它的子分高。记为已知限制，Task 3 用 strict xfail 钉住。
