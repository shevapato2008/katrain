## 1. 根因（已复现）

光从棋盘左侧来，每颗子右边拖一道深色影子。部署模型 `go4_s.rknn` 会把「棋子右半 + 影子」**再框一次**，
框心比真子偏出约半格（实测中心距 0.56–0.75 格）。

`stone_detector.dedup_detections` 现行判据是「两框中心距 < 较小框平均边长 × 0.5」，约 0.47–0.55 格。
影子框刚好落在这个半径外，于是活了下来，走两条路变成假子：

1. **置信度 ≥ 0.40（H5，0.41–0.45）**：视差校正把它的中心推到 G5/H5 分界线（第 6.5 列）附近。
   越过 6.5 的那一帧，它直接落进空着的 H5（`board_state._assign_occupancy_aware` 取整）。
   此后每帧它离 H5 都是 0.61–0.63 格，小于 `STICKY_RADIUS = 0.65`，被粘滞分配一直吸在 H5 ——
   **自我维持**。注意不是「溢出到邻点」：低于 `SPILL_MIN_CONFIDENCE = 0.6` 的撞点框本来就会被丢弃。
2. **置信度 < 0.40（D7，0.32）**：进不了盘面，但 `cell_top` 把它取整到空着的 D7，
   `AmbiguousPromoter` 连续 12 帧看到它，就升级成疑似落子卡片。

两条路都在**去重之后**才发生，所以在去重之后、分置信档之前拦住影子框，两条一起断。

复现（线上日志坐标 + 真实框尺寸 + 线上视差参数 `nadir=(19.612, 9.0)`，`k=0.989689`）：
- 帧 1：影子框原始 (13.69, 6.364) → 校正 (13.642, 6.5006) → **H5 = 黑**；
- 帧 2：原始 (13.71, 6.33) → 校正 (13.662, 6.467)，本应丢弃，但上一帧 H5 有子 → **粘滞保持 H5 = 黑**。

## 2. 判据

**IoMin = 两框交叠面积 ÷ 较小框面积。** 不用 IoU：同一对 H5 框 IoMin 0.37–0.44，IoU 只有 0.2 左右。
**偏离量 = 框心（视差校正后）到最近交叉点的距离，单位：格。**

| | IoMin | 偏离量 |
|---|---|---|
| 会成假子的影子框（09-23 白天局 12 帧，视差校正后，只被新规则影响的 36 个） | 0.326–0.44 | **最小 0.45**，中位 0.55 |
| `kifu_24171` 两颗贴着的真白子里被误并的那颗（第一版的失败） | 0.38 | **0.04–0.08** |
| 标注集 209 张图里所有配上标注的真子框（21171 个，**未做视差校正**，偏保守） | — | p50 0.18 · p90 0.28 · p99 0.35 · p99.9 0.38 · 最大 0.46 |
| 09-23 白天局真子框（视差校正后） | — | p99.9 0.35 · 最大 0.36 |

单看 IoMin，真子（0.38）落在影子的区间里；加上偏离量就分开了。

## 3. 规则（第二版）

识别顺序：**YOLO NMS → 去重复框（`dedup_detections`，原样不动）→ 去影子（新）→ 分置信档 / 落到盘面 / 疑似落子判定**。

去影子是 `BoardStateExtractor.drop_shadow_boxes(detections, img_w, img_h)`：一个棋子框被当作影子去掉，当且仅当

1. 它自己离最近交叉点 **≥ `SHADOW_MIN_OFFSET = 0.35`** 格（视差校正后），**并且**
2. 存在另一个棋子框：与它交叠 **≥ `SHADOW_OVERLAP_MIN = 0.27`**（除以较小框）、大小相近（较大平均边长 ≤ `SHADOW_MAX_SIDE_RATIO = 2.0` × 较小）、
   **离交叉点比它近**、**置信度不低于它**。

- **只去不加、不改顺序**：LED 框、没有面积的框、框心不是有限数的框一律原样通过；输出保持输入顺序。
- **与输入顺序无关**：对整批一次判定，不是贪心扫描，所以没有「并掉 B 以后 C 复活」这种问题。
- **置信度条件是保守的一刀**：它保证这一步永远不删一对里分高的那个。两种罕见情形因此都退回到「没有这一步时」的行为，而不是更坏：
  （a）影子框分数反超它的子（实测 0 / 36）；（b）真子本身被推离交叉点 ≥ 0.35 格、又恰好推向影子一侧，于是影子落在下一个点上 ——
  单看几何会把**真子**当成影子删掉。
- **边长比护栏**：一只手被读成一个大框、压在点上且分数更高时，它下面一颗推离了交叉点的子完全在大框里（IoMin = 1）；只有边长比挡住它。
- **门槛为什么是 0.35**：标注集上把门槛降到 0.25 就开始丢真子（`kifu_24171`），0.30–0.45 一颗不丢；影子框最小 0.45。取两者之间偏保守的一侧。
- **放在哪里**：`worker_inprocess.py` 里紧跟 `self._detector.detect(warped)` 之后、分置信档之前，所以盘面分配、维持档、疑似落子提升器都看不到影子框。
  `worker.py`（子进程版）板上不用，不改。`stone_detector.dedup_detections` 的签名和行为都不变（五子棋钉着它）。

## 4. 性能

每个棋子框算一次位置（与落点分配同一个 `_positions`），然后只对落在两点之间的少数框扫一遍其余棋子框。
本机实测：117 框的真实帧 0.22 ms（旧的去重本身 0.15 ms）；几何整体偏半格、所有框都在两点之间时 1.19 ms。板上约慢 11 倍：
预计每帧多 2–3 ms，最坏约 13 ms，对照整帧中位 504 ms。不需要网格加速结构。上板复测看 `detect − pre − npu − post`
（去重 + 去影子都在这一段里；`post` 是后端自己的解码，不含它们）。
