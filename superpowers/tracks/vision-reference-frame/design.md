# 参照图对比：用上一次确认时刻的画面减少白天强光下的假阴性/假阳性

2026-09-23。Fan 的原始提法：「棋盘初始状态拍一次照，和后续识别用的照片对比；每一次落子确认后都拍一张，
和下一步识别阶段的照片对比，用于排除假阴性、假阳性」，并要求参照图用完即删、别把存储撑爆。

本文是 v3。v1 被 Codex 审出 8 条 P1（其中一条足以让功能变成故障放大器，见 §3 自我中毒），
v2 又被审出 8 条 P1、2 条 P2（投票滞后一帧的中毒、计数可被翻转清零、颜色不一致被错误地按长上限保护、
「新增一子」判不出撤销提子与跳变、重复下发 expected 会反复丢参照）。整套判据因此从「硬真相」
降级为「有界证据」。被推翻的旧判据保留在 §10，以免下一轮有人照着直觉又写回去。

---

## 1. 为什么不是逐像素比差

白天的故障是强光和阴影造成的：光斑移到白子上、阴影边缘扫过空点。这两种情况**像素本来就会大变**，
逐像素比差得到「变了」，什么也否决不掉。

改为**按格算零均值归一化相关（ZNCC）**：只比结构，不比绝对亮度。整格变亮 30%、有一道均匀亮边扫过，
相关度依然很高；多一颗子、少一颗子，结构变了，相关度掉下来。

## 2. 判据：证据，不是真相

**v1 写的是**：「某一格与参照图结构一致 ⇒ 它的占用必须与参照时刻相同」。这句话作为硬不变式**不成立**：
ZNCC 只证明两块归一化后的灰度图案相关。局部过曝、模糊、8 帧平均中的过渡态、只移动一点点的棋子，
都可能在结构变了的情况下仍然相关度很高。

**现在的判据**：相关度高只是「这一格大概率没变」的**证据**，它可以压过模型，但

- **有方向**：保护棋谱已知的子（对抗假阴性）力度大；压制凭空多出的子（对抗假阳性）力度小。
- **有时限**：任何一格的否决都有上限帧数，到点必须放行，让模型说了算。
- **不写回**：否决只作用于「交给下游的盘面」，不回写识别自己的历史状态。

三条合起来保证：**判错了会自愈**，最坏情况是延迟若干帧，而不是卡死。

## 3. 自我中毒：v1 最严重的缺陷

v1 在「摄像头稳定盘面 == 棋谱盘面」时拍参照。但这个条件**只是两个都可能出错的矩阵相等**，
不等于「画面里每一格确实是这样」。

具体场景：人落了一颗子，识别漏了（正是本功能要解决的假阴性）。此时棋谱还没有这手（落子未提交），
摄像头盘面也没有这颗子，两者相等 ⇒ v1 拍下这张**含子的照片**，并把该点标成空。
此后每一帧那一格都「结构一致」，于是那颗真子被永久擦掉，而且 v1 还会每 2 秒用被否决过的盘面
重新拍参照，把中毒状态固化。**一个本来只持续几帧的假阴性，被放大成整局卡死。**

四道防线：

1. 拍参照用的是**未经否决的投票盘面**，不是否决后的结果；而且**这一帧的投票前观测**也必须等于棋谱。
   只看投票结果不够：两帧投票在一格刚变化的那一帧仍输出旧值，而 MoveDetector 在循环里更靠后，
   `pending_move` 还没建立 —— 子刚落下的那一帧恰好会被拍成「含子但标为空」的参照（Codex 第二轮 P1）。
2. 拍参照的条件加上：**没有待确认的落子**、**当前没有任何一格正被否决**、**未暂停**、**同步状态正常**。
3. 取消「盘面没变也每 2 秒重拍」。参照只在**棋谱推进**（收到新的 expected board）或首次满足条件时更新。
4. 逐格**否决上限**：计数在一张参照的生命周期内**只累加不清零**（否则模型隔帧才看见那颗子时，
   连续计数永远攒不满，否决就成了永久的），到上限就放行并作废参照。
   只有「棋谱有子而模型读成空」用宽上限（默认 90 帧，约 36 秒）；
   「凭空多出的子」和「颜色不一致」用窄上限（默认 10 帧，约 4 秒）——
   后者是因为 `board_state.py:316` 本来就有连续 15 帧后释放错色的机制，不能被这一层悄悄堵上。

## 4. 参照图什么时候拍

在主循环里，同时满足以下条件的那一帧：

- 已绑定对局（`_bound`）、未暂停（`_paused` 为假）；
- 画面静止（`_motion_is_stable`）；
- 没有点亮的指引灯（`_lit_points` 为空）；
- **未经否决的**投票盘面与棋谱盘面完全一致（`raw_voted_board == _expected_np`），
  且**这一帧投票前的观测**也与棋谱一致；
- MoveDetector 没有待确认的落子（`pending_move` 为空）；
- 上一帧没有任何一格被否决。

满足条件时，**只有在棋谱盘面自上一张参照以来变过**（或还没有参照）才重拍。开局绑定、盘面为空且一致时
拍下第一张，正是 Fan 说的「棋盘初始状态拍一次」。

**作废时机**：重新标定（几何变了）、`BIND`、`UNBIND`、`RESET_SYNC`、进入摆子/设置模式、暂停、
以及**棋谱不再是参照那个局面往前走一步**：参照里的每颗子都还在且颜色相同、且最多多出一颗，
才保留；悔棋、跳到别的变化、新开一局、被撤销的提子都会拿掉参照里的子，因此作废。
注意编排层是按对局状态**重复下发**同一份 expected 的，重复下发必须视为「没变」，否则参照会被反复丢弃。
作废后规则不开口。

## 5. 比对用哪一帧

用 **warp 之后、8 帧平均之前、CLAHE 之前**的灰度图。

- 不能用 CLAHE 之后的：CLAHE 是自适应的，同一块区域会因为画面别处的变化而输出不同结果。
- 不能用 8 帧平均之后的：新落的子要好几帧才在平均图里显形，这段过渡期里它和参照图仍然相关，
  正好落进「该放行却被否决」的窗口（Codex P1-7）。平均图只服务于模型推理，不服务于本判据。

单帧噪声对 ZNCC 影响很小（2304 个像素一起算相关）。

## 6. 按格取样的几何

warp 之后棋盘是规则网格（950 px 网格 + 53 px 边距，每格 52.78 px），交叉点像素位置由
`coordinates.grid_to_pixel` 给出。

取样中心取**棋子成像的位置**（交叉点经纠偏公式的逆向外移），这样小块能真正盖住棋子。
小块覆盖 0.45 格半径（48×48 像素），但**隔点取样**，即 24×24 个采样点：索引表和每帧计算都省 4 倍，
而 ZNCC 的判别力几乎不变（棋子与木纹的结构差异远大于一个像素的尺度）。

边界格（第 0、18 行列）在带一格边距的 warp 里不会越界；若真的触发边界夹取，小块中心会内移，
参照与当前帧用的是同一张索引表，比较仍然成立。

## 7. 判据与例外

- 相关度 ≥ **0.90**（暂定，必须用板上影子模式的实测分布重定）判为「结构一致」。
- **测不了的格子不参与**，两个条件任一成立即判测不了：
  - 小块标准差 < 3 灰阶（拍平：过曝或全黑）；
  - 小块里 ≥ 250 的像素占比 > 25%（大面积过曝，但一条网格线或棋子边缘仍贡献方差，
    只看标准差会漏掉，Codex P2）。
- 指引灯点亮的格子不参与。
- 参照图与当前帧的图像尺寸、几何必须一致，否则作废。

## 8. 接在流水线的哪一步

```
detections → detections_to_board（滞回/占用感知）→ 两帧投票 → raw_voted_board
                                                              ├─→ 识别自己的历史状态（_last_stable_board / _prev_observed_board / 滞回 / 维持档 / 变色释放）
                                                              └─→ 参照图否决 → effective_board → 落子判定 / 同步 / 状态上报
```

**关键：否决不回写识别的历史状态。** v1 把否决结果写进 `_last_stable_board`，于是下一帧的滞回、
维持档、以及 `board_state.py` 里连续 15 帧的「变色释放」机制全部基于一个被篡改的历史，
形成没有出口的自锁（Codex P1-4）。现在历史永远是 raw，否决只出现在交给下游的那一份上，
因此「模型持续不同意」这件事一直可见，逐格计数器到点就能放行。

盘面变化日志（board delta）打 raw 的那一份；否决单独打一行，写明 raw 与 effective 的差异。

## 9. 三档开关与影子模式

`--vision-reference-check {off,shadow,on}`：

- `off`：完全不算，零开销。
- `shadow`（**默认**）：全部算出来、只记日志，`effective_board` 恒等于 raw，不改任何行为。
- `on`：实际生效。

**本轮只交付到 shadow 为止**：`on` 的代码路径要写全、要有测试，但板上先只跑 shadow，
用真实白天数据定阈值、定两个上限帧数，再决定是否打开。

日志（只在 raw 与 effective 不一致时打，每帧最多一行）：
`refcheck would keep 2 cell(s): (3,15) board=0 ref=2 zncc=0.94 held=3/90 ...`

## 10. v1 里被推翻的判据（别写回去）

| v1 的写法 | 为什么错 |
|---|---|
| 「结构一致 ⇒ 占用一定没变」当硬不变式 | ZNCC 只说明相关，过曝/模糊/过渡态都能高相关（P1-3） |
| 否决结果写回 `_last_stable_board` | 篡改识别历史，滞回与变色释放失去出口，形成自锁（P1-4） |
| 「盘面一致」就拍参照 | 漏识别的真子会被拍进参照并标成空，故障被永久固化（P1-2） |
| 盘面没变也每 2 秒重拍 | 把中毒状态持续固化（P1-2） |
| 只在几何变更与 UNBIND 作废 | BIND / RESET_SYNC / 摆子模式 / 悔棋跳转都会留下过期参照（P1-6） |
| 比对用 8 帧平均图 | 新子在平均图里要几帧才显形，过渡期会被误判为「没变」（P1-7） |
| 只用标准差判「测不了」 | 90% 过曝的格子靠一条网格线就能过标准差（P2） |

## 11. 成本

每帧：361 格 × 24×24 采样点 = 20.8 万个点的取样 + 三遍向量化统计。

**MacBook 实测（2026-09-23，1056×1056）**：每帧 **1.1 ms**，索引表 0.79 MiB、参照图 0.79 MiB（常驻），
每帧临时峰值 2.4 MiB，建一次索引表 2 ms。板上按 5–10 倍估约 5–11 ms，相比每帧 380–600 ms 可忽略；
真值部署后用 vtrace 的 `refchk` 段量，写回这里。

必须整体向量化（RK3562 上逐格 Python 循环是负优化，见 memory `reference_arm_sbc_numpy_call_overhead`）。
