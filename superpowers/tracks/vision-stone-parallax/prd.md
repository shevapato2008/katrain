## 1. 背景与目标

摄像头装在棋盘 480 mm 长边外侧,光轴偏离竖直 **28°**,不是正上方俯拍。棋子有厚度,
识别器报出来的「棋子中心」实际上在棋盘面**上方** h 处;这个点沿视线投回棋盘平面时,
会沿**背离镜头**的方向外移,离镜头越远移得越多。

实测(镜头离棋盘面 H = 339.44 mm,棋子 ⌀22 × 7 mm,h 取厚度一半 3.5 mm):

| | 值 |
|---|---:|
| 最远一排 \|Δy\| | **4.495 mm** |
| 占半格(11.0 mm) | **40.9%** |
| 最大 \|Δ\| | 5.014 mm(A19 角) |

偏移本身还不至于让摆正的棋子跨过半格线。**真正的问题是它把容差吃成了不对称的**:
往镜头方向偏可以容忍 15.50 mm,往远端偏只剩 **6.51 mm**。所以远端棋子只要往远离
摄像头的方向偏一点,就越过半格线被判到邻近交点上 —— 这正是现场观察到的症状。

如果识别器报的是棋子**顶面**圆心而不是 bbox 中心(h = 7.0),最远排 \|Δy\| = 9.085 mm,
占半格 82.6%,远端容差只剩 1.915 mm,基本必然误判。

本轮目标三件事:

1. 在坐标映射链里补上这一步修正,让摆正的棋子落回正确交点,并把远端摆子容差从 6.51 mm
   还原到 11.0 mm 附近。
2. 修正系数不写死在推导上,而是**现场标定**出来 —— 把 h、入瞳位置、装配误差一次吸收。
3. 把「棋子在两个交点之间」这类 `ambiguous_stone` 事件的发生率量出来,修正前后可对照。

**这不是识别率问题,是坐标映射问题。** 本轮不碰 YOLO 模型、不碰 warp / board_finder。

## 3. 需求条目(本轮做)

### P1-1 · 坐标映射链缺一步视差修正

- **现象**:摆正的棋子在棋盘远端被判到相邻交点;越靠远端、越往远离摄像头方向偏,
  越容易发生。现场表现为 `ambiguous_stone` 事件里 `unbacked=True` 的那一类
  (`katrain/vision/worker.py:483-487` 的注释已经把这类描述成
  "the stone sits between intersections and got spill-assigned")。

- **根因(已核实)**:`katrain/vision/coordinates.py` 这条链把检测框中心当作**棋盘平面上的点**:

  - `pixel_to_physical`(`coordinates.py:12-18`):warp 图像像素 → 物理 mm,纯线性缩放。
  - `continuous_grid_pos`(`coordinates.py:31-37`)/ `physical_to_grid`(`:21-28`):mm → 连续 /
    取整网格坐标。
  - 调用点:`katrain/vision/board_state.py:108-109`(`_grid_cell`)与 `:131-132`
    (`detection_points`)。

  整条链没有任何一步扣除棋子厚度带来的投影外移。检测框中心对应的是棋子在**半空中**的
  那个点,不是它接触棋盘的那个点。

- **公式(推导见 `geometry.md`)**:

      正向  D = C + (P − C) · m        m = H / (H − h)
      反向  P = C + (D − C) · k        k = (H − h) / H = 1/m

  其中 C 是 nadir(镜头投影中心在棋盘平面上的垂足),H 是镜头离棋盘面高度,
  h 是棋子视觉中心离棋盘面高度。三个要点:

  1. 偏移方向永远从 nadir **径向朝外**,大小与到 nadir 的水平距离成正比。
  2. **与俯角、焦距、FOV、畸变全都无关** —— 前提是已用棋盘四角 / 网格做过透视矫正,
     在棋盘平面坐标里计算。这是纯针孔几何结论。
  3. 反向是**精确解**,不用迭代:以 nadir 为中心、系数 k 的一次位似。

- **实现上的关键结论 —— k 在仿射变换下不变**:
  位似经任何仿射映射 A 共轭之后还是位似,中心变成 A(C),**系数 k 不变**
  (`D' = A(D) = A(C) + m·(A(P) − A(C))`)。`pixel_to_physical` +
  `continuous_grid_pos` 合起来就是一个仿射映射。所以修正可以直接做在
  **连续网格坐标 (fx, fy)** 上,只需要把 nadir 表示成同一坐标系里的一对数:

      fx' = ncx + (fx − ncx) * k
      fy' = ncy + (fy − ncy) * k

  这一条让实现变得很小:不需要知道 `BoardConfig` 的 mm 尺寸对不对(见 P1-2),
  也不需要关心 warp 的像素尺度。

- **期望**:
  1. `coordinates.py` 新增 `apply_parallax(fx, fy, nadir, k)`,纯函数、无状态。
     (2026-09-22 修订:原文写「幂等」,不对 —— 调两次等于系数 k²。所以每个检测只能修正一次,

### P1-2 · nadir 与 k 的来源:现场标定,不写死推导值

- **现象 / 风险**:直接把 CAD 推出来的常量写进代码有三个坑。

  1. **h 的取值差一倍**。h = t/2 = 3.5 的依据是:棋子实测体积 1773.95 mm³ 正好等于
     a=11、c=3.5 的扁椭球,上下对称,所以投影轮廓也对称于中平面,bbox / 椭圆拟合中心
     对应中平面。但如果识别器实际报的是顶面圆心,h 就是 7.0,k 差一倍。
     **这件事只能靠实测数据判定,不能靠推导。**
  2. **`BoardConfig` 的 mm 尺寸与 ver9 实物不符**。`katrain/vision/config.py:22-23`
     默认 `board_width_mm=424.2`、`board_length_mm=454.5`(标准日式榧木盘),
     而 ver9 实物网格是 **396.0 × 426.6**(间距 22.0 × 23.7)。
     两者不一致不影响 k(见 P1-1 的仿射不变性),但**影响 nadir 的数值**,
     所以 nadir 必须在流水线自己的坐标系里定出来,不能直接搬 CAD 的 mm 值。
  3. **warp 的方向未知**。`board_state` 的 (fx, fy) 哪个角是 (0,0)、行列是否翻转,
     取决于 geometry_lock 存的四角顺序。搬 CAD 数会搬错符号。

- **期望**:提供标定入口,从实测数据直接解 (m, C):

      正向模型 D = m·P + (1−m)·C 对 (m, bx, by) 是线性的
      最小二乘解出 m 与 C = b/(1−m),k = 1/m

  四角 + 天元五点即可(10 个方程 3 个未知数)。解出来的 m 把 h、入瞳位置、装配误差
  **一次性全部吸收**。参考实现见 `parallax_correct.py::fit_from_samples`。

- **实现**:
  1. 标定工具:在已知交点上各放一颗棋子,跑一帧,记 `detection_points` 的 (fx, fy),
     与该交点的 (i, j) 配对,拟合。建议放到 `katrain/vision/tools/` 下,与
     `calibrate_camera.py`、`outer_corner_accuracy.py` 同级。
  2. 标定结果 `{nadir_fx, nadir_fy, k, rms_mm, n_samples, fitted_at}` 落盘,
     与既有的几何标定同一套存取路径(`calibration_registry.py` / `geometry_lock.py`,
     具体挂点在 plan 阶段定)。
     (2026-09-22 修订:`calibration_registry.py` 是 31 行的几何标定策略选择器,不存东西;
     `geometry_lock` 在 kickoff §1 第 7 条的禁区里;真正的几何持久化 `hardware_vision_state.py`
     每次漂移重标定都换代。所以定为**独立文件** `<hardware-vision-dir>/parallax/go-19x19.json`,
     每块棋盘一个文件,记录棋盘、棋子、拟合结果与标定时的几何代次;`rms` 存格不存 mm。
     格式与理由见 `design.md` §0 D1、§3。)
  3. 拟合同时报 `h_implied = H·(1 − 1/m)`,拿它和 3.5 / 7.0 对一下,
     **就知道识别器报的到底是哪个高度** —— 这是一个有诊断价值的副产品。

- **验收**:
  1. 单测:用 `parallax_correct.forward()` 造无噪样本,`fit_from_samples` 解回的
     k 与 nadir 误差 < 1e-6,`rms_mm` < 1e-9。(2026-09-22:`rms` 改存格,即 `rms_cells` < 1e-9。)
  2. 单测:加 ±0.3 mm 高斯噪声,9 点拟合的 k 误差 < 1%。
     (2026-09-22 修订:「k 误差 < 1%」几乎放过任何拟合 —— **完全不修正(k=1)的 k 误差也只有
     1.04%**。改为量修正输出:固定种子 200 次,`h_implied` 相对误差 p95 < 20%,且全盘修正残差
     最大值 p95 < 1.0 mm。实测分别是 7.8% 与 0.38 mm;不修正时是 100% 与 5 mm。
     另外**不对 nadir 做数值断言与合理性检查**:nadir = b/(1−m) 是病态量,0.3 mm 噪声下误差
     p95 = 29 mm,但它对修正输出的影响乘了 1−k ≈ 0.01,可以忽略。)
  3. 单测:样本点共线 / 少于 3 点时明确报错,不返回病态解。
  4. 上板:实测拟合的 `rms` 与 `h_implied` 记进标定报告;`h_implied` 落在 2–8 mm
     之外要当作标定失败(说明 warp 或配对错了),不允许静默写入。

- **依赖**:需要一套已知摆位的实拍帧。

## 5. 风险与未决

1. **棋盘对位还没做**。Fusion 里实测棋盘相对支架差 ΔX +14 / ΔY +2 / ΔZ −2.5 mm。
   未做时 nadir 在 x=0 而棋盘中心在 x=−14,X 方向偏移左右不对称(左最远列 227.3、
   右 199.3)。做了对位之后 nadir 落在中心列上(连续网格坐标 fx = 9.000)。
   **标定是在实物上做的,这条自动被吸收**;但对位前后要重新标定一次。
2. **不同棋子**。换一副厚度不同的棋子,k 会变。标定要写清对应的是哪副棋子。
3. **几何推算 ≠ 识别率测试**。本文所有数字都是几何量。装机后必须在相同光照 / 棋局 / 模型下
   比对修正前后的漏检与误检。
4. **h 的归属**。如果 `h_implied` 稳定落在 7 附近,说明识别器报的是顶面圆心;
   那么除了做修正,还值得回头看一眼 YOLO 的标注口径(`tools/baipu_autolabel.py:177` 附近
   写的是「标注在真实交点上,部署时再做修正」)—— 标注口径与推理口径是否一致,
   会直接决定 h。这条列为观察项,不在本轮范围。
   (2026-09-22 更正:上面对 `baipu_autolabel.py:177` 的引述与原文相反。原文 `:176-178` 写的是
   框「centered on the stone's real visible position (not the grid intersection)」,CLI 的
   `--refine-boxes` 默认开(`:377`)。也就是标注在棋子**看得见的位置**,识别器报的正是带视差的
   位置 D,这正是需要本轮修正的原因,预期 `h_implied` ≈ 3.5。只有盘上找不到棋子轮廓时才退回
   交点居中的框(`:179`);如果这类框在训练集里占比不小,`h_implied` 会偏低 —— 仍然是观察项。)
5. **最外一圈的容差不恢复**(2026-09-22 新增)。为守 P1-1 验收 3,DROP 按「原始或修正任一出界」判,
   最外一圈往盘外方向偏的棋子仍是今天的约 6.5 mm 容差;盘内各排恢复。
6. **摄像头杆被动过而没重标,系统发现不了**(2026-09-22 新增)。视差参数不跟几何代次绑定
   (几何一碰就换代,绑定会让修正频繁失效),标定时的代次只记录、只打日志。操作规程:
   动杆、换棋盘、换棋子、做完棋盘对位之后都要重标。
